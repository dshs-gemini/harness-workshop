클로드 코드를 Docker로 쓰기

Windows에서 PowerShell·CMD 설치 명령이 막히거나 오류가 날 때, 설치 대신 ‘컨테이너’ 안에서 클로드 코드를 실행하는 방법입니다. 기본 가이드의 1.2절(설치와 첫 대화)을 대신하는 경로로 쓸 수 있습니다.

⏱ 약 30~40분 (이미지 내려받기·빌드 대기 포함) 👤 대상: 네이티브 설치가 막힌 Windows 사용자, 환경을 통일하려는 강사 💻 준비물: Windows 10/11 노트북, 인터넷, 클로드 계정

한 줄 요약

클로드 코드를 Windows에 직접 설치하는 대신, Docker Desktop을 한 번 설치하고 Dockerfile + compose.yaml 두 파일로 만든 리눅스 환경에서 claude를 실행합니다. 클로드 코드, Git, Node.js, Firebase CLI가 이미지 안에 이미 들어 있으므로 설치 스크립트 오류·PATH·Git Bash 문제가 생길 자리가 없습니다.

검증 범위 (먼저 읽어 주세요)

이 자료의 Dockerfile·compose.yaml은 macOS(Apple Silicon)의 Docker Desktop 29.4에서 직접 빌드하고 실행해 확인했습니다. 확인한 내용: 이미지 빌드, claude --version(2.1.312), Git·gh·Firebase CLI 동작, work 폴더 파일 공유, 컨테이너를 지워도 로그인 폴더 유지, 이미지 저장·불러오기. Windows 실기와 클로드 계정 로그인 완료까지는 확인하지 못했습니다. 해당 부분은 본문에 확인필요로 표시했으니, 연수 전에 Windows 노트북 한 대로 리허설해 주세요.

이 문서를 읽는 법

왼쪽 사이드바의 ● 파란 점은 이해하기, ● 초록 점은 따라 하기, ● 보라 점은 점검입니다. 코드 블록의 복사 버튼으로 내용을 그대로 복사할 수 있습니다. 같은 폴더의 docker-kit/에는 본문과 똑같은 파일(Dockerfile, compose.yaml)이 들어 있습니다.

이해하기

1. Docker로 해결되는 것과 남는 것

Docker는 설치 문제를 없애는 것이 아니라, 흩어진 문제를 ‘Docker Desktop 설치 한 번’으로 모아 줍니다. 무엇이 사라지고 무엇이 남는지 먼저 정확히 봅니다.

컨테이너가 하는 일

컨테이너는 내 PC 안에서 돌아가는 작은 리눅스 환경입니다. 클로드 코드는 그 안에서 실행되고, 내 PC에서는 터미널 창으로 그 화면을 봅니다. 내 PC의 폴더 중 지정한 폴더 하나(work)만 컨테이너와 공유됩니다. 클로드 코드가 만든 파일은 그 폴더에 그대로 나타납니다.

네이티브 설치에서 겪는 문제Docker 방식에서는
irm·&& 인식 오류, 설치 스크립트가 HTML을 돌려줌, 403, TLS 오류사라짐. 설치 스크립트를 쓰지 않고 Dockerfile이 npm으로 설치합니다. (이미지를 만드는 동안은 인터넷이 필요합니다.)
claude가 인식되지 않음(PATH)사라짐. 이미지 안에서 PATH가 이미 맞춰져 있습니다.
Git for Windows·Git Bash 필요사라짐. 이미지에 git이 들어 있어 하네스 플러그인 설치(/plugin marketplace add)도 그대로 됩니다.
Node.js·Firebase CLI·GitHub CLI를 따로 설치사라짐. 모두 이미지에 포함되어 있습니다.
사람마다 다른 환경 때문에 같은 명령이 다르게 동작사라짐. 모두 같은 이미지에서 시작합니다.
Docker Desktop 설치(WSL 2·가상화·관리자 권한)새로 생김. 이 문제가 Docker 방식의 유일한 큰 관문입니다.
학교 네트워크가 외부 사이트를 차단남음. Docker Hub, npm, claude.ai 접속이 막히면 똑같이 실패합니다. (9절, 11절 참고)
디스크·메모리 부담늘어남. 이미지 약 1.8GB, Docker Desktop은 RAM 8GB 이상을 요구합니다.
공식 문서도 같은 방향을 안내합니다

Claude Code 공식 ‘샌드박스 환경 선택’ 문서는 “네이티브 Windows 호스트에서 작업한다면 컨테이너나 VM, 또는 WSL2 안의 Bash 샌드박스를 쓰라”고 안내합니다. 또 컨테이너를 쓰면 클로드 코드가 실행하는 명령이 호스트가 아니라 컨테이너 안에서 실행되고, 프로젝트 파일의 수정만 내 PC 저장소에 반영됩니다.

Docker가 맞지 않는 경우

학교 관리 PC에서 관리자 권한 설치가 막혀 있거나, BIOS에서 가상화가 꺼져 있고 바꿀 수 없다면 Docker Desktop 자체가 설치되지 않습니다. 이때는 Docker 대신 클로드 데스크톱 앱(GUI) 또는 웹의 클로드 코드를 대안으로 검토하세요. 두 방법 모두 터미널 설치가 필요 없다고 공식 문서가 안내합니다.

3. Docker Desktop 설치

Docker 방식에서 가장 중요한 단계입니다. 약 10~15분 걸립니다. 이미 Docker Desktop을 쓰고 있다면 5번 단계부터 하세요.

STEP BY STEP
1

내 PC가 요건을 만족하는지 확인합니다. Docker 공식 문서(WSL 2 백엔드, x86_64 기준)의 요건은 다음과 같습니다.

항목요건
Windows 버전Windows 10 22H2(빌드 19045) 이상, 또는 Windows 11 23H2(빌드 22631) 이상
WSLWSL 2.1.5 이상 (설치 마법사가 안내)
하드웨어RAM 8GB 이상, SLAT 지원 64비트 프로세서, BIOS/UEFI에서 가상화 사용
지원하지 않음Windows Server 2019·2022 같은 서버 에디션

윈도우 버전은 Win+R → winver 입력으로 볼 수 있습니다. 에디션(Home·Pro 등)별 지원 범위는 문서 표현이 복잡하므로 Docker 공식 설치 문서에서 본인 에디션을 직접 확인하세요. 확인필요

2

가상화가 켜져 있는지 확인합니다. Ctrl+Shift+Esc로 작업 관리자를 열고 성능 > CPU에서 ‘가상화’ 항목이 사용인지 봅니다. ‘사용 안 함’이면 BIOS/UEFI에서 가상화(Intel VT-x, AMD-V/SVM)를 켜야 하며, 학교 관리 PC라면 IT 담당자의 도움이 필요합니다.

3

설치 파일을 내려받아 실행합니다. Docker Desktop for Windows 설치 문서의 다운로드 링크에서 Docker Desktop Installer.exe를 받아 실행합니다. 설치 방식은 두 가지입니다.

  • 현재 사용자만(기본값) — 관리자 권한이 필요 없습니다. 학교 PC에서는 이쪽을 먼저 시도하세요.
  • 모든 사용자 — 관리자 권한(상승)이 필요합니다.

‘구성(Configuration)’ 화면에서 백엔드로 WSL 2를 선택한 채 마법사를 끝내고 닫기(Close)를 누릅니다.

4

Docker Desktop을 직접 실행합니다. 설치가 끝나도 Docker는 자동으로 시작되지 않습니다. 시작 메뉴에서 “Docker Desktop”을 실행하고, 화면 아래쪽에 ‘Engine running’ 같은 실행 상태가 보일 때까지 기다립니다. 재시작을 요구하면 재시작한 뒤 다시 실행하세요.

5

터미널(PowerShell)에서 동작을 확인합니다.

PowerShell
docker --version
docker compose version
docker run --rm hello-world

버전 번호가 나오고 hello-world가 환영 메시지를 출력하면 준비 완료입니다.

라이선스

Docker 공식 문서는 Docker Desktop이 개인 사용, 교육, 비영리 오픈소스에는 무료라고 안내합니다. 다만 ‘정부 기관’은 유료 구독이 필요하다고 명시하고 있어, 공립학교·교육청 소속 PC에서 연수용으로 쓰는 경우는 소속 기관의 정책을 확인하는 것이 안전합니다. 확인필요

4. 실습 키트 만들기와 빌드

파일 두 개를 만들고 이미지를 한 번 빌드합니다. 빌드는 처음 한 번만 하면 됩니다. 이 Mac에서는 약 1분이 걸렸고, 학교 네트워크나 Windows에서는 더 걸릴 수 있습니다.

가장 쉬운 길: 강사가 만든 폴더를 받기

이 자료와 함께 제공되는 docker-kit 폴더(Dockerfile, compose.yaml, 빈 work 폴더)를 통째로 복사해 오면 아래 1~3단계는 건너뛰고 4단계부터 하면 됩니다. 강사에게 받지 못했다면 GitHub의 docker-kit 폴더에서 각 파일을 열어 내용을 복사하거나, 저장소 페이지의 Code > Download ZIP으로 받은 압축 파일 안의 docker-kit 폴더를 쓰세요. 직접 만들 때는 메모장이 파일 이름 뒤에 .txt를 붙이지 않도록 주의하세요(아래 막힐 때 참고).

STEP BY STEP
1

작업 폴더를 만듭니다. 경로에 한글·공백이 없는 위치를 권합니다(문제가 생겼을 때 원인을 좁히기 쉽습니다). 공식 근거는 확인하지 못한 예방 조치입니다.

PowerShell
mkdir C:\claude-docker\work
cd C:\claude-docker
2

Dockerfile을 만듭니다. 확장자 없이 Dockerfile이라는 이름의 텍스트 파일로 저장하고 아래 내용을 붙여넣습니다. 이 파일이 “어떤 도구가 든 환경을 만들지”를 적은 설계도입니다.

C:\claude-docker\Dockerfile
FROM node:22-bookworm-slim

# 기본 도구: git(하네스 플러그인 설치에 필요), gh(GitHub), 편집기·검색 도구
RUN apt-get update && apt-get install -y --no-install-recommends \
      git ca-certificates curl less nano jq ripgrep gh \
    && rm -rf /var/lib/apt/lists/*

# Claude Code와 Firebase CLI 설치 (이미지를 만들 때 한 번만 실행됨)
ARG CLAUDE_CODE_VERSION=latest
RUN npm install -g @anthropic-ai/claude-code@${CLAUDE_CODE_VERSION} firebase-tools

# 로그인 정보가 저장될 폴더를 일반 사용자(node) 소유로 미리 만들어 둠
RUN mkdir -p /workspace /home/node/.claude /home/node/.config \
    && chown -R node:node /workspace /home/node/.claude /home/node/.config

# 컨테이너 안에서는 이미지가 버전을 고정하므로 자동 업데이트는 끈다
ENV DISABLE_AUTOUPDATER=1 \
    CLAUDE_CONFIG_DIR=/home/node/.claude

USER node
WORKDIR /workspace
CMD ["claude"]

한 줄씩 보면 이렇습니다.

  • FROM node:22-… — Node.js 22가 들어 있는 가벼운 리눅스(Debian)에서 시작합니다. 클로드 코드의 npm 설치는 Node.js 22 이상을 요구합니다.
  • npm install -g … — 클로드 코드와 Firebase CLI를 설치합니다. 공식 문서상 npm 패키지는 설치 스크립트와 같은 네이티브 실행 파일을 내려받습니다.
  • USER node — 관리자(root)가 아닌 일반 사용자로 실행합니다. 클로드 코드는 root로 실행하면 --dangerously-skip-permissions를 거부하므로, 일반 사용자가 안전한 기본값입니다.
  • DISABLE_AUTOUPDATER=1 — 이미지가 버전을 고정하므로 자동 업데이트를 끕니다. 새 버전은 이미지를 다시 빌드해 받습니다(9절).
3

compose.yaml을 만듭니다. 같은 폴더에 저장합니다. 이 파일이 “어떤 폴더를 공유하고 무엇을 보관할지”를 정합니다. 들여쓰기는 공백 2칸이며 탭 문자는 쓸 수 없습니다.

C:\claude-docker\compose.yaml
services:
  claude:
    build: .
    image: claude-workshop
    stdin_open: true
    tty: true
    volumes:
      - ./work:/workspace                     # 내 PC의 work 폴더 = 컨테이너의 /workspace
      - claude-config:/home/node/.claude      # Claude Code 로그인·설정 보관
      - tool-config:/home/node/.config        # Firebase·GitHub CLI 로그인 보관

volumes:
  claude-config:
  tool-config:
4

이미지를 빌드합니다. Docker Desktop이 실행 중인 상태에서, C:\claude-docker 폴더의 PowerShell에서 실행합니다.

PowerShell
docker compose build

끝나면 Image claude-workshop Built가 출력됩니다. 중간에 진행 표시가 오래 멈춘 것처럼 보여도 정상일 수 있으니 몇 분은 기다려 보세요.

‘이미지’와 ‘컨테이너’

이미지는 위 설계도로 만든 설치 완료본(읽기 전용 틀)이고, 컨테이너는 그 이미지를 실제로 실행한 인스턴스입니다. 빌드는 이미지를 한 번 만들 뿐이며, 앞으로 docker compose run을 할 때마다 같은 이미지에서 새 컨테이너가 열렸다 닫힙니다.

따라 하기

5. 실행과 로그인

이제부터는 설치 없이 이 명령 하나로 클로드 코드를 시작합니다.

STEP BY STEP
1

클로드 코드를 시작합니다. Docker Desktop이 켜져 있는지 확인하고, 키트 폴더에서 실행합니다.

PowerShell
cd C:\claude-docker
docker compose run --rm claude

--rm은 종료할 때 컨테이너를 자동으로 지우라는 뜻입니다. 로그인 정보와 작업 파일은 따로 보관되므로 지워도 사라지지 않습니다(6절).

2

로그인합니다. 컨테이너 안에는 브라우저가 없어서, 로그인 주소가 터미널에 글자로 표시됩니다.

6. 파일과 로그인은 어디에 남나

컨테이너는 닫을 때마다 지워지므로, 남겨야 할 것이 어디에 있는지 알아야 합니다.

무엇어디에 있나컨테이너를 지우면
내 작업 파일내 PC의 C:\claude-docker\work (컨테이너 안에서는 /workspace)그대로 남음. 탐색기에서 바로 열 수 있음
클로드 로그인·설정·대화 기록Docker 볼륨 claude-config (내 PC 폴더가 아니라 Docker가 관리하는 저장소)그대로 남음. 매번 로그인할 필요 없음
Firebase·GitHub 로그인Docker 볼륨 tool-config그대로 남음
그 밖에 컨테이너 안에 설치·생성한 것컨테이너 내부사라짐. 필요한 도구는 Dockerfile에 추가하고 다시 빌드

이 구조를 이 Mac에서 직접 확인한 결과입니다. 컨테이너 안에서 만든 파일이 호스트의 work 폴더에 나타나고, 컨테이너를 두 번 연달아 열었다 닫아도 볼륨의 파일이 유지되었습니다.

왜 CLAUDE_CONFIG_DIR를 지정하나

클로드 코드는 로그인 토큰·설정을 ~/.claude에, 계정 정보와 프로젝트 신뢰 기록을 별도 파일 ~/.claude.json에 저장합니다. 공식 문서는 볼륨을 ~/.claude에 붙이고 CLAUDE_CONFIG_DIR를 같은 경로로 지정해야 두 가지가 모두 볼륨에 저장된다고 설명합니다. 지정하지 않으면 컨테이너를 지울 때마다 첫 실행 설정을 다시 하게 됩니다. 키트의 Dockerfile이 이미 지정해 두었습니다.

로그인이 사라지는 명령

docker compose down -v의 -v는 볼륨까지 삭제합니다. 클로드·Firebase 로그인 정보가 모두 지워지므로 연수 중에는 쓰지 마세요. --rm만 쓰는 평소 사용에서는 지워지지 않습니다.

Firebase 로그인 (브라우저가 없는 환경)

firebase login은 보통 브라우저를 열고 컴퓨터의 localhost로 결과를 돌려받습니다. 컨테이너 안에서는 이 방식이 되지 않으므로 --no-localhost 옵션을 씁니다. 이 옵션은 도움말에서 “localhost에 접근할 수 없는 장치에서 로그인”하는 용도로 설명됩니다.

PowerShell
PS C:\claude-docker> docker compose run --rm claude firebase login --no-localhost
# 터미널에 로그인 주소가 표시됨 → PC 브라우저에서 열어 승인
# → 브라우저에 표시된 인증 코드를 터미널에 붙여넣기
연수 슬라이드의 ! firebase login과 다릅니다

본 과정 슬라이드는 클로드 코드 안에서 ! firebase login을 실행하는 흐름을 일부 포함합니다. 컨테이너에서는 주소 복사·코드 붙여넣기가 필요한 --no-localhost 방식이 더 안정적일 것으로 보이지만, 클로드 코드 입력창 안에서 코드 붙여넣기가 잘 되는지는 확인하지 못했습니다. 번거로우면 클로드 코드를 시작하기 전에 위 명령으로 먼저 로그인해 두세요. 로그인 정보는 tool-config 볼륨에 남아 이후 클로드 코드 안에서도 사용됩니다. 확인필요

로컬 미리보기가 필요하면

본 과정은 Firebase Hosting에 배포한 뒤 URL로 확인하므로 포트를 열 필요가 없습니다. 컨테이너 안에서 개발 서버(예: 3000번)를 띄워 PC 브라우저로 보고 싶다면 compose.yaml의 claude 서비스에 ports: ["3000:3000"]를 추가하고 docker compose run --rm --service-ports claude로 실행해야 합니다. 서버는 localhost가 아니라 0.0.0.0에 바인딩되어야 PC에서 접속됩니다. 확인필요

8. 안전하게 쓰는 법

컨테이너는 보호막이 되어 주지만 만능은 아닙니다. 공식 문서의 경고를 연수 상황에 맞게 정리했습니다.

컨테이너가 막아 주는 것

PC의 나머지 폴더

클로드 코드가 실행하는 명령은 컨테이너 안에서만 돌고, PC에서는 work 폴더만 보입니다. 바탕화면·문서·다운로드 폴더는 컨테이너에서 접근할 수 없습니다.

컨테이너가 막아 주지 못하는 것

work 폴더와 컨테이너 안의 비밀

클로드 코드는 work 폴더의 파일을 수정·삭제할 수 있고, 인터넷도 쓸 수 있습니다. 컨테이너 안의 로그인 정보(~/.claude)도 같은 영역에 있습니다.

  • 권한 확인 모드를 그대로 쓰세요. 공식 문서는 컨테이너에서 --dangerously-skip-permissions를 쓸 수 있다고 하면서도, 그 경우 악의적인 프로젝트가 컨테이너 안의 모든 것(클로드 로그인 정보 포함)을 외부로 빼낼 수 있다고 경고합니다. 연수에서는 기본 권한 모드로 충분합니다.
  • 믿을 수 있는 저장소만 여세요. 출처를 모르는 프로젝트를 work에 내려받아 실행하지 마세요.
  • PC의 비밀 파일을 마운트하지 마세요. ~/.ssh, 클라우드 인증 파일 등을 volumes에 추가하지 않는 것이 공식 권고입니다. 필요하면 저장소 범위의 짧은 수명 토큰을 쓰세요.
  • work 폴더는 백업하세요. 클로드 코드가 이 폴더를 실제로 수정하므로, 중요한 자료는 따로 복사해 두거나 Git으로 관리하세요.
  • 이 키트에는 방화벽이 없습니다. 공식 참조 컨테이너는 허용한 도메인으로만 나가도록 iptables 방화벽을 두지만, 이 키트는 연수 편의를 위해 넣지 않았습니다. 공식 문서도 방화벽은 클로드 코드 동작에 필수가 아니라고 설명합니다.
데이터 전송은 그대로입니다

컨테이너를 쓰든 안 쓰든 프롬프트와 클로드가 읽은 파일 내용은 Anthropic API로 전송됩니다. 학생 개인정보 같은 민감한 자료는 컨테이너 여부와 상관없이 work 폴더에 두지 마세요.

9. 막혔을 때

증상별로 먼저 확인할 것을 정리했습니다. 항목을 눌러 펼치세요.

docker가 인식되지 않는다고 나와요▾
Docker Desktop을 설치한 뒤 PowerShell 창을 새로 열었는지 확인하세요(이미 열려 있던 창은 새 PATH를 모릅니다). 그래도 안 되면 Docker Desktop이 실제로 설치되었는지, 3절 4단계처럼 직접 실행했는지 확인합니다.
Cannot connect to the Docker daemon 같은 오류가 나요▾
Docker Desktop이 꺼져 있거나 아직 시작 중일 때 나옵니다(이 Mac에서 Docker를 끈 상태로 명령했을 때 같은 오류가 재현되었습니다). Docker Desktop을 실행하고 ‘Engine running’ 상태가 될 때까지 기다린 뒤 다시 시도하세요.
Docker Desktop이 시작되지 않거나 WSL·가상화 오류가 나요▾
3절 2단계의 가상화 사용 여부를 먼저 확인하세요. 꺼져 있으면 BIOS/UEFI에서 켜야 합니다. WSL이 오래된 경우 관리자 PowerShell에서 wsl --update를 실행해 보고, 학교 관리 PC라면 IT 담당자에게 문의하세요. 이 단계가 풀리지 않으면 Docker 방식은 포기하고 클로드 데스크톱 앱이나 웹 버전을 쓰는 것이 시간상 낫습니다. 확인필요
메모장으로 만든 파일이 Dockerfile.txt가 되었어요▾
저장할 때 ‘파일 형식’을 모든 파일로 바꾸고 파일 이름을 Dockerfile 그대로 입력하세요. 탐색기의 ‘보기 > 파일 확장명’을 켜면 숨은 .txt가 보입니다. 인코딩은 UTF-8로 저장합니다. 가장 확실한 방법은 강사가 배포한 docker-kit 폴더를 그대로 쓰는 것입니다.
빌드 중에 apt·npm 오류나 시간 초과가 나요▾
학교 네트워크가 패키지 저장소를 차단하거나 프록시를 거치는 경우가 많습니다. 개인 핫스팟으로 바꿔 다시 빌드해 보세요(docker compose build는 이미 받은 단계를 재사용합니다). 여러 명이 동시에 막힌다면 11절의 ‘이미지 파일 배포’로 빌드 자체를 건너뛰게 하세요.
toomanyrequests(429) 같은 Docker Hub 오류가 나요▾
Docker Hub는 로그인하지 않은 사용자를 IP 주소당 6시간에 100회로 제한합니다(공식 문서). 한 교실에서 여러 명이 같은 공유기로 동시에 이미지를 받으면 이 한도에 가까워질 수 있습니다. 11절의 이미지 파일 배포가 가장 확실한 해결책입니다.
로그인 주소를 눌러도 브라우저가 열리지 않아요▾
정상입니다. 컨테이너에는 브라우저가 없어 자동으로 열리지 않습니다. 터미널에 표시된 주소를 직접 복사해 PC 브라우저에 붙여넣고, 화면에 나온 코드를 터미널에 붙여넣으세요(5절 2단계). 주소가 여러 줄로 꺾여 복사가 어렵다면 PowerShell 창을 넓히고 다시 시도합니다.
work 폴더에 파일을 저장할 수 없다는 권한 오류가 나요▾
이 Mac에서는 발생하지 않았지만, Windows 폴더를 컨테이너에 공유할 때 권한 차이로 쓰기가 막히는 사례가 있을 수 있습니다. 먼저 폴더가 C:\claude-docker처럼 일반 위치(바탕화면 동기화 폴더나 OneDrive 폴더가 아닌 곳)인지 확인하세요. 해결되지 않으면 리허설에서 재현해 원인을 기록해 두세요. 확인필요
클로드 코드를 최신 버전으로 올리고 싶어요▾
컨테이너 안에서는 자동 업데이트를 껐으므로 이미지를 다시 만들어야 합니다. 캐시를 쓰지 않고 새로 빌드하세요.
docker compose build --no-cache
특정 버전을 고정하려면 docker compose build --build-arg CLAUDE_CODE_VERSION=버전번호를 씁니다. 로그인 정보는 볼륨에 있으므로 유지됩니다.
연수가 끝났어요. 깨끗하게 지우고 싶어요▾
키트 폴더에서 아래 두 명령을 차례로 실행합니다. 첫 명령은 로그인 정보가 담긴 볼륨까지 삭제하고, 두 번째는 이미지를 삭제합니다. work 폴더의 파일은 지워지지 않으니 필요 없으면 탐색기에서 직접 삭제하세요.
docker compose down --volumes
docker rmi claude-workshop

10. 다른 방법: sbx, VS Code, WSL

A 방식이 맞지 않을 때의 대안입니다. 아래 내용은 공식 문서를 근거로 정리했으며, 직접 실행해 확인하지는 않았습니다.

B. VS Code Dev Container

VS Code와 Dev Containers 확장이 있다면, 프로젝트의 .devcontainer/devcontainer.json 한 파일로 클로드 코드를 컨테이너에 설치할 수 있습니다. 클로드 코드 공식 문서가 안내하는 최소 설정은 다음과 같습니다.

.devcontainer/devcontainer.json (공식 문서 예시)
{
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/anthropics/devcontainer-features/claude-code:1.0": {}
  }
}

저장한 뒤 명령 팔레트(Ctrl+Shift+P)에서 Dev Containers: Rebuild Container를 실행하고, 열린 터미널에서 claude를 입력해 로그인합니다. 컨테이너를 다시 만들 때 로그인이 유지되게 하려면 문서의 ‘Persist authentication’ 절처럼 볼륨과 CLAUDE_CONFIG_DIR를 추가하세요. Node.js 설치 오류가 나면 ghcr.io/devcontainers/features/node:1 기능을 함께 넣으라고 문서가 안내합니다.

C. Docker Sandboxes (sbx)

Docker가 제공하는 별도 제품으로, 에이전트를 가상머신(microVM) 안에서 실행합니다. Docker Desktop이 필요 없고, 프로젝트 폴더만 호스트와 공유됩니다. 공식 문서와 검색 결과에서 확인한 내용은 다음과 같습니다.

  • Windows 요건: Windows 11, 64비트 Intel/AMD 프로세서, Windows Hypervisor Platform 활성화(관리자 권한 PowerShell에서 선택 기능 활성화).
  • 설치: winget install -h Docker.sbx (사용자 단위 설치, 관리자 권한 불필요).
  • 실행: 프로젝트 폴더에서 sbx run claude. 클로드 구독 로그인은 샌드박스 안에서 /login을 입력하며, 세션 토큰은 호스트에 남고 샌드박스에는 저장되지 않는다고 문서가 설명합니다.
연수에는 아직 권하지 않는 이유

Windows Hypervisor Platform은 Docker Desktop과 같은 종류의 가상화 요건이라, 가상화 문제로 막힌 PC에서는 똑같이 막힙니다. 또 비교적 새 제품이어서 명령·화면이 바뀔 수 있고, 이전 형태인 docker sandbox run claude는 문서에서 deprecated로 표시됩니다. 강사가 먼저 시험해 본 뒤 도입 여부를 정하세요. 확인필요

D. WSL 2에 직접 설치

공식 문서는 WSL 2를 Windows에서 클로드 코드를 쓰는 정식 방법 중 하나로 안내하며, 이 방식은 샌드박스 기능도 지원합니다. WSL 터미널을 열어 리눅스용 설치 명령(curl -fsSL https://claude.ai/install.sh | bash)을 실행하면 됩니다. 다만 WSL 2도 가상화가 필요하고, 설치 스크립트와 네트워크 차단 문제는 일부 남습니다.

따라 하기

11. 강사용 사전 준비

연수 당일 20~30명이 동시에 이미지를 빌드하면 학교 네트워크와 Docker Hub 한도 때문에 막힐 수 있습니다. 강사가 한 번 만들고 파일로 나눠 주는 방법입니다.

STEP BY STEP
1

강사 PC에서 이미지를 빌드합니다. 반드시 참가자와 같은 종류의 CPU(대부분의 Windows 노트북은 x64) PC에서 만드세요. Apple Silicon Mac에서 만든 이미지는 ARM용이라 Intel/AMD Windows에서 실행되지 않습니다. Mac에서 만들어야 한다면 아래 명령으로 플랫폼을 지정해 빌드하는 방법이 있습니다. 확인필요

Mac에서 x64용으로 빌드할 때
docker buildx build --platform linux/amd64 -t claude-workshop --load .
2

이미지를 파일 하나로 저장합니다. 이 Mac에서 저장한 결과 약 487MB였습니다.

강사 PC
docker save claude-workshop -o claude-workshop.tar
3

USB나 공유 드라이브로 claude-workshop.tar와 docker-kit 폴더를 나눠 줍니다. 참가자는 Docker Desktop만 설치한 뒤 아래 명령으로 불러옵니다.

참가자 PC (키트 폴더에서)
docker load -i claude-workshop.tar
docker compose run --rm claude

이 Mac에서 save → 이미지 삭제 → load → docker compose run --rm claude claude --version 순서로 실행해, 다시 빌드하지 않고 바로 실행되는 것을 확인했습니다.

연수 전 리허설 체크 (Windows 노트북 1대 이상)

  • Docker Desktop을 학교 관리 계정 권한으로 설치할 수 있다(설치 방식: 현재 사용자 / 모든 사용자).
  • docker compose run --rm claude 실행 후 로그인 주소 복사 → 코드 붙여넣기로 로그인이 끝난다.
  • 컨테이너에서 만든 파일이 work 폴더에 나타나고, 컨테이너를 닫았다 열어도 로그인이 유지된다.
  • /plugin marketplace add revfactory/harness가 성공한다.
  • firebase login --no-localhost로 로그인하고, 이후 클로드 코드 안에서 Firebase 명령이 동작한다.
  • 학교 네트워크에서 이미지 빌드(또는 docker load)가 몇 분 안에 끝난다.
연수 시간 계획에 미치는 영향

Docker Desktop 설치(약 10~15분)와 첫 실행 확인은 연수 시간에 하기에 길고 실패 가능성도 큽니다. 가능하면 연수 전에 사전 과제로 3절을 완료하게 하고, 당일에는 5절(실행과 로그인)부터 시작하도록 안내하세요. 연수 슬라이드에는 M1의 5번(개념), 6번(이미지 빌드), 7번(실행·로그인, 6~7번은 해당자만)으로 반영되어 있습니다. 기본 가이드 HTML은 수정하지 않았습니다.

12. 체크리스트와 참고 자료

  • Docker Desktop이 실행 중이고 docker run --rm hello-world가 성공한다.
  • 키트 폴더(Dockerfile, compose.yaml, work)가 준비되어 있고 docker compose build가 끝났다(또는 docker load 완료).
