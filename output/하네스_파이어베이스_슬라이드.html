이 덱은 전체 연수에서 하네스(revfactory/harness)와 Firebase 부분만 따로 뗀 것이다. 앞부분(Claude Code 설치·첫 대화, 프롬프트, CLAUDE.md·스킬)은 이미 알고 있다고 전제한다. 시작 전 확인: ① Claude Code가 설치되어 로그인되어 있다(Pro·Max·Team·Enterprise 또는 Console 계정) ② Firebase 실습용 개인 구글 계정(학교 관리 계정은 프로젝트 생성이 막힐 수 있음) ③ 실제 학생 이름·계정은 쓰지 않는다. M1·M2(하네스)는 39분, M3(Firebase)는 27분이다. 두 부분은 서로 독립이라 하나만 써도 된다. (1분)

슬라이드 2 · M1 하네스 입문 · 소요 2분

Claude Code 기본 사용법을 안다는 전제에서 시작한다고 전환한다. 혼자 맡기면 생기는 문제는 한 줄만 말한다. 코드를 쓴 바로 그 에이전트가 검토하면 놓친 부분을 또 놓치기 쉽고, "정리해줘" 같은 모호한 요청을 스스로 해석해 필요한 데이터까지 지우는 사고가 보고된 바 있다(원본 표현). 하네스 정의는 《하네스 엔지니어링 with 클로드 코드》(황민호, 한빛미디어) 인용이다: "모델의 가중치를 건드리지 않고, 모델 바깥에 권한·도구·검증·관측을 설계해 에이전트가 홀로 움직이게 만드는 환경." 하네스는 새 AI 모델이 아니라 기존 모델이 동작하는 조건(도구·지침·검증·제어 흐름)을 바꾸는 환경이다. 저자 주장 "모델이 아니라 하네스가 결과를 결정한다"와 평균 점수 49.5 → 79.3은 저자가 직접 한 소프트웨어 엔지니어링 과제 15개 실험이고 관련 저장소 README에도 제3자 재현 검증이 아직 없다고 적혀 있다. 방향성만 참고하고 개선폭은 하나의 사례로 말한다(단서 배지: 저자 자체 실험, 재현 검증 전). 이 연수는 하네스의 원리를 설계하는 시간이 아니라 revfactory/harness를 써서 팀 파일을 만들게 하고 고치는 시간이라고 분명히 안내한다. 구성 요소 이름(에이전트·스킬·오케스트레이터)은 슬라이드 7에서 한 줄씩만 정리한다. (2분)

도식 설명(강사용) 가로 3칸 화살표 "말로 요청 → 하네스가 팀 파일 생성 → 팀 실행·검수". 칸 1에 말풍선 한 줄(예: "형성평가 문항을 만들고 검수하는 하네스를 구성해줘"), 칸 2에 .claude/ 폴더 아이콘, 칸 3에 "만드는 쪽 / 검수하는 쪽" 두 상자. 아래에 작은 단서 배지 "수치 49.5 → 79.3: 저자 자체 실험, 재현 검증 전"은 노트에만 두고 슬라이드에는 넣지 않는다.
