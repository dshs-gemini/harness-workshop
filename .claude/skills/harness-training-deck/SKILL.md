# 하네스 엔지니어링 연수 HTML 슬라이드 오케스트레이터

**목적(브리프):** 특정 앱을 만드는 것이 아니라 Claude Code와 하네스 엔지니어링(에이전트·스킬·오케스트레이터·훅·검수 게이트) 방법을 가르친다. 추가로 Firebase 각 기능을 어떤 상황에 쓰는지, 콘솔 설정은 어떻게 하는지 알려준다. 앱(클래스룸)은 방법을 보여주는 "예시 소재"로만 쓴다.

**원본:** `클로드코드_하네스엔지니어링_교원연수.html` (Track 1 Claude Code 기초, Track 2 하네스, 마무리). **실행 모드:** 혼합. 설계는 서브에이전트, 조사·원고는 병렬 서브에이전트, 검수·조립은 순차.

## 0단계: 맥락 확인
- 이 오케스트레이터 전용 작업 폴더는 `_workspace/deck/`. 없으면 처음부터. 부분 수정 요청이면 해당 모듈 writer → reviewer → builder만 다시. 새 요구면 `_workspace/deck_{타임스탬프}`로 옮기고 새로 시작.
- 기존 `_workspace/`의 클래스룸 PPT 산출물은 건드리지 않는다.

## 1단계: 설계 (순차)
`curriculum-designer`에 브리프와 원본 HTML 경로를 주고 호출. 총 180분(현재 구성: 옛 M6·M7 삭제 후 M7을 프로젝트로 확장, 74장, 사용자가 다르게 말하면 따름), 구성은 대략 Claude Code 기초 → 하네스 엔지니어링 → Firebase 기능 지도·설정 → 종합 실습·점검. 산출: `deck/01_designer_curriculum.md`(모듈, 시간, 슬라이드 수, writer별 지시, Firebase 모듈에서 다룰 기능 목록).

## 2단계: 병렬 제작 (한 메시지에서 동시 호출)
- `slide-writer` × 모듈 수. 원본 HTML의 해당 섹션을 읽고 슬라이드 원고로 재구성한다. 산출: `deck/02_writer_{M}_slides.md`.
- `firebase-guide-researcher` × 1. 산출: `deck/02_researcher_firebase_facts.md`. Firebase 모듈 writer는 이 파일이 있어야 쓰므로, Firebase 모듈은 researcher 완료 후 호출한다(나머지 모듈이 먼저 시작).

## 3단계: 검수
`content-reviewer`에 원고 전체, 원본 HTML, Firebase 사실표를 주고 호출. 확인: 원본과의 내용 일치, 하네스 설명의 정확성(에이전트·스킬 파일 형식), Firebase 메뉴 이름(공식 문서), 시간 합계, 초보자 접근성, 앱 제작 중심으로 흐르지 않았는지(브리프 준수). 산출: `deck/03_reviewer_report.md`. `수정필요`는 해당 writer만 재호출 후 재검수, 최대 2회. 남은 항목은 최종 보고에 명시.

## 4단계: 조립
`html-deck-builder` 호출. 산출: `output/하네스엔지니어링_교원연수_슬라이드.html`.

## 5단계: 보고
산출물 경로, 슬라이드 수·시간 합계, 검수 요약, 미검증(Firebase 실제 콘솔 확인 못한 부분, 렌더 확인 여부), `[확인필요]` 잔여를 알린다.

## 오류 처리
실패 시 1회 재시도, 재실패하면 해당 결과 없이 진행하고 누락을 보고. 한도 소진·인증 오류는 재시도하지 않고 부분 산출물 상태를 확인해 보고. 에이전트 판단을 추측으로 채우지 않는다.

## 테스트 시나리오
- 정상: "연수 슬라이드 HTML 만들어줘" → 설계 → 원고·조사 병렬 → 검수 통과 → HTML 생성, 시간 합계 180분, 슬라이드 번호 연속.
- 오류: researcher가 메뉴 이름을 확인하지 못함 → `[확인필요]`로 남고 최종 보고에 표시, 덱은 정상 조립.
- 부분 재실행: "Firebase 설정 부분만 더 쉽게" → researcher/writer(Firebase)만 재호출 → 재검수 → 재조립.
