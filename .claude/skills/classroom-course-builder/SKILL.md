# 클래스룸 연수 PPT 제작 오케스트레이터

**실행 모드:** 혼합. 설계·실습 설계·검수는 서브에이전트 위임, 슬라이드 작성은 모듈별 병렬 위임.

## 0단계: 맥락 확인
- `_workspace/`가 없으면 처음부터 실행한다.
- 있고 일부 수정 요청이면 해당 단계의 에이전트만 다시 실행한다. (예: "3모듈만 다시" → 해당 slide-writer, 이어서 reviewer, deck-builder)
- 있고 새 요구면 `_workspace`를 `_workspace_{타임스탬프}`로 옮기고 새로 시작한다.

## 1단계: 설계 (순차)
`curriculum-designer`를 호출한다. 산출: `_workspace/01_designer_curriculum.md`. 호출 전에 `firebase-classroom-spec`을 읽게 한다.

## 2단계: 병렬 제작
메시지 한 번에 아래를 모두 호출한다(서로 입력이 독립적이다).
- `slide-writer` × 모듈 수 (각자 모듈 하나 담당)
- `firebase-practice-engineer` × 1 (프롬프트·보안 규칙·완성본)

## 3단계: 교차 검수
`content-reviewer`를 호출한다. 산출: `_workspace/03_reviewer_report.md`.
- `수정필요`가 있으면 해당 writer/engineer를 해당 부분만 다시 호출하고 재검수한다. 반복은 최대 2회. 이유: 무한 수정 루프는 비용만 늘린다. 2회 후에도 남은 항목은 최종 보고서에 명시한다.

## 4단계: 조립
`deck-builder`를 호출한다. 산출: `output/온라인클래스룸_교원연수.pptx`.

## 5단계: 보고
사용자에게 산출물 경로, 검수 결과 요약, 미검증 항목(실제 Firebase 프로젝트로 확인하지 못한 부분), `[확인필요]` 잔여 항목을 알린다.

## 데이터 전달
`_workspace/{phase}_{agent}_{artifact}` 파일. 최종 산출물만 `output/`에 둔다. `_workspace/`는 사후 검증용으로 남긴다.

## 오류 처리
- 에이전트 실패 시 1회 재시도. 재실패하면 해당 결과 없이 진행하고 최종 보고에 누락을 적는다.
- 한도 소진·인증 오류는 재시도하지 않고 부분 산출물 상태를 확인해 보고한다.
- 에이전트의 판단을 추측으로 채우지 않는다.

## 테스트 시나리오
- 정상: "연수 PPT 만들어줘" → 설계 → 병렬 제작 → 검수 통과 → pptx 생성, 슬라이드 수와 시간 합계(180분) 일치.
- 오류: engineer가 완성본을 검증하지 못함 → "미검증" 표시가 최종 보고에 포함되고 PPT는 정상 조립된다.
- 부분 재실행: "5모듈 학습지 부분 더 쉽게" → writer(5)만 재호출 → 재검수 → 재조립.
