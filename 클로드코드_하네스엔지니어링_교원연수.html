클로드 코드 기반 하네스 엔지니어링 교원 연수

클로드 코드(Claude Code)를 처음 켜보는 선생님도, 이 문서를 처음부터 순서대로 따라오면 수업 자료 제작을 돕는 나만의 AI 팀 하나를 직접 설계해볼 수 있도록 구성했습니다.

⏱ 총 소요 시간: 약 3.5~4시간 (Track 1 약 1.5시간 + Track 2 약 2시간) 👤 대상: 클로드 코드를 처음 접하는 교원 💻 준비물: 노트북(macOS 또는 Windows), 터미널, 클로드 계정

이 연수의 목표

이 연수는 두 개의 트랙으로 이어집니다. Track 1은 클로드 코드를 설치하고, 대화하고, 프로젝트에 기억을 남기고, 나만의 명령어를 만드는 법까지 — 클로드 코드를 “혼자 쓸 수 있는” 수준까지 끌어올립니다. Track 2는 카카오 황민호 수석의 저서 《하네스 엔지니어링 with 클로드 코드》와 오픈소스 revfactory/harness 프로젝트가 제시하는 개념을 교육 현장 언어로 재구성하여, 여러 AI 에이전트가 역할을 나누어 협업하는 “하네스”를 직접 설계해보는 단계까지 나아갑니다.

개념 먼저, 그다음 실습

모든 절은 개념과 실습이 번갈아 등장합니다. 개념 절에서는 “왜”를 이해하고, 바로 이어지는 실습 절에서는 그 개념을 손으로 직접 확인합니다. 실습을 건너뛰고 개념만 읽으면 절반만 배우는 것과 같으니, 가능하면 노트북을 펴고 순서대로 따라 해보시길 권합니다.

사전 준비물 체크

  • 노트북 — macOS 13.0 이상 또는 Windows 10 이상. 학교 관리 PC는 관리자 권한 설치 제한이 있을 수 있으니 미리 확인하세요.
  • 터미널 — macOS는 기본 제공되는 ‘터미널’ 앱(Spotlight에서 “터미널” 검색), Windows는 ‘PowerShell’(시작 메뉴에서 “PowerShell” 검색)을 사용합니다. 터미널이 완전히 낯설다면 1.2절에서 최소한의 명령어부터 짚어 드립니다.
  • 클로드 계정 — 클로드 코드는 Claude Pro / Max / Team / Enterprise 요금제 또는 Console(API) 계정이 필요합니다. 무료 claude.ai 계정만으로는 클로드 코드를 사용할 수 없습니다.
  • 실습용 폴더 — 바탕화면 등에 claude-training 같은 빈 폴더 하나를 미리 만들어 두면 좋습니다.
이 문서를 읽는 법

왼쪽 사이드바에서 ● 파란 점은 개념, ● 초록 점은 실습, ● 보라 점은 체크포인트를 뜻합니다. 코드 블록 오른쪽 위의 복사 버튼으로 명령어를 그대로 복사해 터미널에 붙여넣을 수 있습니다. 설치 명령처럼 운영체제별로 다른 코드는 macOS / Windows 탭으로 전환해서 보세요.

개념

1.1 클로드 코드란 무엇인가

클로드 코드는 터미널(명령줄) 안에서 실행되는 “에이전틱(agentic)” AI 도구입니다. 웹의 클로드 채팅창과 무엇이 다른지 먼저 짚고 넘어가겠습니다.

일반 채팅 AI

묻고, 복사하고, 붙여넣는다

코드나 글을 요청하면 채팅창에 답이 나옵니다. 그 결과를 내가 직접 파일로 저장하고, 실행하고, 오류가 나면 다시 채팅창에 오류 메시지를 붙여넣어야 합니다.

클로드 코드

직접 읽고, 쓰고, 실행한다

내 컴퓨터의 실제 폴더 안에서 파일을 스스로 읽고, 새 파일을 만들고, 명령을 실행하고, 그 결과(오류 메시지 포함)를 스스로 확인해 다음 행동을 결정합니다. 사람은 결과를 검토하고 승인하는 역할에 가까워집니다.

이렇게 “스스로 행동하고 결과를 관찰해 다음 행동을 정하는” 루프를 에이전틱 루프(agentic loop)라고 부릅니다. 클로드 코드는 이 루프를 터미널 위에서 반복하면서, 파일 읽기·쓰기, 검색, 명령 실행 같은 “도구(tool)”를 사용해 작업을 끝까지 밀고 나갑니다.

개념 · 왜 “코드” 도구를 수업 자료 제작에 쓰는가

이름은 “코드”이지만 클로드 코드가 다루는 파일이 반드시 프로그램 코드일 필요는 없습니다. 이 연수에서는 클로드 코드를 수업 계획서, 평가 문항, 학생 배포용 HTML 학습 자료 등을 만드는 도구로 사용합니다. 파일을 직접 읽고 쓰고 실행 결과를 스스로 검증할 수 있다는 성질은, 글이나 웹페이지 형태의 자료를 만들 때도 그대로 유용합니다 — 예를 들어 만든 HTML 파일을 브라우저 대신 명령줄에서 문법 오류가 없는지 검사하게 시킬 수 있습니다.

클로드 코드는 터미널 CLI 외에도 데스크톱 앱, VS Code·JetBrains 확장, 웹(claude.ai/code) 등 여러 형태로 제공되지만, 이 연수에서는 가장 기본이 되는 터미널 CLI 사용법을 기준으로 설명합니다. 한 번 터미널 사용법을 익히면 다른 형태로 넘어가는 것은 어렵지 않습니다.

실습

1.2 설치와 첫 대화

클로드 코드를 설치하고, 로그인하고, 첫 문장을 입력해 봅니다. 약 15분 정도 걸립니다.

STEP BY STEP
1

터미널을 엽니다. macOS는 Spotlight(⌘+Space)에서 “터미널”을 검색해 실행하고, Windows는 시작 메뉴에서 “PowerShell”을 검색해 실행합니다. 검은(또는 흰) 화면에 깜빡이는 커서가 보이면 준비 완료입니다.

2

설치 명령을 붙여넣고 Enter를 누릅니다. 아래에서 내 운영체제 탭을 선택하세요. macOS는 공식 설치 스크립트(네이티브 설치)를 사용하는 방법을 권장합니다 — Node.js 같은 별도 프로그램을 먼저 깔 필요가 없습니다.

terminal
curl -fsSL https://claude.ai/install.sh | bash
irm https://claude.ai/install.ps1 | iex
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
Windows 팁

프롬프트가 PS C:\>처럼 PS로 시작하면 PowerShell, C:\>만 보이면 CMD입니다. irm 명령이 CMD에서 “인식할 수 없는 명령”이라고 뜨면 PowerShell 탭의 명령을 시도해 보세요.

3

설치가 끝나면 버전을 확인합니다.

bash
$ claude --version
2.1.211 (Claude Code)

버전 번호가 보이면 설치 성공입니다. command not found 같은 오류가 뜬다면 터미널을 완전히 닫았다가 다시 여는 것만으로 해결되는 경우가 많습니다.

4

실습용 폴더로 이동한 뒤 클로드 코드를 처음 실행합니다. cd는 폴더를 이동하는 명령입니다.

bash
# 바탕화면에 만들어 둔 실습 폴더로 이동
$ cd Desktop/claude-training

# 클로드 코드 시작
$ claude

처음 실행하면 브라우저가 열리며 로그인 화면이 나타납니다. 사용 중인 Claude 계정으로 로그인하고 터미널로 돌아오면, 클로드 코드가 현재 폴더 이름과 함께 대화를 시작할 준비가 된 화면을 보여줍니다.

5

첫 문장을 입력해 봅니다. 아직 아무 파일도 없는 빈 폴더이니, 클로드 코드가 무엇을 할 수 있는지부터 물어봅니다.

claude
> 너는 지금 이 폴더에서 무엇을 할 수 있어? 교사인 내가 수업 자료를 만드는 걸 어떻게 도와줄 수 있는지 3가지만 예를 들어줘

클로드 코드가 답변을 생성합니다…

클로드가 이 폴더가 비어 있다는 것, 그리고 자신이 파일을 만들고 실행할 수 있다는 것을 바탕으로 구체적인 제안을 돌려주는 것을 확인해 보세요.

막혔을 때

로그인 브라우저 창이 뜨지 않으면 방화벽·보안 프로그램이 원인인 경우가 많습니다. 학교 네트워크에서는 잠시 개인 핫스팟으로 시도해 보는 것도 방법입니다. 대화를 끝내고 싶을 때는 /exit를 입력하거나 Ctrl+D를 두 번 누릅니다.

개념

1.3 프롬프트, 컨텍스트, 플랜 모드

클로드 코드와 잘 대화하려면 세 가지 개념만 이해하면 충분합니다.

① 프롬프트는 구체적일수록 좋다

모호한 요청

“퀴즈 좀 만들어줘”

구체적인 요청

“고1 정보 수업 ‘변수와 자료형’ 단원 복습용으로, 객관식 5문항짜리 퀴즈를 만들어줘. 각 문항에 정답과 한 줄 해설을 붙이고, 난이도는 쉬움 3개·보통 2개로 섞어줘”

대상·범위·형식·기준을 문장에 명시할수록 다시 요청할 일이 줄어듭니다.

② 컨텍스트는 자동으로 쌓인다

클로드 코드는 대화가 이어지는 동안 이전 요청과 읽은 파일 내용을 컨텍스트로 기억합니다. 대화가 길어지면 컨텍스트도 커지는데, 관련 없는 이야기가 오래 쌓이면 답변 품질이 흐려질 수 있습니다. 이럴 때 쓰는 두 명령이 있습니다.

명령동작언제 쓰나
/clear대화 기록을 완전히 비웁니다완전히 다른 작업을 새로 시작할 때
/compact지금까지의 대화를 요약해서 압축합니다같은 작업을 계속하되 맥락은 유지하고 싶을 때

③ 플랜 모드 — 먼저 계획하고, 그다음 실행한다

파일을 여러 개 고치거나 새로 만드는 작업처럼 되돌리기 번거로운 일을 시키기 전에는, Shift+Tab을 눌러 플랜 모드(Plan Mode)로 전환할 수 있습니다(화면 하단에 ⏸ plan mode on이 보일 때까지 누릅니다. 최신 버전은 Auto 모드로 시작하므로 세 번 눌러야 할 수 있고, 프롬프트 앞에 /plan을 붙여도 됩니다). 플랜 모드에서는 클로드가 파일을 바로 고치지 않고 “이렇게 하겠습니다”라는 계획만 먼저 제시하고, 사람이 승인해야 실제 작업이 시작됩니다.

권한 모드도 함께 기억해 두세요

Shift+Tab은 플랜 모드뿐 아니라 이후 1.9절에서 다룰 권한 모드(자동 승인 범위)를 순환 전환하는 단축키이기도 합니다. 화면 하단 상태 표시줄에서 지금 어떤 모드인지 항상 확인할 수 있습니다.

실습

1.4 수업 자료 초안 만들어보기

배운 세 개념(구체적 프롬프트·컨텍스트·플랜 모드)을 실제로 써서, 다음 수업 차시 개요를 초안으로 만들어봅니다.

STEP BY STEP
1

이전 실습에서 열어둔 클로드 코드 세션이 있다면 /clear로 대화를 정리하고 새로 시작합니다.

2

Shift+Tab을 눌러 화면 하단에 ⏸ plan mode on이 보일 때까지 전환합니다(또는 프롬프트 앞에 /plan을 붙입니다). 실제 담당 과목을 떠올리며 구체적으로 요청해 봅니다. 예시 프롬프트입니다.

claude — plan mode on
> 고1 정보과학 ‘조건문과 반복문’ 1차시(50분) 수업 개요를 markdown 파일로 만들어줘.
  도입(5분)-전개(35분)-정리(10분) 구조로 나누고, 전개 단계에는 학생이 직접 코드를
  고쳐보는 미니 실습을 하나 포함해줘. 파일 이름은 lesson-01.md로 해줘

계획: lesson-01.md 파일을 새로 만들겠습니다. 구성은 다음과 같습니다…
1. Yes, and use auto mode
2. Yes, manually approve edits   ← 이 연수에서는 이것을 고릅니다
3. No, keep planning
3

제시된 계획을 읽고 “Yes, manually approve edits”를 고르면 lesson-01.md 파일이 폴더 안에 생성됩니다. 이 선택지는 세션을 일반(수동) 모드로 바꾸므로 파일을 만들 때 허용 여부를 한 번 더 묻습니다. 그때 허용하세요. 1번(auto mode)을 고르면 이후 작업이 자동 승인되므로 연수에서는 고르지 않습니다. 3번은 계획을 더 고치게 하고 싶을 때 씁니다. 터미널이 아니라 평소 쓰던 편집기(메모장, VS Code 등)로 파일을 열어 내용을 확인해 보세요.

4

마음에 들지 않는 부분이 있다면 새 파일을 처음부터 만들지 말고, 이어서 수정을 요청합니다. 클로드 코드는 방금 만든 파일을 기억하고 있으므로 무엇을 바꿀지만 말하면 됩니다.

claude
> 전개 단계 미니 실습을 더 쉽게 바꿔줘. for문 대신 if문만 쓰는 문제로 바꿔줘
방금 무슨 일이 있었나

이 짧은 실습 안에 세 가지가 모두 들어 있었습니다. 구체적인 프롬프트(대상·시간·구조·형식 지정) → 플랜 모드(파일을 만들기 전 계획 확인) → 컨텍스트 유지(다시 설명하지 않고 “더 쉽게 바꿔줘”만으로 이어서 수정). 앞으로 모든 실습이 이 세 가지 위에서 이루어집니다.

개념

1.5 CLAUDE.md — 프로젝트의 기억

1.3절에서 컨텍스트는 대화가 끝나면 함께 사라진다고 했습니다. 그런데 “내 수업 자료는 항상 한국어로, 학생 배포용은 HTML 한 파일로, 코드 예제는 파이선으로” 같은 규칙은 대화를 새로 시작할 때마다 매번 다시 설명하고 싶지 않습니다. 이럴 때를 위한 파일이 CLAUDE.md입니다.

CLAUDE.md는 프로젝트 폴더 맨 위에 두는 평범한 markdown 파일입니다. 클로드 코드는 세션을 시작할 때 이 파일을 자동으로 읽어들여, 이후 모든 대화에서 “이미 아는 규칙”처럼 취급합니다. 특별한 프로그램이 아니라 그냥 텍스트 파일이라는 점이 핵심입니다 — 메모장으로 열어 직접 고쳐도 되고, 클로드에게 고쳐달라고 부탁해도 됩니다.

무엇을 CLAUDE.md에 적는가
  • 산출물 형식 — “학생 배포용 자료는 항상 자급형(외부 파일 참조 없는) HTML 한 파일로 만든다”
  • 대상 독자와 어조 — “고등학교 1학년 대상, 존댓말, 어려운 용어는 처음 나올 때 한 줄 설명을 붙인다”
  • 반복되는 제약 — “수식은 KaTeX로 렌더링하고 \ 이스케이프에 주의한다”처럼, 매번 같은 실수를 반복하지 않도록 남겨두는 메모
  • 절대 하지 말아야 할 것 — “학생 개인정보(이름·학번)가 들어간 예시 데이터는 만들지 않는다”
CLAUDE.md의 한계 — 2부에서 다시 만납니다

CLAUDE.md는 산문으로 적은 부탁입니다. 클로드가 대체로 지키려 하지만, 사람이 지침서를 완벽히 암기하지 못하듯 클로드도 가끔 놓칠 수 있습니다. Track 2에서는 역할과 절차를 에이전트·스킬 파일로 나누어 더 체계적으로 관리하는 방법을 배웁니다. 지금은 CLAUDE.md로 시작하는 것으로 충분합니다.

실습

1.6 나의 CLAUDE.md 작성하기

직접 손으로 치지 않고, 클로드 코드에게 대화하듯 불러주는 방식으로 만들어봅니다.

STEP BY STEP
1

실습 폴더에서 클로드 코드를 실행한 뒤, 내장 명령 /init을 입력합니다. 이 명령은 현재 폴더를 훑어보고 기본 뼈대의 CLAUDE.md를 자동으로 만들어 줍니다.

claude
> /init
2

생성된 뼈대에 우리 상황에 맞는 규칙을 이어서 불러줍니다.

claude
> CLAUDE.md에 다음 규칙을 추가해줘:
  1. 이 폴더는 고등학교 정보과 수업 자료 제작용이다
  2. 학생 배포용 산출물은 항상 외부 파일 참조가 없는 자급형 HTML 한 파일로 만든다
  3. 본문은 한국어, 코드와 전문 용어는 원어를 유지한다
  4. 학생 이름·학번 등 개인정보가 들어간 예시 데이터는 절대 만들지 않는다
  5. 코드 예제는 별도 요청이 없으면 파이선으로 작성한다
3

규칙이 실제로 지켜지는지 바로 확인해 봅니다. 앞서 1.4절에서 만든 것과 비슷한 요청을 다시 해보되, 이번에는 형식을 굳이 설명하지 않습니다.

claude
> 조건문 개념을 설명하는 학생용 학습 자료를 하나 만들어줘

(형식을 다시 설명하지 않았는데도, CLAUDE.md 규칙에 따라
자급형 HTML 파일로, 한국어 본문에 파이선 코드 예제를 넣어 생성합니다)
여러 프로젝트를 오가는 선생님이라면

과목별·업무별로 폴더를 나누고 있다면, 폴더마다 서로 다른 CLAUDE.md를 둘 수 있습니다. 반대로 모든 프로젝트에 공통으로 적용하고 싶은 규칙(예: “항상 한국어로 답한다”)은 홈 폴더의 ~/.claude/CLAUDE.md에 적어두면 어느 폴더에서 클로드 코드를 켜도 함께 적용됩니다.

개념

1.7 슬래시 커맨드와 스킬

/init, /clear, /compact처럼 /로 시작하는 명령을 슬래시 커맨드라고 부릅니다. 자주 쓰는 몇 가지만 먼저 정리합니다.

명령기능
/help사용 가능한 명령 목록을 보여줍니다
/clear대화 기록을 초기화합니다
/compact대화를 요약해 압축합니다
/initCLAUDE.md 뼈대를 생성합니다
/permissions권한(허용 범위)을 확인·수정합니다 (1.9절)
/agents서브에이전트 관리 안내 (2부). 요즘 버전은 목록 대신 “서브에이전트는 Claude에게 만들어 달라고 하라”는 안내를 보여 줍니다
/skills설치된 스킬 목록을 보여줍니다
/exit클로드 코드를 종료합니다

여기까지는 클로드 코드가 미리 만들어둔 명령입니다. 그런데 “퀴즈 5문항 만들어줘”처럼 내가 반복해서 시키는 요청이 있다면, 그 요청 자체를 나만의 슬래시 커맨드로 등록해 둘 수 있습니다. 이것이 바로 스킬(Skill)입니다.

스킬 = 저장된 절차서

스킬은 .claude/skills/스킬이름/SKILL.md라는 markdown 파일 하나로 정의됩니다. 파일 맨 위에는 “이 스킬이 무엇을 하는지, 언제 써야 하는지”를 적은 짧은 설명(description)이 있고, 그 아래 본문에는 실제로 수행할 절차를 적습니다. 클로드 코드는 평소에는 이 설명 한 줄만 기억해 두었다가(가벼움), 실제로 필요한 순간에만 본문 전체를 읽어들입니다(필요할 때만 로드). 이 방식을 점진적 공개(progressive disclosure)라고 부르는데, 대화창이 불필요하게 무거워지지 않도록 하는 장치입니다.

스킬의 명령 이름은 SKILL.md의 name 값이 정하고, name이 없으면 폴더 이름을 씁니다. .claude/skills/quiz/SKILL.md를 만들면 /quiz라는 새 슬래시 커맨드가 생기는 식입니다. 직접 만들어 보겠습니다.

실습

1.8 /quiz 커스텀 커맨드 만들기

“주제만 말하면 객관식 퀴즈를 만들어주는” 나만의 명령 /quiz를 만들어봅니다.

STEP BY STEP
1

클로드 코드에게 직접 만들어달라고 부탁하는 것이 가장 쉽습니다. 파일 경로와 형식을 몰라도 됩니다.

claude
> .claude/skills/quiz/ 에 SKILL.md를 만들어줘.
  이름은 quiz, 설명은 "주제를 입력하면 객관식 퀴즈를 생성한다. 사용자가
  /quiz라고 명시적으로 호출했을 때만 실행한다"로 하고,
  $ARGUMENTS로 받은 주제에 대해 객관식 5문항(정답+한 줄 해설 포함)을
  만들도록 본문을 작성해줘. 난이도는 쉬움 2 · 보통 2 · 어려움 1로 섞어줘
2

완성되면 아래와 비슷한 파일이 생성됩니다. 실제로 폴더를 열어 내용을 확인해 보세요.

.claude/skills/quiz/SKILL.md
---
name: quiz
description: 주제를 입력하면 객관식 퀴즈를 생성한다. 사용자가 /quiz라고
  명시적으로 호출했을 때만 실행한다.
disable-model-invocation: true
argument-hint: [주제]
---

## 지시사항

$ARGUMENTS 주제에 대한 객관식 퀴즈 5문항을 만든다.

- 난이도 구성: 쉬움 2문항, 보통 2문항, 어려움 1문항
- 각 문항은 4지선다, 정답 표시, 한 줄 해설 포함
- 학생이 헷갈릴 만한 오답 보기를 최소 1개 이상 포함
- 출력은 markdown 표 형식으로 정리
disable-model-invocation: true가 하는 일

이 설정이 있으면 클로드가 눈치껏 알아서 퀴즈를 만드는 일이 없고, 사람이 /quiz라고 직접 호출했을 때만 실행됩니다. 자동 실행되면 곤란한 명령(배포, 삭제 등)에 특히 유용한 설정입니다.

3

만든 명령을 실제로 사용해 봅니다.

claude
> /quiz 재귀함수

(재귀함수를 주제로 한 5문항짜리 객관식 퀴즈 표를 생성합니다)

주제만 바꿔가며 /quiz 반복문, /quiz 리스트와 딕셔너리처럼 계속 재사용할 수 있습니다. 매번 형식을 설명하지 않아도 되는 것이 핵심입니다.

개념

1.9 권한과 안전장치

클로드 코드가 파일을 스스로 고치고 명령을 실행할 수 있다는 것은 편리하지만, “어디까지 스스로 하게 둘 것인가”는 사람이 정해야 합니다. 이를 위한 것이 권한 모드(permission mode)입니다.

모드동작
일반(Manual) 모드파일 수정이나 명령 실행 전마다 사람에게 승인을 구합니다. 처음 배우는 단계에 가장 안전합니다. (하단 표시 ⏸ manual mode on)
편집 자동 승인(Accept edits) 모드파일 수정은 묻지 않고 진행하고, 명령 실행 등은 승인을 구합니다. (⏵⏵ accept edits on)
계획(Plan) 모드1.3절에서 다룬 모드로, 어떤 변경도 실행하지 않고 계획만 제시합니다. (⏸ plan mode on)
Auto 모드분류 모델이 대신 검토해 위험도가 낮은 작업은 자동으로 진행하고, 위험도가 높다고 판단되는 작업만 승인을 구합니다. (⏵⏵ auto mode on)

최신 버전(v2.1.283 이상)은 Auto 모드로 시작합니다. 처음 배울 때와 개인정보가 있는 폴더에서는 시작하자마자 Shift+Tab을 한 번 눌러 일반(Manual) 모드로 바꾸세요. 이후 누를 때마다 Accept edits, Plan 순으로 순환 전환되고, 화면 하단 상태 표시줄에 지금 어떤 모드인지 항상 표시됩니다. /permissions 명령으로는 “이 명령은 항상 자동 승인”, “이 폴더 바깥은 절대 건드리지 않기”처럼 더 세밀한 규칙도 지정할 수 있습니다.

교원 연수에서 특히 강조하는 원칙

학생 성적·개인정보가 담긴 파일이 있는 폴더, 또는 실제 서비스 중인 웹사이트 배포 작업에는 절대 완전 자동 승인 모드를 쓰지 마세요. 무엇을 삭제하고 무엇을 공개했는지 사람이 눈으로 확인하는 단계를 항상 남겨두는 것이 원칙입니다.

체크포인트

1.10 Track 1 정리

다음 문장에 스스로 답할 수 있다면 Track 2로 넘어갈 준비가 된 것입니다.

  • 클로드 코드가 일반 채팅 AI와 다른 점(파일을 직접 읽고 쓰고 실행 결과를 스스로 확인한다는 점)을 한 문장으로 설명할 수 있다.
  • 내 컴퓨터에 클로드 코드를 설치하고 로그인했다.
  • 플랜 모드(Shift+Tab)로 전환해 파일이 바뀌기 전에 계획을 먼저 확인해 봤다.
  • 내 폴더에 CLAUDE.md를 만들어 반복되는 규칙을 등록했다.
  • 나만의 슬래시 커맨드(/quiz)를 최소 한 번 만들어보고 실행해 봤다.
  • 권한 모드가 왜 존재하는지, 언제 자동 승인을 피해야 하는지 설명할 수 있다.
Track 2로 넘어가기 전에

여기까지는 클로드 코드 “혼자”와 대화하는 법이었습니다. 다음 Track 2부터는 관점이 바뀝니다 — 클로드 “한 명”에게 모든 걸 맡기는 대신, 역할이 나뉜 여러 에이전트가 협업하도록 환경을 설계하는 법을 배웁니다. 이것이 바로 “하네스 엔지니어링”입니다.

개념

2.1 왜 하네스인가

카카오 FDE팀 황민호(로빈 황) 수석의 저서 《하네스 엔지니어링 with 클로드 코드》(한빛미디어)가 제시하는 문제의식으로 Track 2를 시작합니다.

단일 에이전트의 구조적 한계

클로드 코드 하나에게 크고 복잡한 작업을 통째로 맡기면 두 가지 문제가 반복해서 나타납니다. 첫째, 자기 실수를 스스로 알아채기 어렵습니다 — 코드를 작성한 바로 그 에이전트가 자기 코드를 검토하면, 놓친 부분을 또 놓치는 경우가 많습니다. 둘째, 혼자 판단하고 혼자 실행까지 끝내버릴 위험이 있습니다. 예를 들어 “정리해줘”라는 요청을 스스로 해석해 필요한 데이터까지 지워버리는 식의 사고가 실제로 보고된 바 있습니다.

이 문제의 해법으로 저자가 제시하는 개념이 하네스(harness)입니다.

하네스의 정의 — 《하네스 엔지니어링 with 클로드 코드》

“모델의 가중치를 건드리지 않고, 모델 바깥에 권한·도구·검증·관측을 설계해 에이전트가 홀로 움직이게 만드는 환경.”

핵심 명제는 이렇습니다: “모델이 아니라 하네스가 결과를 결정한다.” 저자의 A/B 실험(소프트웨어 엔지니어링 과제 15개 기준)에서, 같은 클로드 모델을 사용했음에도 하네스 구성 차이만으로 평균 품질 점수가 49.5점에서 79.3점으로 상승했다고 보고합니다. 모델을 바꾼 것이 아니라, 모델 주변의 설계를 바꾼 결과입니다.

※ 이 수치는 저자 자신이 수행한 실험(n=15)이며, 관련 저장소 README에는 아직 제3자 재현 검증이 이루어지지 않았다는 점이 명시되어 있습니다. 하네스가 결과에 영향을 준다는 방향성 자체는 참고할 만하지만, 구체적인 개선폭은 하나의 사례로 받아들이는 것이 정확합니다.

다시 말해 하네스는 새로운 AI 모델이 아닙니다. 기존 모델을 어떤 역할 구조·검증 절차·권한 범위 안에 놓아두는가에 대한 설계도입니다. 모델의 능력은 그대로 두고, 모델 바깥의 구조(역할 분리, 검증 단계, 권한 제한)로 결과의 신뢰성을 높이는 접근입니다.

준구 선생님의 “하네스” 개념과의 연결

하네스를 환경 · 컨텍스트 · 커맨드 · 검증 · 가드레일 · 리뷰 · 관측의 일곱 층으로 나누어 보는 관점도 있습니다. 이 연수의 나머지 절들은 이 일곱 요소를, 교사가 오늘 당장 손으로 만들어볼 수 있는 세 가지 산출물 — 에이전트, 스킬, 오케스트레이터 — 로 압축해서 다룹니다.

이 문서에서 “에이전트”라는 말이 가리키는 것

지금까지는 “클로드 코드와 대화한다”고 표현했지만, 하네스를 설계하기 시작하면 대화 상대가 하나가 아니게 됩니다. 메인 세션(사람과 직접 대화하는 클로드)이 특정 역할을 맡은 서브에이전트를 필요할 때 불러 쓰는 구조가 됩니다. 서브에이전트는 각자 독립된 컨텍스트에서 자기 역할만 수행하고, 결과만 메인 세션에 돌려줍니다 — 메인 세션은 서브에이전트에 작업 범위를 지정해 위임하고, 반환된 결과만 받아 이어 갑니다.

2.2 하네스 플러그인 설치하고 첫 팀 만들기

개념으로만 이해한 하네스를, 실제로 배포된 오픈소스 플러그인 revfactory/harness를 설치해 손으로 체험해봅니다. 이 플러그인은 도메인을 한 문장으로 설명하면 에이전트 팀 전체(에이전트+스킬)를 자동으로 설계해 파일로 만들어 줍니다.

2.3 하네스의 세 기둥 — 에이전트 · 스킬 · 오케스트레이터

방금 만든 미니 하네스를 확장하기 전에, 하네스를 이루는 세 가지 구성 요소의 책임을 분리해서 이해할 필요가 있습니다. 세 가지를 한 파일에 뒤섞으면 무엇이 “누구”이고 무엇이 “방법”인지 구분이 안 되어, 팀이 커질수록 관리가 어려워집니다.

A

에이전트 (Agent)

누가 할 것인가. .claude/agents/*.md에 정의되는, 역할과 권한(사용 가능한 도구)을 가진 “사람 격” 단위입니다. 2.2절에서 플러그인이 자동 생성한 quiz-checker가 예입니다.

2.4절에서 직접 만듭니다

B

스킬 (Skill)

어떻게 할 것인가. .claude/skills/이름/SKILL.md에 정의되는 절차서·참고자료입니다. 1.8절의 /quiz가 예입니다. 에이전트가 이 절차서를 참고해 작업을 수행합니다.

2.6절에서 직접 만듭니다

C

오케스트레이터 (Orchestrator)

누가 언제 누구를 부르는가. 에이전트가 셋 이상으로 늘어나면, 메인 세션이 모든 통신을 중계하는 병목이 됩니다. 이때 작업 큐를 공유하고 에이전트끼리 직접 메시지를 주고받게 하는 조율 체계가 필요해집니다.

개념으로만 소개합니다

지금 단계에서 기억할 것

이 연수에서는 오케스트레이터를 “3명 이상이 동시에 협업할 때 필요해지는 통신 규칙” 정도로만 이해하고 넘어갑니다. 학교 현장에서 실제로 자주 쓰게 되는 것은 에이전트 1~2개와 스킬 여러 개를 조합하는 소규모 구성이며, 이 정도만으로도 충분히 효과적인 하네스를 만들 수 있습니다. 다음 두 절에서 에이전트와 스킬을 각각 더 깊이 다룹니다.

2.4 첫 서브에이전트 제대로 정의하기

2.2절에서는 플러그인이 자동으로 만들어 줬다면, 이번에는 프론트매터 각 항목의 의미를 이해하며 같은 것을 손으로 직접 만들어 봅니다.

서브에이전트 파일의 구조

필드의미
name(필수) 소문자와 하이픈으로 된 고유 이름. 서브에이전트를 부를 때 쓰는 식별자입니다.
description(필수) 언제 이 서브에이전트에게 맡겨야 하는지 설명. 메인 세션이 “지금은 이 에이전트를 부를 차례”를 판단하는 근거가 되므로, 막연하게 쓰지 않고 구체적인 상황을 적습니다.
tools사용할 수 있는 도구 허용 목록. 생략하면 모든 도구를 물려받습니다. 검수만 하는 에이전트라면 Read만 주는 식으로 권한을 최소화하는 것이 원칙입니다.
model사용할 모델(sonnet, opus, haiku 등). 단순 검수 작업에는 가볍고 빠른 모델을 배정해 비용과 속도를 관리할 수 있습니다.
본문(markdown)이 에이전트만의 “업무 지침서”입니다. 메인 세션의 지침을 물려받지 않고, 이 내용만 가지고 작업하므로 필요한 맥락을 스스로 다 담고 있어야 합니다.
STEP BY STEP
1

이번에는 검수가 아니라 “평가 문항 난이도 태깅” 역할을 맡는 새 에이전트를 손으로 직접 만들어 봅니다. 실습 폴더에 아래 경로로 파일을 만드세요 (메모장 등 아무 편집기나 사용).

.claude/agents/difficulty-tagger.md
---
name: difficulty-tagger
description: 시험 문항 목록을 읽고 각 문항에 난이도(하/중/상)와
  근거를 태깅한다. 문항 파일이 준비된 뒤 난이도 분류가
  필요할 때 사용한다.
tools: Read, Grep
model: sonnet
---

당신은 평가 문항 난이도 분류 전문가입니다.

## 작업 방식

1. 주어진 문항 파일을 읽습니다
2. 각 문항을 다음 기준으로 하/중/상으로 분류합니다:
   - 하: 개념을 그대로 묻는 단순 확인 문항
   - 중: 개념을 응용하되 단계가 1~2단계인 문항
   - 상: 두 개 이상의 개념을 결합하거나 다단계 추론이 필요한 문항
3. 각 문항 옆에 [난이도: X] 태그와 한 줄 근거를 표로 정리해 보고합니다

## 하지 않는 일

- 문항 내용을 고치거나 새 문항을 만들지 않습니다
- 문항 파일을 직접 수정하지 않습니다 (Write 도구를 사용하지 않습니다)
2

주목할 부분은 본문 마지막의 “하지 않는 일” 항목입니다. 이것이 바로 가드레일입니다 — 이 에이전트가 할 수 없는 일을 파일에 명시적으로 적어두는 것으로, tools 필드에서 Write를 아예 빼는 것과 함께 이중으로 안전장치를 겁니다.

3

1.8절에서 만든 /quiz로 문항을 몇 개 만든 뒤, 새 에이전트를 불러 실제로 태깅을 시켜봅니다.

claude
> /quiz 이진 탐색 트리
> 방금 만든 퀴즈 파일을 difficulty-tagger한테 넘겨서 난이도를 매겨줘
에이전트가 늘어나기 시작할 때

“지금 이 폴더에서 쓸 수 있는 서브에이전트 목록을 보여줘”라고 물어보거나 .claude/agents/ 폴더를 직접 열어 현재까지 만든 서브에이전트를 확인할 수 있습니다(요즘 버전의 /agents는 목록 대신 안내 문구만 보여 줍니다). 에이전트가 서너 개를 넘어가기 시작하면, 각 에이전트의 description이 서로 겹치지 않고 명확히 구분되는지 한 번씩 점검해 보세요 — 설명이 애매하면 메인 세션이 어떤 에이전트를 불러야 할지 헷갈려 합니다.

2.5 좋은 스킬 설계의 원칙

1.8절에서 /quiz 스킬을 이미 만들어봤습니다. 이번에는 스킬을 잘 설계하는 세 가지 원칙을 짚습니다. 스킬 여러 개를 함께 쓰기 시작하면 이 원칙들이 품질 차이를 크게 만듭니다.

원칙 1 — Description이 호출 여부를 결정한다

스킬의 description은 단순한 메모가 아니라, 클로드가 “지금 이 스킬을 써야 하는가”를 판단하는 유일한 근거입니다. “퀴즈 관련 스킬”처럼 막연하게 적으면 필요한 순간에 호출되지 않거나, 반대로 관계없는 순간에 잘못 호출될 수 있습니다.

모호한 description

description: 퀴즈를 만든다

명확한 description

원칙 2 — 점진적 공개(Progressive Disclosure)

1.7절에서 잠깐 언급했던 개념을 조금 더 구체화합니다. SKILL.md 본문은 500줄을 넘기지 않는 것이 권장됩니다. 참고 자료가 방대하다면 SKILL.md에는 “개요와 언제 무엇을 참고할지”만 남기고, 세부 내용은 reference.md, rubric.md 같은 별도 파일로 분리해 필요할 때만 불러 읽게 합니다.

.claude/skills/lesson-plan-writer/

원칙 3 — Why-First (이유를 먼저)

절차만 나열하기보다, 왜 이 순서로 해야 하는지를 한두 문장 앞에 적어두면 클로드가 예외 상황을 만났을 때도 원래 의도에 맞게 판단할 확률이 높아집니다. “3번을 먼저 하고 4번을 하라”보다 “평가 기준을 먼저 확정해야 문항 난이도를 거기에 맞춰 설계할 수 있으므로, 3번을 먼저 한다”처럼 적는 식입니다.

With/Without으로 검증하기

2.6 SKILL.md 만들어보기 — 수업안 작성 스킬

세 원칙을 반영해서, 우리 학교 표준 양식에 맞춘 수업안을 자동으로 만들어주는 스킬을 설계해 봅니다.

STEP BY STEP
1

먼저 참고 자료가 될 우리 학교 수업안 양식을 별도 파일로 준비합니다(점진적 공개 원칙). 실제 학교 양식이 있다면 그 내용을 붙여넣고, 없다면 클로드에게 표준적인 형태로 초안을 만들어달라고 요청해도 됩니다.

claude
> .claude/skills/lesson-plan-writer/template.md 에 우리 학교
  표준 수업안 양식 초안을 만들어줘. 단원명/차시/성취기준/
  도입-전개-정리 시간 배분/평가계획 항목을 포함해줘
2

이제 이 양식을 참조하는 SKILL.md를 만들어달라고 요청합니다. “왜 이 순서인지”를 포함하도록 명시적으로 부탁해 봅니다.

claude
> 같은 폴더에 SKILL.md를 만들어줘. 폴더 이름은 lesson-plan-writer지만
  명령 이름(name)은 lesson으로 해줘.
  description은 "차시 주제와 성취기준을 입력하면 template.md
  양식에 맞춰 수업안을 작성한다. /lesson으로 호출했을 때만 실행"
  으로 해줘. 본문에는 각 단계를 왜 그 순서로 하는지 이유를
  한 줄씩 적고, template.md를 참조하도록 안내문을 넣어줘.
  disable-model-invocation은 true로 해줘
3

생성 결과는 대략 다음과 같은 모습이어야 합니다.

.claude/skills/lesson-plan-writer/SKILL.md
---
name: lesson
description: 차시 주제와 성취기준을 입력하면 template.md 양식에
  맞춰 수업안을 작성한다. /lesson으로 호출했을 때만 실행한다.
disable-model-invocation: true
argument-hint: [단원/차시 주제]
---

## 이 스킬을 쓰는 이유

표준 양식 없이 매번 새로 작성하면 학년/과목 간 수업안 형식이
제각각이 되어 검토와 공유가 어려워집니다. 이 스킬은 template.md에
정의된 우리 학교 양식을 항상 따르도록 강제합니다.

## 절차

1. template.md를 먼저 읽습니다 — 양식을 확인해야 이후 내용을
   양식에 맞게 채울 수 있기 때문입니다
2. $ARGUMENTS로 받은 주제에 맞는 성취기준을 함께 물어봅니다
   (성취기준이 명시되지 않으면 사용자에게 되묻습니다)
3. 도입-전개-정리 시간 배분을 template.md 형식대로 작성합니다
   — 전개 단계에는 반드시 학생 참여형 활동을 하나 이상 포함합니다
4. 완성된 수업안을 lesson-［주제slug］.md로 저장합니다
4

실제로 호출해서 확인합니다.

2.7 나만의 하네스 설계도 — 종합 워크숍

지금까지 배운 개념(에이전트·스킬·오케스트레이터)을 하나로 모아, 실제로 만들어볼 하네스의 설계도를 완성합니다.

오늘 바로 시작하는 법

2.2절에서 설치한 revfactory/harness 플러그인이 이미 준비되어 있다면, 완성한 설계도를 그대로 붙여넣고 이렇게 요청해 보세요: “위 설계도대로 하네스를 구성해줘.” 플러그인이 설치되어 있지 않거나 더 세밀하게 직접 통제하고 싶다면, 대신 “위 설계도대로 .claude/agents/와 .claude/skills/에 필요한 파일을 만들어줘.”라고 요청해도 됩니다. 어느 쪽이든 오늘 연수에서 배운 개별 실습들을 하나씩 다시 반복할 필요 없이, 설계도 자체가 곧 첫 하네스의 명세서가 됩니다.

자주 묻는 질문

클로드 코드 사용료는 어떻게 되나요? 학교 예산으로 감당할 수 있을까요?▾
클로드 코드는 무료 claude.ai 계정으로는 쓸 수 없고 Pro/Max/Team/Enterprise 등 유료 요금제나 Console(API) 계정이 필요합니다. 개인적으로 소규모로 시작한다면 Pro 요금제로 충분히 이 연수의 모든 실습을 진행할 수 있습니다. 여러 교사가 함께 쓸 계획이라면 학교 차원의 Team/Enterprise 도입을 행정 부서와 상의해 보시길 권합니다.
서브에이전트를 여러 개 만들면 속도나 비용이 얼마나 늘어나나요?▾
서브에이전트를 호출할 때마다 별도의 대화(컨텍스트)가 새로 열리므로, 호출 횟수만큼 처리 시간과 비용이 늘어납니다. 그래서 2.4절에서 “권한을 최소화”하고 2.5절에서 “가벼운 모델을 배정”하라고 강조했습니다. 처음에는 에이전트 1~2개로 시작해 정말 필요할 때만 늘려가는 것을 권합니다.
학생에게 직접 클로드 코드를 사용하게 해도 될까요?▾
이 연수는 교사가 수업 자료·행정 업무를 준비하는 용도를 기준으로 설계되었습니다. 학생 실습에 활용하려면 학교의 AI 도구 사용 지침, 개인정보 처리 방침, 계정 관리 방식을 먼저 별도로 검토하시길 권합니다. 특히 1.9절의 권한 모드는 학생 사용 환경에서 더욱 엄격하게 적용되어야 합니다.
CLAUDE.md, 스킬, 서브에이전트 파일들을 동료 교사와 함께 쓸 수 있나요?▾
네. 이 파일들은 모두 프로젝트 폴더 안의 평범한 텍스트 파일이므로, Git이나 학교 공유 드라이브로 그대로 공유할 수 있습니다. 동료 교사가 같은 폴더를 내려받아 클로드 코드를 실행하면 동일한 CLAUDE.md·스킬·에이전트 구성이 그대로 적용됩니다. 여러 하네스가 늘어나면 어떤 버전이 최신인지 기록해 두는 습관이 중요해집니다.
2.2절의 revfactory/harness 플러그인은 Anthropic 공식 기능인가요?▾
아닙니다. Anthropic이 제공하는 것은 플러그인 마켓플레이스라는 “설치 통로” 자체뿐입니다. harness v2 플러그인은 실험 플래그 없이 동작합니다. revfactory/harness는 그 위에서 커뮤니티 개발자가 만들어 공개한 서드파티 플러그인입니다. 그래서 2.2절에서 다룬 것처럼 설치 전에 저장소 내용을 한 번 확인하는 것이 안전합니다. 또한 에이전트 팀 기능은 현재 대화형 세션에서만 동작하며, 자동화 스크립트용 헤드리스 모드(-p 옵션)에서는 사용할 수 없습니다.
오늘 배운 것 이상으로 더 깊이 공부하고 싶다면 어디서부터 보면 되나요?▾
아래 참고 자료 절의 공식 문서와 황민호 저자의 책을 순서대로 읽는 것을 권합니다. 특히 책의 Part 4(실전편)는 코드 리뷰 자동화, 풀스택 기능 구현, 레거시 마이그레이션, 디버깅/RCA 등 이 연수에서 다루지 못한 실전 사례를 다루고 있어, 학교 밖 개발 현장에서 하네스가 어떻게 쓰이는지 참고하기에 좋습니다.
