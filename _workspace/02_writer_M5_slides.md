# 02. 슬라이드 원고: 모듈 5 웹 학습지 (슬라이드 33–39, 25분)

## 가정
- 번호·장수·시간은 커리큘럼 고정값(33–39, 7장, 25분 = 설명 6 / 실습 19)을 그대로 따랐다.
- practice-engineer 결과(`02_engineer_prompts.md` 모듈 5, `02_engineer_rules.md` D4~D7)를 반영해 확정했다. 정답 저장 방식·문항 필드명·임시 규칙 범위의 `[확인필요]`는 해제했다.
  - 정답 저장(D6): 정답은 명세 경로 안에서 `questions[]`의 각 문항에 `answer` 필드로 함께 저장한다. 명세에 없는 새 경로를 만들지 않기 위해서다.
  - 이 경우 학생이 개발자 도구로 정답을 볼 수 있다. 슬라이드 38에서 이 한계를 솔직히 짚고, "정답을 별도 교사 전용 문서로 분리"하는 대안은 명세 밖 변경이므로 심화 아이디어로만 언급한다.
- `questions[]` 문항 필드는 D7로 확정: `type`("essay"/"choice"), `text`, `choices`(선택형 보기 배열, 서술형 `[]`), `answer`(선택형은 0부터 세는 정답 보기 번호, 서술형 `null`). 제출 `answers[i]`는 `questions[i]`의 답(서술형 문자열, 안 쓰면 `""` / 선택형 고른 보기 번호 0부터, 안 고르면 `null`). 화면 표시 보기 번호는 1부터, 저장만 0부터다. 데이터 경로(`classes/{classId}/worksheets/{id}`, `.../submissions/{uid}`)와 `title`, `questions`, `answers`, `submittedAt`은 명세와 동일하다. `feedback`은 모듈 6에서 채운다.
- 실습 중 보안 규칙은 모듈 2에서 쓴 임시 규칙 상태다(D8: 로그인하면 classes 아래 읽기·쓰기 허용, 학습지·제출 경로 포함). 최종 규칙은 모듈 7에서 적용한다.
- 재제출은 병합 저장(merge)으로 answers·submittedAt만 바꾼다(D5). 임시 규칙에서는 덮어써도 막히지 않지만 모듈 6의 feedback이 지워질 수 있고, 최종 규칙(D4)에서는 권한 오류가 된다.
- 모듈 2~4 결과 프로젝트(로그인, 수업 목록, 수업 화면)가 이어져 있다고 가정한다.
- 시간 배분(분): 33=3, 34=3, 35=5, 36=5, 37=4, 38=3, 39=2 → 합계 25.

## [슬라이드 33] 학습지 = 문항지 1장 + 학생별 답안지
- 유형: 개념
- 본문: 문항지는 교사가 1장 만든다.
  답안지는 학생마다 1장씩 쌓인다.
  Firestore(학급 서류함)에 이 두 종류를 나눠 보관한다.
- 도식: 두 칸 트리. 위 칸 `classes/{classId}/worksheets/{id}` (title, questions[]) = "문항지". 그 아래 `submissions/{uid}` (answers, submittedAt) = "학생별 답안지". 학생 3명이 각자 답안지 한 장씩 갖는 그림. feedback 칸은 점선으로 "모듈 6에서 채움" 표시.
- 노트: (3분) "오늘 학습지는 종이 학습지와 똑같이 생각하세요. 문제가 적힌 문항지는 반 전체에 한 장이고, 답이 적힌 답안지는 학생마다 한 장입니다. Firestore는 학급 서류함이라고 했죠. 문항지 서랍 안에 학생별 답안지 칸이 들어 있다고 보시면 됩니다. 이 그림의 경로 이름이 바로 Claude Code에게 알려줄 이름입니다. 문항 하나는 종류(서술형/선택형), 질문, 선택지, 정답으로 구성합니다." 학습 목표: 문항 작성 → 제출 → 교사 확인.

## [슬라이드 34] 답안지 이름이 학생 번호(uid)인 이유
- 유형: 개념
- 본문: 답안지 문서 이름 = 그 학생의 uid(출석 번호표).
  내 번호표와 같은 이름의 답안지만 열 수 있다.
  보안 규칙 원칙 2: 학생은 자기 제출물만 읽고 쓴다.
- 도식: 서랍장 그림. 서랍 라벨이 `uid-A`, `uid-B`, `uid-C`. 학생 A는 `uid-A` 서랍만 열리고 나머지는 잠김 표시. 교사는 전체 열람 가능 표시.
- 노트: (3분) "보안 규칙은 교무실 출입 규칙입니다. 규칙 문장은 이렇게 쉽게 말할 수 있어요. '내 번호표와 같은 이름의 답안지만 열어도 된다.' 그래서 문서 이름을 uid로 정해 둡니다. 이름이 uid이면 규칙이 한 줄로 끝나요. 같은 학생이 다시 제출하면 같은 이름의 문서에 답만 바뀌어 저장됩니다(병합 저장, 슬라이드 36). 이 규칙은 지금 만들지 않고 모듈 7에서 한꺼번에 적용·검증합니다. 지금은 이름 붙이는 방식만 기억해 주세요. (제출 확인 권한은 해당 수업 교사에게 있다는 점도 원칙 3과 연결해 한 줄 언급.)" 사실 관련 추가 확인 없음.

## [슬라이드 35] 교사 학습지 작성 화면 만들기
- 유형: 실습
- 본문: 교사 화면에서 문항을 추가해 학습지를 저장한다.
  서술형과 선택형(정답 포함) 두 종류를 만든다.
  모듈 6의 자동 피드백 초안에 정답을 쓴다.
- 프롬프트:
```
지금 만든 클래스룸에 웹 학습지 작성 기능을 추가해 줘.

1. 교사가 자기가 만든 수업 화면에 들어가면 "학습지 만들기" 영역이 보이게 해 줘. 학생에게는 보이지 않게 해 줘.
2. 학습지 제목을 입력하고, "서술형 문항 추가"와 "선택형 문항 추가" 버튼으로 문항을 여러 개 추가할 수 있게 해 줘.
3. 서술형 문항은 질문 문장만 입력한다.
4. 선택형 문항은 질문 문장, 보기 2~5개, 정답 보기 하나를 입력한다.
5. 저장하면 Firestore의 classes/{classId}/worksheets 컬렉션에 새 문서를 추가하고 title(문자열)과 questions(배열) 두 필드만 저장해 줘. questions의 각 항목은 아래 4개 필드로 해 줘.
   - type: 서술형은 "essay", 선택형은 "choice"
   - text: 질문 문장
   - choices: 선택형은 보기 문장 배열, 서술형은 빈 배열 []
   - answer: 선택형은 정답 보기의 순서 번호(첫 번째 보기가 0인 숫자), 서술형은 null
6. 저장이 끝나면 "저장되었습니다"를 보여 주고, 이 수업의 학습지 목록에 제목이 나타나게 해 줘.
7. 제목이 비었거나, 문항이 없거나, 보기가 2개보다 적거나 정답을 고르지 않은 선택형 문항이 있으면 저장하지 말고 무엇이 빠졌는지 알려 줘.

기존 로그인, 수업, 자료 기능은 그대로 두고, 한 번에 이 기능만 만들어 줘.
```
- 예상 결과: 교사 계정으로 수업에 들어가면 "학습지 만들기" 폼이 보인다. 서술형 1개, 선택형 1개를 넣고 저장하면 목록에 제목이 뜨고, 콘솔 Firestore의 `classes/{classId}/worksheets`에 문서가 생기고, `questions`에 `type`, `text`, `choices`, `answer`가 들어 있다(선택형 `answer`는 숫자, 서술형은 `null`). 제목을 비우고 저장하면 저장되지 않고 빠진 항목 안내가 나온다. 학생 계정 화면에는 작성 폼이 없다.
- 막힐 때:
  - 저장 시 "권한 없음(permission-denied)" → 모듈 2의 임시 규칙이 게시되어 있는지 확인(임시 규칙은 로그인하면 `classes` 아래 `worksheets`를 포함해 허용). 오류 메시지를 그대로 Claude Code에 붙여넣고 "이 오류를 고쳐 줘"라고 요청.
  - 폼이 안 보임 → 교사 계정으로 로그인했는지, 내가 만든 수업인지 확인.
- 노트: (5분) "코드는 쓰지 않습니다. 박스 안의 문장을 통째로 복사해서 Claude Code에 붙여넣으세요. 문항 필드 이름은 정해 둔 대로 넣었습니다. 선택형에는 정답을 같이 저장합니다. 모듈 6에서 정답 비교로 피드백 초안을 만들 때 쓰기 때문입니다. 정답을 이렇게 같이 저장해도 괜찮은지는 슬라이드 38에서 함께 생각합니다. 한 가지 약속: 화면에는 보기 1, 2, 3으로 보이지만 저장은 0, 1, 2로 됩니다. 컴퓨터는 0부터 셉니다. 그래서 첫 번째 보기가 정답이면 answer는 0이에요. 확인은 콘솔의 Firestore 화면에서 문서가 생겼는지, answer 숫자가 맞는지 보면 됩니다."

## [슬라이드 36] 학생 학습지 풀기와 제출
- 유형: 실습
- 본문: 학생 화면에서 학습지를 열어 답하고 제출한다.
  답안지 문서 이름은 내 uid로 한다.
  다시 제출하면 병합 저장으로 답만 바꾼다.
- 프롬프트:
```
이어서 학생이 학습지를 풀고 제출하는 기능을 추가해 줘.

1. 학생이 가입한 수업 화면에 학습지 목록이 보이고, 제목을 누르면 문항이 화면에 나오게 해 줘.
2. 서술형은 글상자, 선택형은 보기 라디오 버튼으로 답하게 해 줘. 학생에게는 정답(answer)을 화면에 보여 주지 마.
3. "제출" 버튼을 누르면 classes/{classId}/worksheets/{id}/submissions/{내 uid} 문서에 answers와 submittedAt(서버 시각)을 저장해 줘. 문서 이름은 반드시 로그인한 학생의 uid로 해 줘. answers는 문항 순서대로의 배열이고, 서술형은 쓴 글(안 쓰면 빈 문자열 ""), 선택형은 고른 보기 번호(첫 번째 보기가 0, 안 고르면 null)로 넣어 줘.
4. 이미 제출한 학생이 다시 열면 이전 답이 채워져 있게 해 줘. 다시 제출할 때는 setDoc의 merge(병합) 옵션으로 answers와 submittedAt만 바꾸고, 나중에 선생님이 쓸 feedback 같은 다른 필드는 지우지 마.
5. 제출 후 "제출했습니다"와 제출 시각을 보여 줘.

기존 기능은 그대로 두고, 이 기능만 추가해 줘.
```
- 예상 결과: 테스트 학생 계정으로 학습지를 열어 답하고 제출하면 "제출했습니다"가 뜬다. 콘솔 Firestore의 `submissions` 아래에 학생 uid와 같은 이름의 문서가 있고 `answers`, `submittedAt`이 들어 있다. `answers[i]`는 문항 순서와 같고 선택형은 0부터 센 번호다. 다시 제출해도 문서는 1개이고 내용만 바뀐다.
- 막힐 때:
  - 학습지가 목록에 안 뜸 → 이 학생이 그 수업에 가입했는지(모듈 3) 확인.
  - 제출 시 권한 오류 → 오류 메시지를 그대로 Claude Code에 붙여넣어 요청하고, 안 되면 임시 규칙 게시 여부 확인.
- 노트: (5분) "시크릿 창이나 두 번째 브라우저에서 테스트 학생 계정으로 로그인해 주세요. 실제 학생 이름이나 계정은 쓰지 않습니다. 프롬프트의 3번이 슬라이드 34에서 배운 부분입니다. 문서 이름이 uid이므로 같은 학생이 다시 제출해도 새 문서가 생기지 않습니다. 4번의 '병합'이 중요합니다. 통째로 덮어쓰면 나중에 모듈 6에서 선생님이 쓴 피드백까지 지워질 수 있어서, 답과 제출 시각만 바꾸도록 했습니다. 다시 제출해 보고 콘솔에서 문서가 1개인지 확인하세요." 

## [슬라이드 37] 교사 제출현황 표
- 유형: 실습
- 본문: 교사 화면에 학생별 제출 여부 표를 만든다.
  학생을 누르면 그 학생의 답안을 본다.
  이 화면은 해당 수업 교사만 본다.
- 프롬프트:
```
이어서 교사용 제출현황 화면을 추가해 줘.

1. 교사가 자기 수업의 학습지를 누르면 "제출현황" 표가 나오게 해 줘.
2. 표에는 수업에 가입한 학생(classes/{classId}/members)을 한 줄씩 보여 주고, 열은 학생 이름, 제출 여부(제출/미제출), 제출 시각으로 해 줘. 학생 이름은 users/{uid}의 name을 사용해 줘.
3. 제출 여부는 classes/{classId}/worksheets/{id}/submissions/{uid} 문서가 있는지로 판단해 줘.
4. 제출한 학생 줄을 누르면 문항별로 그 학생의 답을 보여 주고, 선택형은 학생 답(answers의 번호)과 정답(questions의 answer 번호)이 같은지로 맞음/틀림을 표시해 줘. 보기 번호는 화면에 1부터 보여 줘.
5. 이 화면은 학생에게는 보이지 않게 해 줘.
```
- 예상 결과: 교사 계정에서 학습지를 누르면 가입 학생 목록이 나오고, 제출한 테스트 학생은 "제출", 안 한 학생은 "미제출"로 보인다. 학생 줄을 누르면 문항별 답과 선택형 정오 표시가 보인다.
- 막힐 때:
  - 학생 이름이 비어 있음 → 그 학생이 모듈 2에서 로그인해 `users/{uid}`가 만들어졌는지 확인.
  - 표가 비어 있음 → 학생이 수업코드로 가입했는지(`members/{uid}`) 확인.
- 노트: (4분) "이제 한 바퀴가 돌았습니다. 교사가 만들고, 학생이 풀고, 교사가 확인합니다. 제출 여부를 '그 이름의 답안지가 서랍에 있는가'로 판단한다는 점이 포인트입니다. 학생 이름과 이메일은 최소한만 수집하고 실습은 테스트 계정으로만 합니다(개인정보 원칙). 이 표가 모듈 6에서 피드백 버튼이 붙을 자리입니다." 

## [슬라이드 38] 생각해 보기: 정답이 문항 속에 있으면?
- 유형: 개념
- 본문: 정답을 questions[]에 같이 저장했다.
  학생이 문항 문서를 읽으면 정답도 읽을 수 있지 않을까?
  옆 사람과 1분 토론한 뒤 대안을 찾아 본다.
- 도식: 문항 문서 그림 안에 "질문 / 보기 / 정답" 세 줄. 학생이 문서를 열면 정답 줄까지 보이는 화살표. 오른쪽에 "대안" 두 칸: ① 정답 없이 서술형 중심으로 운영 ② 정답을 교사만 읽는 별도 문서로 분리(심화).
- 노트: (3분) 먼저 질문만 던진다: "화면에는 안 보이게 했지만 데이터 자체는 어떨까요?" 1분 짝 토론 후 설명. 용어 한 줄: 개발자 도구(F12 키로 여는 창) = 브라우저 속 데이터를 들여다보는 점검 창, 교실로 치면 칠판 뒤편을 살피는 점검용 뒷문이다. "솔직히 말씀드리면, 이번 실습 구조에서는 학생이 브라우저 개발자 도구로 문항 문서를 보면 정답이 보일 수 있습니다. 화면에서 숨기는 것과 데이터를 못 읽게 하는 것은 다릅니다. 보안은 화면이 아니라 규칙과 데이터 구조로 합니다. 이것이 보안 감각의 핵심입니다. 오늘 수업의 선택형은 연습·형성평가용이고 성적에 직접 쓰는 평가에는 부적합합니다. 대안은 둘입니다. 첫째, 성적에 쓰는 문항은 서술형 위주로 하고 교사가 직접 확인합니다. 둘째, 정답을 문항과 분리해 교사만 읽는 문서에 두는 방식입니다. 둘째는 데이터 모델 변경이 필요해 오늘은 하지 않고 연수 후 심화 과제로 남깁니다." (정답은 `questions[i].answer`에 함께 저장하는 방식으로 확정, D6. 가입한 학생은 문항을 풀려면 문서를 읽어야 하고 규칙은 문서 단위로 읽기를 허용하므로 `answer` 필드만 숨길 수 없다.)

## [슬라이드 39] 막힘 모음과 복구 지점 checkpoint-m5
- 유형: 정리
- 본문: 모듈 5 완성: 작성 → 제출 → 제출현황.
  막히면 오류 메시지를 그대로 Claude Code에 붙여넣는다.
  그래도 안 되면 `checkpoint-m5`.
- 도식: 3칸 체크리스트. 교사 학습지 작성 / 학생 제출 / 교사 제출현황. 각 칸에 확인 방법 한 줄(콘솔에서 문서 생성 확인).
- 막힐 때:
  - 권한 오류(permission-denied) → 오류 메시지 전체 복사해 붙여넣기. 임시 규칙 점검.
  - 문항이 저장되지 않음/선택형 보기 누락 → 안내 문구에 나온 빠진 항목(제목, 보기 2개 이상, 정답 선택)을 채운다. 안내가 안 나오면 "저장 전에 빠진 입력을 알려 주는 안내를 추가해 줘"라고 요청.
  - 모듈 6에서 정답 비교가 모두 틀림으로 나옴 → 콘솔에서 `answer`가 0부터 센 숫자인지 확인.
- 노트: (2분) 체크리스트 세 칸을 소리 내어 확인한다. "막혔다면 checkpoint 폴더를 열고 다음 모듈부터 따라오세요. 복구 지점 이름은 `checkpoint-m5`입니다. 이 폴더는 모듈 5가 끝난 상태입니다. 다음 모듈 6에서는 이 제출현황 표에 피드백 버튼을 붙입니다." 모듈 5 시간 합계 3+3+5+5+4+3+2 = 25분.
