# 02. 슬라이드 원고: 모듈 2. Firebase 설정 + 구글 로그인 (슬라이드 7–18, 35분)

## 가정
- 번호 범위(7–18), 장수(12장), 시간(35분 = 설명 8 / 실습 27)은 요청에 따라 변경한 값이다. 이전 값은 7–14, 8장, 30분이었다.
- 시간 배분: 개념 7(4분) + 10(4분) = 설명 8분. 실습 8(2) + 9(3) + 11(2) + 12(2) + 13(3) + 14(2) + 15(4) + 16(4) + 17(3) + 18(2) = 27분. 합계 35분. (검산은 슬라이드 18 노트)
- 번호 대응표(옛 → 새): 7→7, 8→8·9로 분리, 9→10, 10→11·12·13으로 분리, 새로 추가 14, 11→15, 12→16, 13→17, 14→18.
- 슬라이드 18은 유형이 [정리]지만 막힘 해결과 복구 지점 사용에 실습 시간(2분)을 쓰므로 실습 시간에 넣었다.
- 슬라이드 13의 "임시 규칙"은 practice-engineer 제안(`02_engineer_rules.md` 7절, 파일명 `firestore.temp.rules`)으로 채웠다(해소됨). 규칙 전문은 슬라이드 분량 때문에 슬라이드에서 빼고 이 원고 맨 아래 부록 A에 7절 그대로 옮겼다(슬라이드에는 "배포 파일 통째로 복사" 한 줄). 게시 버튼 이름과 게시 완료 표시는 콘솔 화면이라 `[확인필요]`로 남긴다.
- 슬라이드 18의 체크포인트 firebaseConfig 교체 방법은 `02_engineer_prompts.md` 0-2절(`firebase-config.js` 파일 하나만 교체, 직접 또는 Claude Code 문장)로 확정했다(해소됨). 복구 지점 폴더 안의 규칙 파일 이름은 `firestore.rules`(임시 규칙 사본, 참고용)다.
- 엔지니어 문서도 새 슬라이드 번호(13~18)로 맞춰져 있다. 슬라이드 16의 "역할은 한 번만 고르고 화면에서 바꿀 수 없게" 문장은 엔지니어 문서(옛12)와 일치함을 확인했다.
- 모듈 2에 영향 있는 설계 결정은 D3(role 변경 불가, 슬라이드 16)과 D8(임시 규칙, 슬라이드 13)이다. D9(users 읽기)는 모듈 2에서는 임시 규칙이 로그인한 사람의 users 읽기를 허용한다는 점만 슬라이드 17 노트에 한 줄 반영했다. 규칙 점검 페이지(`rules-check.html`)는 모듈 7 전용이라 모듈 2 슬라이드에는 넣지 않았다.
- 프로젝트 폴더는 모듈 1에서 만든 것(index.html가 있는 폴더)을 그대로 이어서 쓴다고 가정했다.
- 기술 기준은 커리큘럼대로 빌드 도구 없는 정적 웹(HTML + JS, Firebase JS SDK)이다.
- 역할(role) 선택은 화면 분기용이다. 실제 권한 판정은 모듈 3 이후 `classes/{classId}.teacherUid`로 한다(노트에 명시).
- 콘솔 메뉴 이름, 버튼 이름, 승인된 도메인 위치, 로컬 서버 필요 여부는 모두 `[확인필요]` 처리했다. 새로 나눈 슬라이드 8, 9, 11, 12, 13의 화면 순서와 단추 이름도 확인된 것이 아니라 일반적인 흐름을 적은 것이므로 검수자가 실제 콘솔로 확인해야 한다.
- 새 슬라이드 14는 firebaseConfig를 `export const firebaseConfig = { ... };` 형태의 `firebase-config.js`로 저장하는 단계다. 파일명은 엔지니어 문서(`02_engineer_prompts.md`)와 일치 확인함. 슬라이드 15는 이 파일을 불러 쓰도록 바꿨고(설정값 재붙여넣기 없음), 슬라이드 15·16 프롬프트와 슬라이드 18 복구 안내는 같은 문서의 표현(네 파일 구조, SDK 12.19.0 주소, localhost 명령 요청, 역할 한 번만 선택, `firebase-config.js` 하나만 교체)에 맞췄다.

## [슬라이드 7] Firebase 한 장 정리
- 유형: 개념
- 본문:
  - Firebase = 구글이 빌려주는 "학교 운영 도구 세트"
  - Authentication = 출석부 확인 (누구인지 확인)
  - Firestore = 학급 서류함 (데이터 보관) / Hosting = 학교 게시판 (웹 주소로 공개)
- 도식: 가로 3칸 카드. 왼쪽부터 [Authentication: 출석부 확인 / 아이콘 사람 확인], [Firestore: 학급 서류함 / 아이콘 서류함], [Hosting: 학교 게시판 / 아이콘 게시판]. 카드 아래에 "오늘 모듈 2는 앞의 두 개(Authentication, Firestore)를 씁니다. Hosting은 모듈 7" 한 줄.
- 프롬프트: (해당 없음)
- 예상 결과: (해당 없음)
- 막힐 때: (해당 없음)
- 노트: (4분) "오늘 쓸 Firebase 도구는 세 가지입니다. 출석부 확인은 Authentication, 서류함은 Firestore, 게시판은 Hosting입니다. 우리가 서버를 직접 만들 필요 없이 이 세 가지를 빌려 씁니다. 오늘은 로그인(출석부 확인)과 서류함을 먼저 연결하고, 게시판은 마지막 모듈에서 씁니다." 전문 용어가 나오면 반드시 비유를 같이 말한다. 다음 슬라이드는 바로 손을 움직이는 실습이므로 넘어가기 전에 "구글 계정으로 Firebase 콘솔에 들어갈 수 있는지" 손을 들어 확인한다.

## [슬라이드 8] 프로젝트 생성
- 유형: 실습
- 본문:
  - Firebase 콘솔에서 새 프로젝트 만들기 (이름 예: `my-classroom`). 프로젝트 = 우리 학급 전용 "교실 한 칸"
  - 테스트용 구글 계정(교사용)으로 진행. 실제 학생 정보 사용 금지
  - 순서: 화면에서 찾을 것 → 누를 것 → 확인할 것
- 도식: 단계 화살표 3칸. [콘솔 접속] → [프로젝트 추가] → [프로젝트 홈 도착]. 각 칸에 콘솔 화면 캡처 자리 표시. 캡처 위에 "찾을 것"은 빨간 테두리, "누를 것"은 번호 말풍선으로 표시.
- 프롬프트: (콘솔 작업이므로 Claude Code 프롬프트 없음. 아래 순서를 화면에서 따라 한다.)
  1. 화면에서 찾을 것: 브라우저 주소창 → 누를 것: Firebase 콘솔 주소 `console.firebase.google.com` 입력 후 이동 `[확인필요: 접속 주소]` → 확인할 것: 구글 로그인 화면 또는 Firebase 시작 화면이 보인다
  2. 화면에서 찾을 것: 구글 로그인 화면 → 누를 것: 교사용(테스트) 구글 계정 선택 후 로그인 → 확인할 것: Firebase 콘솔 첫 화면에 "프로젝트 만들기(또는 프로젝트 추가)" 카드나 버튼이 보인다 `[확인필요: 버튼 이름]`
  3. 화면에서 찾을 것: "프로젝트 만들기(또는 프로젝트 추가)" → 누를 것: 그 버튼, 이어서 이름 칸에 `my-classroom` 입력 후 "계속" `[확인필요: 버튼 이름]` → 확인할 것: 이름 아래에 고유 프로젝트 ID가 자동으로 붙어 표시된다 `[확인필요: ID 자동 표시 위치]`
  4. 화면에서 찾을 것: 이어지는 안내 화면(Gemini 사용 안내 `[확인필요: 화면 유무]`, Google 애널리틱스 `[확인필요: 선택 화면 유무]`) → 누를 것: 애널리틱스 스위치는 끄고 "프로젝트 만들기" `[확인필요: 버튼 이름]` → 확인할 것: 프로젝트 준비 중 표시 후 "계속" 버튼이 나타난다
  5. 화면에서 찾을 것: "계속" 버튼 → 누를 것: 계속 → 확인할 것: 프로젝트 홈(왼쪽 메뉴와 가운데 앱 추가 아이콘들)이 열리고 왼쪽 위에 `my-classroom`이 보인다
- 예상 결과: 프로젝트 홈 화면이 열려 있고 왼쪽 위(또는 상단)에 내 프로젝트 이름이 보인다.
- 막힐 때:
  - 프로젝트 만들기 버튼이 안 보일 때: 학교 계정(관리자 제한)이면 개인 구글 계정으로 다시 로그인한다 `[확인필요]`
  - 프로젝트 ID가 이미 쓰인 이름이라고 나올 때: 이름 뒤에 숫자를 붙이거나 화면의 ID 수정 연필을 누른다 `[확인필요: ID 편집 방법]`
- 노트: (2분) 화면을 같이 띄우고 천천히 한 단계씩 시연한다. 콘솔 메뉴 이름은 시기에 따라 바뀔 수 있으니 "화면이 조금 달라도 같은 이름의 버튼을 찾으세요"라고 먼저 안내한다. 조교는 이 단계에서 막힌 분(계정 문제)을 우선 돕는다. 2분 안에 끝난 분은 다음 슬라이드를 먼저 읽게 한다.

## [슬라이드 9] 웹 앱 등록과 firebaseConfig 복사
- 유형: 실습
- 본문:
  - 프로젝트 안에 "웹 앱"을 등록한다 = 교실 안에 "우리 웹 페이지용 출입문" 하나 달기
  - 등록이 끝나면 `firebaseConfig`(설정값 묶음)가 나온다 → 통째로 복사
  - 복사한 값은 메모장에 임시로 붙여 둔다 (슬라이드 14에서 사용)
- 도식: 단계 화살표 4칸. [앱 추가 `</>` 아이콘] → [앱 닉네임 입력] → [firebaseConfig 블록 보임] → [메모장에 복사]. 각 칸에 콘솔 화면 캡처 자리 표시. `[확인필요: 아이콘·메뉴 이름]`
- 프롬프트: (콘솔 작업이므로 Claude Code 프롬프트 없음. 아래 순서를 화면에서 따라 한다.)
  1. 화면에서 찾을 것: 프로젝트 홈 가운데의 앱 아이콘들 중 `</>` 모양(웹) → 누를 것: 그 아이콘 `[확인필요: 메뉴 위치, 아이콘 모양]` → 확인할 것: "웹 앱에 Firebase 추가(또는 앱 등록)" 화면이 열린다
  2. 화면에서 찾을 것: "앱 닉네임" 입력 칸 → 누를 것: 칸을 눌러 `my-classroom-web` 입력 `[확인필요: 입력 칸 이름]` → 확인할 것: 칸에 글자가 들어갔다
  3. 화면에서 찾을 것: "Firebase Hosting도 설정" 체크 칸 → 누를 것: 체크하지 않은 상태로 두고 "앱 등록" 버튼 `[확인필요: 체크 칸과 버튼 이름. Hosting은 모듈 7에서 설정]` → 확인할 것: 다음 단계 화면으로 바뀐다
  4. 화면에서 찾을 것: "SDK 설정 및 구성" 부분의 `const firebaseConfig = { ... }` 블록 `[확인필요: 부분 이름]` → 누를 것: "CDN" 또는 "구성" 선택이 있으면 구성(config) 표시를 선택한 뒤 블록을 마우스로 드래그해 복사(Ctrl+C / Cmd+C) `[확인필요: npm/CDN 선택 화면 유무]` → 확인할 것: `apiKey`, `authDomain`, `projectId` 등이 들어 있는 블록을 복사했다
  5. 화면에서 찾을 것: 내 컴퓨터의 메모장 → 누를 것: 붙여넣기(Ctrl+V / Cmd+V) → 확인할 것: 메모장에 `apiKey`, `projectId` 줄이 보인다. 그다음 콘솔의 "콘솔로 이동" 버튼 `[확인필요: 버튼 이름]`
- 예상 결과: 메모장에 `firebaseConfig` 블록이 복사돼 있고, 콘솔은 프로젝트 홈으로 돌아와 있다.
- 막힐 때:
  - 설정값 화면을 닫아 버렸을 때: 프로젝트 설정(톱니바퀴) → "내 앱"(또는 일반 탭 아래쪽)에서 다시 볼 수 있다 `[확인필요: 메뉴 이름]`
  - 웹 앱 아이콘을 못 찾을 때: 프로젝트 홈에서 "앱 추가" 버튼을 먼저 누른다 `[확인필요: 화면 구성]`
- 노트: (3분) 한 단계씩 시연한다. 가장 많이 놓치는 부분은 4단계 블록 위치와 Hosting 체크이므로 두 곳은 화면을 확대해 보여 준다. "복사한 값은 메모장에 두세요. 다음 슬라이드에서 이 값이 공개되어도 되는지 이야기합니다"라고 연결한다. 3분 안에 끝난 분은 다음 슬라이드(개념)를 먼저 읽게 한다.

## [슬라이드 10] 웹 설정값은 공개돼도 괜찮다
- 유형: 개념
- 본문:
  - `firebaseConfig`는 "학교 주소" 같은 것. 알려져도 문은 열리지 않는다
  - 문을 지키는 것은 **보안 규칙**(교무실 출입 규칙) → 모듈 7에서 완성
  - 단, **AI API 키는 다르다** → 비밀. 모듈 6에서 이유를 본다
- 도식: 좌우 비교 2칸. 왼쪽 "공개해도 됨" 초록(보조색 `#356e67`) 상자: firebaseConfig = 학교 주소. 오른쪽 "절대 공개 금지" 강조색(`#b0402c`) 상자: AI API 키 = 교무실 금고 열쇠. 가운데 방패 아이콘에 "보안 규칙" 표기.
- 프롬프트: (해당 없음)
- 예상 결과: (해당 없음)
- 막힐 때: (해당 없음)
- 노트: (4분) "설정값이 인터넷에 보이면 큰일 아닌가요?"라는 질문이 반드시 나온다. 답: 이 값은 "어느 프로젝트로 연결할지"를 알려주는 주소 역할이고, 누가 무엇을 읽고 쓸 수 있는지는 보안 규칙이 정한다. 그래서 규칙이 중요하며 모듈 7에서 완성한다. 대비해서 AI API 키는 브라우저에 두면 누구나 가져다 쓸 수 있어 비용과 오남용으로 이어지므로 서버에 보관한다(모듈 6 예고. Cloud Functions를 배포하려면 Blaze(종량제) 요금제가 필요하다(공식 문서). 무료 사용량과 AI API 비용은 연수 시점에 확인 `[확인필요: 연수 시점 요금]`). 이 슬라이드가 끝나면 바로 설정 실습으로 넘어가므로 질문은 2분 안에 정리한다.

## [슬라이드 11] 구글 로그인 제공업체 켜기
- 유형: 실습
- 본문:
  - Authentication(출석부 확인)에서 **Google** 로그인 방법을 켠다 = "구글 계정이 있으면 출석 확인을 해 주겠다"고 허락
  - 프로젝트 지원 이메일은 내 교사용 계정으로 선택
  - 순서: 화면에서 찾을 것 → 누를 것 → 확인할 것
- 도식: 콘솔 왼쪽 메뉴 스케치 한 장. [보안(Security) > Authentication → 시작하기 → 로그인 방법 → Google → 사용 설정 → 지원 이메일 선택 → 저장] `[확인필요: 리허설 캡처 - 한국어 메뉴·버튼 이름]`

## [슬라이드 12] 승인된 도메인에 localhost 추가
- 유형: 실습
- 본문:
  - **승인된 도메인** = 로그인 창구를 쓸 수 있는 "허가받은 주소 목록"
  - 2025-04-28 이후 만든 프로젝트에는 `localhost`가 기본으로 없다
  - "도메인 추가"로 우리 실습 주소 `localhost`를 직접 넣는다 (Hosting 주소는 모듈 7에서)
- 도식: 콘솔 Authentication 화면 스케치. [보안(Security) > Authentication → 설정 탭 → 승인된 도메인 → 도메인 추가 → `localhost` 입력 → 추가 후 목록: localhost, (프로젝트 주소).firebaseapp.com …] 추가 후 목록의 `localhost` 줄에 빨간 동그라미. `[확인필요: 리허설 캡처 - 한국어 메뉴·탭 이름]`
- 프롬프트: (콘솔 작업이므로 Claude Code 프롬프트 없음. 아래 순서를 화면에서 따라 한다.)
  1. 화면에서 찾을 것: Authentication 화면 위쪽 탭들 중 "설정(Settings)" `[확인필요: 탭 이름. 시기에 따라 "설정" 아래 하위 메뉴일 수 있음]` → 누를 것: 설정 → 확인할 것: 설정 화면이 열리고 여러 항목 목록이 보인다
  2. 화면에서 찾을 것: "승인된 도메인(Authorized domains)" 항목 `[확인필요: 항목 위치와 이름]` → 누를 것: 항목 선택 → 확인할 것: 도메인 목록이 보인다
  3. 화면에서 찾을 것: 도메인 목록 위쪽의 "도메인 추가(Add domain)" 버튼 `[확인필요: 리허설 캡처 - 한국어 버튼 이름]` → 누를 것: 그 버튼을 눌러 `localhost`를 입력하고 추가 → 확인할 것: 목록에 `localhost`가 한 줄로 보인다 (새 프로젝트에는 기본으로 없으므로 추가가 필요하다. 이미 보이면 추가하지 않는다)
- 예상 결과: 승인된 도메인 목록에 `localhost`가 새로 추가되어 보인다.
- 막힐 때:
  - 승인된 도메인 항목을 못 찾을 때: 설정 화면을 아래로 스크롤하거나 Authentication 안의 다른 탭을 확인한다 `[확인필요: 화면 구성]`
  - 나중에 로그인 때 `auth/unauthorized-domain` 오류가 나면: 이 슬라이드로 돌아와 현재 접속 주소가 목록에 있는지 본다 (슬라이드 18 참고)
- 노트: (2분) 비유: "로그인 창구는 아무 주소에서나 쓸 수 있는 것이 아니라 허가받은 주소에서만 열립니다. 우리 컴퓨터의 임시 주소가 localhost입니다." 지금 추가해 두면 슬라이드 15 이후 가장 흔한 오류를 미리 막는다고 설명한다. 오늘 만드는 새 프로젝트는 모두 localhost가 기본으로 없으므로 "확인"이 아니라 "추가"로 진행한다. 운영 단계에서는 localhost를 목록에서 지우는 것이 공식 권장이다(모듈 7 슬라이드 53에서 한 줄 언급). 접속 주소에 포트 번호(예: `:3000`)가 붙어도 목록에는 localhost만 있으면 되는지는 `[확인필요]`이므로 단정하지 않는다.

## [슬라이드 13] Firestore 만들기 (위치·모드 선택)
- 유형: 실습
- 본문:
  - Firestore(학급 서류함)를 설치한다. **위치(리전)** = 서류함을 둘 건물 위치. 만든 뒤에는 못 바꾼다
  - **모드는 테스트 모드가 아닌 잠금 모드(프로덕션 모드)** 로 시작
  - 임시 규칙은 강사가 제공(`firestore.temp.rules`). 로그인한 사람만 쓰는 연습용이고, 최종 규칙은 모듈 7에서 완성
- 도식: 콘솔 왼쪽 메뉴 스케치 한 장. [데이터베이스 및 스토리지(Databases & Storage) > Firestore → 데이터베이스 만들기 → 위치 선택 → 잠금(프로덕션) 모드 → 만들기 → 규칙 탭] `[확인필요: 리허설 캡처 - 한국어 메뉴·버튼 이름, 화면 순서(모드·위치 선택 순서)]`
- 프롬프트: (콘솔 작업. Claude Code 프롬프트 없음. 아래 순서를 따른다.)
  1. 화면에서 찾을 것: 콘솔 왼쪽 메뉴의 **데이터베이스 및 스토리지(Databases & Storage) > Firestore** `[확인필요: 리허설 캡처 - 한국어 메뉴 표기]` → 누를 것: Firestore → 확인할 것: "데이터베이스 만들기" 버튼이 보인다
  2. 화면에서 찾을 것: "데이터베이스 만들기" 버튼 → 누를 것: 그 버튼 → 확인할 것: 데이터베이스 ID와 위치를 고르는 화면이 열린다 `[확인필요: 화면 순서, 에디션(Standard/Enterprise) 선택 화면 유무]`
  3. 화면에서 찾을 것: "위치(Location)" 선택 목록 `[확인필요: 항목 이름]` → 누를 것: 강사가 안내하는 리전을 선택(예: 서울 `asia-northeast3`은 안내 후보. 권장 리전 확정 필요) 후 "다음" `[확인필요: 권장 리전, 서울 리전 표기 이름]` → 확인할 것: 선택한 위치가 목록 위에 표시된다
  4. 화면에서 찾을 것: 보안 규칙 모드 선택 "프로덕션(잠금) 모드 / 테스트 모드" `[확인필요: 모드 이름]` → 누를 것: **프로덕션(잠금) 모드** 선택 후 "만들기". 테스트 모드는 선택하지 않는다 → 확인할 것: 만들기 후 잠시 기다리면 Firestore 데이터 화면(빈 상태)이 열린다
  5. 화면에서 찾을 것: Firestore 화면 위쪽 "규칙" 탭 → 누를 것: 규칙 탭을 열고, 강사가 나눠 준 `firestore.temp.rules`(복구 지점 폴더에서는 `firestore.rules`) 파일 내용을 통째로 복사해 붙여넣고 "게시(Publish)" 버튼 `[확인필요: 리허설 캡처 - 한국어 탭·버튼 이름]` → 확인할 것: 규칙 탭에 게시 시각이 표시된다 `[확인필요: 리허설 캡처 - 게시 완료 표시]`
  
  (규칙 전문은 슬라이드에 싣지 않는다. 강사 배포 파일 `firestore.temp.rules`를 통째로 복사한다. 전문은 이 원고 맨 아래 "부록 A"와 노트에 있다.)
- 예상 결과: Firestore 화면에 빈 데이터 탭이 보이고, 규칙 탭에 임시 규칙이 게시된 상태.
- 막힐 때:
  - 위치를 고른 뒤 바꾸고 싶을 때: 위치는 만든 뒤 바꿀 수 없으므로(공식 문서) 안내받은 리전을 그대로 쓰고 진행한다
  - "만들기" 단계에서 요금제(Blaze) 안내가 나올 때: Firestore 생성에는 Blaze가 필요 없다(무료 한도 안에서 가능, 공식 요금 문서). 안내가 나오면 결제 정보를 넣지 말고 강사에게 알린다
- 노트: (3분) 테스트 모드를 쓰지 않는 이유를 한 문장으로 말한다. "테스트 모드는 일정 기간 누구나 읽고 쓸 수 있는 상태라 학생 정보가 있는 서류함에는 맞지 않습니다." `[확인필요: 테스트 모드 공개 범위와 기간 표현]` 임시 규칙 설명 한 줄(엔지니어 문서 그대로): "이 임시 규칙은 로그인한 사람이면 실습 데이터를 읽고 쓸 수 있는 연습용입니다. 학생끼리 서로의 답안도 보이는 상태이므로 실제 학생 정보는 넣지 않고, 모듈 7에서 진짜 규칙으로 바꿉니다." 규칙 내용은 엔지니어 문서의 `firestore.temp.rules`를 그대로 쓰고 강사가 임의로 고치지 않는다(전문은 부록 A). 시간이 빠듯한 슬라이드이므로 강사가 단계마다 리허설 캡처를 띄운다. 규칙 읽기 도우미: `signedIn()` = "출석부 확인을 마친 사람인가?", `users`는 본인 서류철만 쓰기, `classes` 아래는 로그인하면 모두 열린다. 코드 읽기는 필수가 아니다. 임시 규칙에는 보안 5원칙이 아직 없다(학생 계정도 수업을 만들 수 있음)는 점도 짧게 말한다. 연수 당일 안에 모듈 7의 최종 규칙을 게시하도록 예고한다. 위치 선택을 모두 같은 값으로 맞추도록 화면에 리전을 크게 띄운다.

## [슬라이드 16] 프롬프트 2: 첫 로그인 시 users 문서 저장 + 역할 선택
- 유형: 실습
- 본문:
  - 처음 로그인하면 `users/{uid}` 문서를 만든다 (name, email, role)
  - 역할(교사/학생)은 처음 한 번 고른다 → **화면을 나누는 용도**
  - 문서 이름(uid)은 "출석 번호" 같은 사용자 고유 번호

- 프롬프트:
  ```
  방금 만든 로그인 페이지에 이어서 기능을 추가해 줘.
  - 로그인에 성공하면 Firestore의 users 컬렉션에서 문서 이름이 로그인한 사용자의 uid인 문서를 확인해 줘. 경로는 users/{uid}야.
  - 그 문서가 없으면(처음 로그인이면) "교사" / "학생" 중 하나를 고르는 역할 선택 화면을 보여 줘.
  - 역할을 고르면 users/{uid} 문서를 만들어 아래 3개 필드를 저장해 줘.
    name: 구글 계정 이름
    email: 구글 계정 이메일
    role: "teacher" 또는 "student" (교사를 고르면 teacher, 학생을 고르면 student)

  - 위 3개 필드 외에 다른 정보(전화번호, 사진 등)는 저장하지 마.

  - 필드 이름과 경로는 위에 쓴 것을 글자 그대로 사용해 줘.
  - 코드를 설명하지 말고 바뀐 점만 짧게 알려 줘.
  ```
- 예상 결과: 처음 로그인하면 "교사 / 학생" 선택 화면이 나오고, 선택하면 환영 문구에 역할이 붙어 표시된다. 로그아웃 후 다시 로그인하면 선택 화면 없이 바로 환영 문구가 나온다.
- 막힐 때:
  - 역할 저장 시 "permission-denied(권한 없음)" 오류가 날 때: 슬라이드 13의 임시 규칙이 게시됐는지 콘솔 Firestore 규칙 탭에서 확인하고, 없으면 다시 게시한다. 그래도 같으면 오류 메시지를 Claude Code에 붙여넣는다.
  - 선택 화면이 로그인할 때마다 뜰 때: "문서가 이미 있으면 건너뛰도록 고쳐 줘"라고 요청한다.

## 부록 A. 슬라이드 13 임시 규칙 전문 (슬라이드 외 항목. 규칙 줄은 `02_engineer_rules.md` 7절과 같고 머리 주석만 줄였다. 강사 배포 파일 `firestore.temp.rules`는 rules 7절 기준)
```
rules_version = '2';

// [임시 규칙] 연수 모듈 2~6 실습용 (Firestore 규칙 탭에 붙여넣기)
// - 로그인한 사람만 읽고 쓸 수 있다. 로그인하지 않은 사람은 모두 거부.
// - users 문서는 본인만 만들고 고친다.
// - classes 아래(수업, 가입, 자료, 학습지, 제출물)는 로그인한 사람 누구나 읽고 쓴다.
//   연습용 설정이므로 실제 학생 정보는 절대 넣지 않는다. 모듈 7에서 최종 규칙으로 반드시 바꾼다.
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    match /users/{uid} {
      allow read: if signedIn();
      allow create, update: if signedIn() && request.auth.uid == uid;
    }

    match /classes/{document=**} {
      allow read, write: if signedIn();
    }

    // 모듈 3 "내가 가입한 수업" 목록(컬렉션 그룹 조회)용
    match /{path=**}/members/{memberId} {
      allow read: if signedIn();
    }
  }
}
```
