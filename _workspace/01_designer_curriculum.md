# 01. 커리큘럼 설계: Claude Code로 나만의 온라인 클래스룸 만들기 (교원 연수 180분)

> **설계자 공지 (오류 처리 규칙에 따른 상단 기재)**
> - 기능 명세 5개(구글 로그인, 수업코드, HTML 자료, 웹 학습지, 맞춤 피드백)는 하나도 줄이지 않았다.
> - 단, **모듈 6의 "AI 호출 Cloud Functions"는 배포하려면 Blaze(종량제) 요금제가 필요하다(공식 문서). 무료 사용량과 AI API 비용은 연수 시점에 확인 `[확인필요]`** 이므로 180분 안에 전원이 실습하기 어렵다. 그래서 모듈 6을 다음과 같이 나눈다.
>   - **기본 경로(전원 실습)**: 피드백 데이터 흐름 완성 — 교사가 제출물을 보고 피드백을 작성·저장, 학생이 자기 피드백만 열람. 여기에 "정답 비교 기반 자동 피드백 초안"을 붙여 개인별 맞춤의 뼈대를 만든다.
>   - **심화 선택 박스**: Cloud Functions에 AI API 키를 두고 제출 답안 기반 AI 피드백을 생성. 강사는 완성본으로 시연하고, 원하는 참가자는 연수 후 과제로 진행한다.
> - 위 분리는 시간과 요금제 제약 때문이며 기능 명세 자체는 변경하지 않았다.

### 시간 배분 원칙 검증
- 고정 확보: 휴식 10분 + 마무리 5분 = 15분
- 나머지 165분 = 설명 47분(약 28%) + 실습 118분(약 72%) (원고 노트 기준)
  - 모듈별 설명/실습: M1 10/5, M2 8/27, M3 7/18, M4 5/15, M5 6/19, M6 7/18, M7 전반 4/16(슬라이드 47 개념 3 + 48 설명 1, 나머지 실습)

### 기술 선택 (slide-writer·practice-engineer 공통 전제)
- 빌드 도구 없는 **정적 웹(HTML + JS, Firebase JS SDK)** 한 폴더 구조. 이유: 설치 단계를 최소화해 초보 교원이 "저장 → 새로고침"으로 결과를 확인하게 한다.
- 배포는 Firebase Hosting, 데이터는 Firestore, 로그인은 Firebase Authentication(구글).
- HTML 수업자료는 Firestore 문서의 `html` 필드에 저장하고 **sandbox iframe**으로 표시한다(Storage는 쓰지 않음 → 설정 단계 1개 절약).
- 역할: `users/{uid}.role`(teacher/student)은 화면 분기용이고, **실제 권한은 `classes/{classId}.teacherUid`로 판정**한다(보안 규칙 원칙 3).

### 사전 준비(연수 안내문에 포함, 슬라이드 3에서 점검)
- 구글 계정 1개(교사용) + 테스트 학생용 구글 계정 1개(또는 시크릿 창용 두 번째 계정). 실제 학생 계정·이름 사용 금지.
- Claude Code 설치 및 로그인 완료. Claude Code는 Pro·Max·Team·Enterprise 또는 Console(API) 계정이 필요하고 무료 플랜으로는 쓸 수 없다. 설치는 공식 설치 명령(macOS: `curl -fsSL https://claude.ai/install.sh | bash`). 유료 계정 준비 여부는 연수 당일이 아니라 사전 안내 단계에서 확인한다.
- Node.js 설치, Firebase CLI 설치(`npm install -g firebase-tools`), 터미널에서 `firebase login` 완료(슬라이드 49 시간 부족 대비. 못 한 사람은 휴식 시간에 한다)
- 크롬 브라우저

## 5. 모듈별 slide-writer 지시사항

공통 규칙 (모든 모듈)
- `course-slide-authoring` 스킬의 원고 블록 형식(유형/본문/도식/프롬프트/예상 결과/막힐 때/노트)을 그대로 쓴다.
- 개념 슬라이드는 연속 3장을 넘기지 않는다. 3장 안에 실습 또는 질문 슬라이드를 둔다.
- 실습 슬라이드는 "프롬프트 → 예상 결과 → 막힐 때" 순서. 코드가 아닌 **Claude Code에 붙여넣을 요청 문장 전체**를 쓴다.
- 전문 용어는 처음 등장할 때 교실 비유 한 줄을 붙인다(Authentication=출석부 확인, Firestore=학급 서류함, 수업코드=교실 열쇠, 보안 규칙=교무실 출입 규칙, sandbox iframe=유리 진열장).
- 데이터 경로·필드 이름은 `firebase-classroom-spec` 데이터 모델과 글자 하나까지 일치시킨다.
- Firebase 콘솔 메뉴 이름, 요금제, 설치 명령처럼 바뀔 수 있는 사실은 `[확인필요]`를 붙인다.
- 각 모듈 마지막 슬라이드의 노트에 해당 **복구 지점 이름**과 사용법("막혔다면 checkpoint 폴더를 열고 다음 모듈부터 따라오세요")을 넣는다.
- 노트에는 슬라이드별 소요 시간(분)을 적고, 모듈 내 합계가 아래 배정 시간과 일치해야 한다.

### 모듈 1. 도입·완성본 데모
- **슬라이드 번호**: 1–6 (6장)
- **시간**: 15분 (설명 10 / 실습 5)
- **학습 목표**: 완성된 클래스룸의 흐름을 보고, Claude Code에 첫 요청을 보내 결과 파일을 확인할 수 있다.
- **실습 산출물**: 빈 프로젝트 폴더 + "환영합니다" index.html (브라우저로 열어 확인)
- **복구 지점**: `checkpoint-0`
- **슬라이드 구성 안**
  1. [정리] 표지: 연수 제목, 오늘의 최종 산출물(배포된 내 클래스룸 주소) 한 줄
  2. [데모] 완성본 데모: 교사 화면(수업 생성→자료→학습지→피드백)과 학생 화면(코드 가입→열람→제출→피드백 확인)을 2분 시연. 도식: 교사·학생 두 줄 흐름도
  3. [개념] 오늘의 지도 + 준비물 점검: 7개 모듈 로드맵, 테스트 계정 원칙(실제 학생 정보 금지)
  4. [개념] Claude Code란: "말로 시키면 파일을 만들어 주는 보조교사" 비유, 우리는 코드를 읽기보다 요청과 확인을 한다
  5. [실습] 첫 요청: 폴더 만들기 → Claude Code 실행 → "환영합니다" index.html 생성 요청 → 브라우저로 열기
  6. [정리] 오늘의 작업 리듬: 요청 → 확인 → 막히면 오류 메시지 그대로 붙여넣기 → 그래도 막히면 checkpoint. 복구 지점 사용법 안내
- **주의**: 데모는 완성본(`checkpoint-final`)을 사용하고, 슬라이드 2에는 화면 캡처 자리 표시를 둔다.

### 모듈 2. Firebase 설정 + 구글 로그인

- **실습 산출물**: 구글 로그인 버튼 → 로그인 후 이름 표시 → Firestore `users/{uid}`(name, email, role) 문서 생성되는 페이지

- **슬라이드 구성 안** (원고 7–18, 12장 기준)
  7. [개념] Firebase 한 장 정리: Authentication(출석부 확인), Firestore(학급 서류함), Hosting(학교 게시판)
  8. [실습] Firebase 콘솔에서 프로젝트 생성 `[확인필요: 한국어 콘솔 메뉴 이름]`

  16. [실습] Claude Code 프롬프트: 첫 로그인 시 `users/{uid}`에 name, email, role 저장 + 역할 선택(교사/학생, 처음 한 번만) 화면
  17. [실습] 확인: 콘솔 Firestore에서 내 문서 보기, 시크릿 창에서 테스트 학생 계정으로 로그인
  18. [정리] 막힘 모음(승인된 도메인, 팝업 차단, localhost 접속) + `checkpoint-m2`
- **주의**: 로컬 확인은 파일 직접 열기가 아니라 로컬 서버(localhost)로 해야 로그인이 동작할 수 있음을 막힐 때에 명시 `[확인필요]`. 역할은 화면 분기용이고 권한 판정은 teacherUid라는 점을 노트에 한 줄 언급.

### 모듈 3. 수업코드 수강신청
- **슬라이드 번호**: 19–25 (7장)
- **시간**: 25분 (설명 7 / 실습 18)
- **학습 목표**: 교사가 수업을 만들어 수업코드를 발급하고 학생이 코드로 가입하는 흐름을 구현할 수 있다.
- **실습 산출물**: 교사용 "수업 만들기"(title 입력 → 6자리 joinCode 발급) + 학생용 "코드로 가입"(→ `classes/{classId}/members/{uid}` 생성) + 내 수업 목록
- **복구 지점**: `checkpoint-m3`
- **슬라이드 구성 안**
  19. [개념] 수업코드 = 교실 열쇠. 데이터 모델 도식: `classes/{classId}`(title, teacherUid, joinCode) 와 `members/{uid}`(joinedAt, uid)
  20. [개념] 보안 원칙 3·4 미리보기: 수업 만들기는 교사만, 수업코드로만 찾고 전체 수업 목록은 못 본다
  21. [실습] 프롬프트: 교사 화면에 수업 만들기 + 헷갈리는 글자(0/O, 1/I) 뺀 6자리 코드 발급
  22. [실습] 프롬프트: 학생 화면에 코드 입력 → 일치하는 수업에 members 문서 추가
  23. [실습] 프롬프트: 교사는 내가 만든 수업, 학생은 내가 가입한 수업 목록 표시
  24. [실습] 짝 활동: 옆 사람 수업코드로 가입해 보기 + "잘못된 코드를 넣으면?" 확인
  25. [정리] 막힘 모음(색인 필요 오류, 권한 오류) + `checkpoint-m3`, 휴식 안내 예고
- **주의**: 원칙 4(코드 조회는 가입 시점만)를 구현 방식과 맞추기 위해 practice-engineer와 조회 방식(수업 문서 이름 = 수업코드, `classes/{코드}` 1건 읽기(get), 결정 D1)을 맞춘다. 슬라이드에는 "전체 목록을 내려받아 비교하지 않는다"는 요점만 쓴다.

### 휴식
- **슬라이드 번호**: 26 (1장), **시간**: 10분
- 유형: 정리. 본문: 휴식 10분 + "막힌 분은 강사석으로 / `checkpoint-m3`에서 이어 시작 가능". 노트에 조교 복구 지원 동선.

### 모듈 4. HTML 수업자료 등록
- **슬라이드 번호**: 27–32 (6장)
- **시간**: 20분 (설명 5 / 실습 15)
- **학습 목표**: 교사가 HTML 자료를 등록하고 학생이 가입한 수업의 자료만 안전하게(sandbox) 열람하게 할 수 있다.
- **실습 산출물**: 교사용 자료 등록 폼(title + html 붙여넣기 → `classes/{classId}/materials/{id}`) + 학생용 수업별 자료 목록·열람(sandbox iframe)
- **복구 지점**: `checkpoint-m4`
- **슬라이드 구성 안**
  27. [개념] 기존 HTML 수업자료(예: 이전 연수에서 만든 자료)를 클래스룸에 올리는 이유와 흐름 도식
  28. [개념] 보안 원칙 1·5: 가입한 수업 자료만 / sandbox iframe = 유리 진열장(보이지만 손댈 수 없다, 자료 속 스크립트가 로그인 정보에 접근 못 함)
  29. [실습] 프롬프트: 교사 수업 화면에 자료 등록 폼(제목, HTML 붙여넣기) + 저장
  30. [실습] 프롬프트: 학생 수업 화면에 자료 목록 + 클릭 시 sandbox iframe(srcdoc)으로 표시
  31. [실습] 확인: 테스트 학생 계정으로 열람, 가입하지 않은 계정으로는 안 보이는지 예고(실제 차단 검증은 모듈 7)
  32. [정리] 막힘 모음(문서 크기 한도 1MiB, 이미지가 깨질 때) + `checkpoint-m4`
- **주의**: sandbox 속성에서 `allow-same-origin`과 `allow-scripts`를 함께 주지 않는다는 점을 노트에 이유와 함께 적는다. 연습용 HTML 샘플 자료 1개를 practice-engineer에게 요청.

### 모듈 5. 웹 학습지
- **슬라이드 번호**: 33–39 (7장)
- **시간**: 25분 (설명 6 / 실습 19)
- **학습 목표**: 문항을 작성하고 학생 제출을 받아 교사가 확인하는 학습지를 구현할 수 있다.
- **실습 산출물**: 교사 학습지 작성(`worksheets/{id}`: title, questions[]) + 학생 제출(`submissions/{uid}`: answers, submittedAt) + 교사 제출현황 표
- **복구 지점**: `checkpoint-m5`
- **슬라이드 구성 안**
  33. [개념] 학습지 = 문항지 1장 + 학생별 답안지. 데이터 모델 도식(worksheets → submissions/{uid})
  34. [개념] 보안 원칙 2: 제출물 문서 이름이 학생 uid인 이유 → 자기 답안지만 열 수 있다
  35. [실습] 프롬프트: 교사 학습지 작성(서술형·선택형 문항 추가, 선택형은 정답 포함 — 모듈 6 자동 피드백에 사용)
  36. [실습] 프롬프트: 학생 학습지 풀기 + 제출(재제출 시 덮어쓰기)
  37. [실습] 프롬프트: 교사 제출현황 표(학생별 제출 여부, 답안 보기)
  38. [개념] 생각해 보기: "정답을 questions[]에 같이 넣으면 학생이 볼 수 있지 않을까?" → 답과 대안(practice-engineer 구현 방식에 맞춰 노트 작성, 필요 시 `[확인필요]`)
  39. [정리] 막힘 모음 + `checkpoint-m5`
- **주의**: 슬라이드 38는 보안 감각을 기르는 질문 슬라이드다. 구현 결정(정답 분리 저장 여부)은 practice-engineer 결과와 일치시킨다.

### 모듈 6. 개인별 맞춤 피드백
- **슬라이드 번호**: 40–46 (7장)
- **시간**: 25분 (설명 7 / 실습 18)
- **학습 목표**: 제출 답안별 피드백을 생성·저장하고 학생이 자기 피드백만 보게 할 수 있다.
- **실습 산출물(기본 경로)**: 교사 제출현황에서 학생별 "피드백 초안 만들기"(정답 비교 + 문항별 안내 문구 조합) → 교사가 수정 → `submissions/{uid}.feedback` 저장 → 학생 화면에 내 피드백 표시
- **심화 선택 박스**: Cloud Functions에서 AI API 호출로 피드백 생성(Functions 배포에 Blaze 요금제 필요, 공식 문서. 무료 사용량·AI API 비용은 `[확인필요]`). 강사 시연 + 연수 후 과제용 프롬프트 제공
- **복구 지점**: `checkpoint-m6`
- **슬라이드 구성 안**
  40. [개념] 맞춤 피드백의 세 단계: 답안 읽기 → 초안 생성 → 교사 검토 후 전달(교사가 최종 책임자)
  41. [개념] 비밀 정보 원칙: AI API 키는 브라우저에 두면 누구나 훔쳐 쓴다 → 서버(Cloud Functions)에 둔다 / 보안 원칙 2 재확인(피드백도 본인만)
  42. [실습] 프롬프트: 정답 비교로 문항별 맞음/다시 보기 + 교사 안내 문구를 조합한 피드백 초안 생성 버튼
  43. [실습] 프롬프트: 교사가 초안을 고쳐 저장 → 학생 화면에 "선생님 피드백" 카드 표시
  44. [실습] 확인: 테스트 학생 계정으로 제출 → 피드백 수신까지 한 바퀴
  45. [데모] 심화 선택 박스: AI 피드백(Cloud Functions) 시연 — 구조 도식(브라우저 → 함수 → AI → Firestore), 요금제·비용 주의 `[확인필요]`, 연수 후 과제 프롬프트 QR/링크 자리
  46. [정리] AI 피드백 활용 윤리(교사 검토 필수, 학생 개인정보 최소 전달) + `checkpoint-m6`
- **주의**: 기본 경로만으로 산출물이 완결되도록 쓴다. 슬라이드 45은 눈에 띄는 "심화 선택" 박스 스타일로 표시하라고 deck-builder에 넘길 표기를 원고에 남긴다.

### 모듈 7. 배포·보안 규칙·마무리
- **슬라이드 번호**: 47–54 (8장)
- **시간**: 25분 (배포·보안 20분 = 설명 4 / 실습 16, 마무리 5분). 슬라이드별: 3+4+4+5+4 + 2+2+1
- **학습 목표**: 보안 규칙 5원칙을 적용해 배포하고, 다른 계정으로 접근 차단을 직접 검증할 수 있다.
- **실습 산출물**: Firebase Hosting 공개 주소 + 보안 규칙 검증 체크리스트(5항목 통과)
- **복구 지점**: `checkpoint-final`
- **슬라이드 구성 안**
  47. [개념] 보안 규칙 = 교무실 출입 규칙. 지금까지 소개한 5원칙 한 장 요약표
  48. [실습] 프롬프트: 5원칙을 그대로 문장으로 주고 firestore.rules 작성 요청 + "각 줄이 몇 번 원칙인지 주석으로 설명해 줘"
  49. [실습] 프롬프트/명령: 규칙 배포 + Hosting 배포 → 공개 주소 확인 `[확인필요: CLI 명령]`
  50. [실습] 검증: 테스트 학생 계정으로 점검 페이지(`rules-check.html`) 버튼 1~6(미가입 수업 자료, 다른 학생 제출물, 수업 만들기, 수업 전체 목록, 내 feedback 고치기, 가입 수업에 자료 쓰기) 막힘 + 확인 버튼(가입 수업 자료, 내 제출물) 열림 확인
  51. [정리] 검증 체크리스트 5항목(원칙 1–5)과 결과 기록, 승인된 도메인에 배포 주소 추가 `[확인필요]`
  52. [정리] 마무리(5분 시작): 오늘 만든 것 한 장 회고 — 7개 모듈 산출물 그림
  53. [정리] 현장 적용 전 체크: 개인정보(최소 수집, 기관 지침), 테스트 데이터 정리, 요금제 확인
  54. [정리] 다음 걸음: 심화 과제(AI 피드백, 디자인 다듬기), 자료 링크, 설문
- **주의**: 슬라이드 50은 반드시 "차단되는 것"을 눈으로 확인하는 실습이어야 한다. 규칙 작성 결과가 데이터 모델 경로와 일치하는지 content-reviewer 검수 대상으로 표시.
