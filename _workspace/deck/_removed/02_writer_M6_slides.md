## [슬라이드 37] 여섯 가지 팀 패턴 ①: 순서, 동시, 골라 부르기
- 유형: 개념
- 본문:
  - 팀이 여러 명이면 "어떤 구조로 협업하나"가 다음 질문이다. 패턴은 외우는 표가 아니라 "내 상황과 비슷한 것을 찾는 사전"이다.
  - 1 파이프라인 / 2 팬아웃·팬인 / 3 전문가 풀
- 도식: 카드 3장을 가로로 놓고, 카드마다 `.flow` 도식 한 줄 + 적용 예시 한 줄.
  - 1 파이프라인 (Pipeline): `[초안 작성] → [사실 검증] → [문체 교정]`. 앞 단계의 결과가 다음 단계의 입력. 예: 초안 → 사실 검증 → 문체 교정
  - 2 팬아웃 · 팬인 (Fan-out/Fan-in): `[같은 문항] → ┬ [난이도 검토] ┬ → [결과 모으기]` (중간 3갈래: 난이도 / 오탈자 / 편향성). 예: 같은 문항을 난이도·오탈자·편향성 관점에서 동시에 검토
  - 3 전문가 풀 (Expert Pool): `[요청] → [라우터] → 국어 / 수학 / 과학 중 해당 과목 1명만 호출`. 예: 과목별 전문 에이전트 중 해당 과목만 호출
- 노트: 에이전트는 별도 컨텍스트에서 실행되는 역할 특화 에이전트이고, 여러 에이전트를 어떤 순서·구조로 실행할지가 패턴이다. 세 가지를 한 줄로 말한다. 파이프라인은 순차 처리(앞 단계 출력이 다음 입력), 팬아웃·팬인은 같은 입력을 병렬로 처리한 뒤 결과를 병합하는 것, 전문가 풀은 입력에 따라 해당 전문가 에이전트를 선택 호출하는 것. 전문가 풀은 누구를 부를지 고르는 "라우터" 역할이 필요하다는 점만 짚는다. 패턴 출처는 원본에 따라 `revfactory/harness` 오픈소스와 황민호 저자의 책이라고 한 줄로 밝힌다. 원본 대비 변경: 도식(`.flow`)은 원본에 없고 카드 문장을 그림으로 옮긴 것. (2분)

## [슬라이드 38] 여섯 가지 팀 패턴 ②: 되풀이, 감독, 층층이. 그리고 오케스트레이터
- 유형: 개념
- 본문:
  - 4 생성-검증 / 5 감독자 / 6 계층적 위임. 실전은 섞어 쓰는 **복합 패턴이 기본값**이다.
  - 에이전트가 3명 이상이면 **오케스트레이터**(하위 에이전트의 호출 순서·입출력을 정의하는 조정 스킬)가 필요하다. 누가 언제 누구를 호출하는지 정하는 통신 규칙이다.
- 도식: 위쪽에 카드 3장(`.flow` 한 줄씩), 아래쪽에 한 줄 복합 예시.
  - 4 생성-검증 (Generate-Verify): `[만들기] → [검사] → 통과? 아니오 → [다시 만들기]` (순환 화살표). 예: 검수 에이전트가 지적하면 재생성(M4에서 만든 "생성+검수" 2인 팀)
  - 5 감독자 (Supervisor): `[감독] → 상황 보고 → [작업자 A] / [작업자 B] / [작업자 C]에 동적 배분`. 예: 규모가 크고 작업량을 예측하기 어려운 프로젝트
  - 6 계층적 위임 (Hierarchical): `[총괄] → [팀장] → [실무자]`. 예: 교과 전체 커리큘럼 총괄 → 단원별 담당 → 차시별 작성
  - 아래 한 줄 도식 "이 연수 덱도 하네스로 만들었다": `설계 → 원고 병렬(팬아웃) → 검수 후 재작성(생성-검증) → 조립(파이프라인)`
- 노트:
  - 복합 패턴 설명(원본 콜아웃): 실전에서 한 가지 패턴만 순수하게 쓰는 경우는 드물다. 예를 들어 "수업 자료 제작 하네스"는 파이프라인(초안 → 검수 → 배포용 변환)과 생성-검증(검수 실패 시 재생성)이 섞인 형태가 된다. 처음 설계할 때는 "이 작업의 병목이 어디인가"를 먼저 찾고, 그 병목을 풀어 주는 패턴부터 하나씩 적용한다.
  - 오케스트레이터(원본 `t2-pillars` C 카드): 에이전트가 셋 이상이 되면 메인 세션이 모든 통신을 중계하는 병목이 된다. 그때 작업 큐를 공유하고 에이전트끼리 직접 메시지를 주고받는 조율 체계가 필요해진다. 이 연수에서는 "3명 이상이 동시에 협업할 때 필요해지는 통신 규칙" 정도로만 이해하고 넘어간다. 학교 현장에서 자주 쓰게 되는 것은 **에이전트 1~2개와 스킬 여러 개**를 조합하는 소규모 구성이며, 이 정도로도 충분히 효과적이다. 이 말을 꼭 한다.
  - 덱 예시: 이 연수 슬라이드 자체를 설계 에이전트가 먼저 계획을 만들고, 모듈별 원고 에이전트가 병렬로 쓰고(팬아웃), 검수 에이전트가 지적하면 해당 원고만 다시 쓰고(생성-검증, 최대 2회), 마지막에 조립(파이프라인)하는 순서로 만들었다. 이 한 줄 도식은 `harness-training-deck` 스킬의 단계와 맞춘 것이다. 선택 예시이므로 시간이 모자라면 말로만 짧게 언급한다.
  - 원본 대비 변경: 생성-검증 예시 "2.2절의 quiz-checker가 지적하면 재생성"을 "M4에서 만든 생성+검수 2인 팀"으로 바꿨다(절 번호 대신 덱 모듈). 덱 예시 도식은 원본에 없는 추가 내용. (2분)

## [슬라이드 39] 패턴 맞히기: 이 업무는 어떤 패턴일까요?
- 유형: 점검
- 본문:
  - 아래 학교 업무 3개는 각각 여섯 패턴 중 무엇에 가장 가까운가?
  - 혼자 1분 생각, 짝과 1분 답 맞추기.
- 도식: 사례 카드 3장(번호만 매기고 패턴 이름은 숨김).
  - 사례 A: "같은 시험 문항을 난이도, 오탈자, 편향성 세 관점에서 한꺼번에 검토한다."
  - 사례 B: "교과 전체 커리큘럼 총괄이 단원별 담당에게, 단원별 담당이 차시별 작성자에게 일을 내려보낸다."
  - 사례 C: "국어·수학·과학 전문 에이전트 중 요청에 해당하는 과목 하나만 불러 쓴다."
- 노트: 정답은 A = 팬아웃·팬인, B = 계층적 위임, C = 전문가 풀. 이 3개는 원본 패턴 카드의 예시 문장을 순서만 섞어 쓴 것이다. 틀려도 괜찮다고 먼저 말한다. 판별 요령 한 줄: A는 "동시에, 같은 입력", B는 "위에서 아래로 단계가 내려감", C는 "골라서 하나만". 여유가 있으면 "사례 A를 검토 후 틀린 문항만 다시 만들게 하려면 어떤 패턴이 섞이나요?"(생성-검증)를 덧붙인다. 보너스: 파이프라인(초안 → 사실 검증 → 문체 교정), 생성-검증, 감독자는 38번 슬라이드의 카드를 다시 보게 하면 된다. 이 슬라이드는 실습 시간(질문)으로 센다. (2분)

## [슬라이드 40] 워크숍: 내 업무에 맞는 패턴 찾기 (5문항)
- 유형: 실습
- 본문:
  - 코드를 쓰는 실습이 아니다. 내가 하는 반복 업무 하나로 종이(또는 화면)에 설계도를 그린다.
  - 5문항을 위에서 아래로 채운다. **3번(사람이 개입할 단계)은 다음 모듈에서 다시 쓴다.**
- 프롬프트: 이 실습은 Claude Code에 붙여넣는 문장이 없다. 워크숍 시트(종이 또는 메모)에 아래 5문항을 적는다. 막막하면 4번째 줄의 "예"를 그대로 따라 써도 된다.
  1. 반복해서 하고 있는 업무는 무엇인가요? (예: 매주 형성평가 문항 제작 및 학년 부장 검토)
  2. 이 업무를 단계별로 쪼개면 몇 단계인가요? 각 단계에 이름을 붙여 보세요. (예: ① 문항 초안 작성 → ② 난이도 태깅 → ③ 교사 검토 → ④ 최종본 정리)
  3. 이 중 사람이 반드시 개입해야 하는 단계는 어디인가요? (M7에서 다시 확인합니다) (예: ③ 교사 검토는 사람이 반드시 확인)
  4. 여섯 가지 패턴 중 가장 가까운 것은 무엇인가요? (예: 파이프라인 + 생성-검증)
  5. 이 구조라면 에이전트는 몇 개, 스킬은 몇 개가 필요할 것 같나요? (예: 에이전트 2개(난이도 태깅, 최종 형식 정리) + 스킬 1개(문항 생성 절차))
- 예상 결과: 5문항이 모두 채워진 워크숍 시트 1장. 예시 답이 그대로 들어간 시트의 모양은 다음과 같다.
  - 1 매주 형성평가 문항 제작 및 검토
  - 2 ① 초안 → ② 난이도 태깅 → ③ 교사 검토 → ④ 최종본 정리
  - 3 ③ 교사 검토
  - 4 파이프라인 + 생성-검증
  - 5 에이전트 2개 + 스킬 1개
  (이 예시는 안내용이며, 내 업무로 바꿔 쓰는 것이 목표다.)
- 막힐 때:
  - "업무가 떠오르지 않아요" → 시험 문항 만들기, 수업 안내문 쓰기, 학부모 알림장 초안처럼 지난주에 두 번 이상 한 일을 하나 고른다. 실제 학생 이름이나 개인정보는 적지 않는다.
  - "몇 단계로 쪼개야 할지 모르겠어요" → 3~5단계면 충분하다. 단계마다 "누가(사람/에이전트) 하는가"만 표시한다.
- 노트: 원본(`t2-pattern-workshop`)의 5문항과 예시를 그대로 옮겼다. 원본 대비 변경은 두 가지. 3번의 "2.11절에서 다시 확인합니다"를 "M7에서 다시 확인합니다"로, 4번의 "2.7절의 여섯 패턴"을 "여섯 가지 패턴"으로 바꿨다(절 번호 대신 덱 모듈). 3번 답은 M7 슬라이드 47(게이트 위치 표시)에서 다시 꺼내 쓰므로, 시트를 사진으로 찍거나 보관해 두게 한다. 순회하며 4번을 보고 "병목이 어디인가"를 질문한다(복합 패턴이 정상이라고 안심시킨다). 앱 제작 이야기로 흐르지 않게, 대상은 본인의 반복 업무다. (5분)

## [슬라이드 41] 짝에게 30초 설명하기
- 유형: 정리
- 본문:
  - 짝에게 30초: "내 업무는 ○○이고, 패턴은 △△이며, 사람이 꼭 볼 곳은 □□이다."
  - 다른 교과의 업무에서도 같은 패턴이 반복해서 나타난다.
- 도식: 3칸 문장 틀 `업무 ○○ ─ 패턴 △△ ─ 사람이 볼 곳 □□`
- 노트: 원본 팁(짝과 함께 하는 방법)을 줄인 슬라이드다. 원본은 5분씩 서로의 설계도를 설명하고 피드백을 나누라고 하지만, 시간 때문에 30초로 줄였다. 다른 교과의 반복 업무를 들어 보면 의외로 같은 패턴이 재사용된다는 점을 짚는다. 이 슬라이드는 실습 시간으로 센다. 다음 예고: M7에서는 방금 적은 3번 답을 다시 보고, 사람이 반드시 확인할 위치를 게이트로 표시한다. (1분)
