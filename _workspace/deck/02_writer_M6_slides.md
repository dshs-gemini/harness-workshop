## [슬라이드 34] Firebase 기능 지도: 앱 백엔드 서비스 묶음
- 유형: 개념
- 본문:
  - Firebase = Google의 앱 백엔드 플랫폼. 여러 서비스의 묶음이며 필요한 서비스만 골라 쓴다.
  - 오늘 6개 항목: Authentication, Firestore, 요금제, Storage, Hosting, Cloud Functions
  - 무료(Spark)로 되는 것과 결제 수단(Blaze)이 필요한 것이 나뉜다.
- 도식: 6개 카드가 한 장에 놓인 지도. 카드마다 `[역할 한 줄] / 기능 이름 / 요금제 표식 / 클래스룸 예시 한 단어`.

  | 기능 | 역할 | 요금제 표식 | 클래스룸 예시 한 단어 |
  |---|---|---|---|
  | Authentication | 사용자 인증, uid 발급 | Spark | 로그인 |
  | Firestore | 문서 지향 NoSQL 데이터베이스 | Spark | 수업 기록 |
  | 요금제(Spark/Blaze) | Spark = 무료 요금제 / Blaze = 종량제 | — | 선택 |
  | Storage | 파일(객체) 저장 | **Blaze 필요** | 큰 파일 |
  | Hosting | 정적 웹 콘텐츠 호스팅, 공개 URL | Spark | 공개 주소 |
  | Cloud Functions | 서버리스 백엔드 코드(비밀 키 사용 가능) | **Blaze 필요** | AI 피드백 |

  표 아래 범례: 내가 직접 해 볼 것 = Authentication · Firestore / 강사 시연(심화 선택) = 요금제 · Storage · Hosting · Functions.
  표 아래 한 줄: 접근을 제한하는 보안 규칙은 이 연수에서 설명하지 않는다. Claude Code가 작성하고 배포한다(M7).
- 노트: 오늘의 학습 목표는 "6개를 언제 쓰는지 고르고, 인증·DB를 설정한다"이다. 지도를 먼저 보여 주고, 앞쪽 2개는 직접 손을 움직인다고 예고한다. 접근 규칙은 설명하지 않고 Claude Code가 만든다는 점을 한 줄만 말한다. Spark/Blaze 표식은 사실표 8절 기준이다. Storage 표식은 "2026-02-03부터 Blaze 필요"이다(검수 확인: pricing 페이지 Spark의 Cloud Storage가 "Not applicable", Storage FAQ와 일치). Hosting이 Spark로 되는 이유는 사실표 8절. 클래스룸은 예시 소재일 뿐 앱을 만들지 않는다고 한 번 더 말한다. (1분)

- 본문:
  - Firebase 프로젝트 = 서비스·설정·앱을 묶는 최상위 단위. 하나 만들어 보자.
  - 이름에 **test**를 넣는다. 실제 학생 정보는 넣지 않는다.

  2. **프로젝트 만들기(추가)** 버튼 클릭 `[확인필요: 정확한 버튼 문구]`
  3. 프로젝트 이름 입력(예: `classroom-test-이니셜`, **실명은 넣지 않는다**) → 약관 확인 → 계속
     - 이름은 내가 알아보려고 붙이는 표시이고, 나중에 바꿀 수 있다.
     - 이름과 별개로 Firebase가 고유한 **프로젝트 ID**를 자동으로 정해 준다. ID는 만든 뒤에는 바꿀 수 없고, `PROJECT_ID.web.app` 같은 공개 주소에 드러난다. 영문 소문자·숫자·하이픈만 쓴다. M7에서 이 ID를 Claude Code에 알려 준다.
  4. Gemini in Firebase, Google Analytics 단계가 나오면 연수에서는 **끄거나 기본값** `[확인필요: 화면 순서]` (Analytics는 끄기 권장, 작성자 판단). Gemini를 켜더라도 **Gemini API 키는 절대 코드에 넣지 않는다**(36번)
  5. **프로젝트 만들기(Create project)** 클릭 → 프로젝트 개요 화면이 뜨면 성공
- 프롬프트: (Claude Code 사용 없음. 콘솔 직접 조작)
- 예상 결과: 프로젝트 개요(Overview) 페이지가 열려 있고 상단에 내 프로젝트 이름이 보인다.
- 막힐 때:
  - 프로젝트 만들기가 막히거나 권한 오류 → 학교 관리(Workspace) 계정일 수 있다. 개인 구글 계정으로 다시 로그인 `[확인필요: 학교 계정에서 생성이 막히는지]`.
  - 버튼 문구가 다르면 화면의 "프로젝트 추가/만들기"에 해당하는 버튼을 고른다. 강사 화면과 짝 화면을 본다.
- 노트: 프로젝트는 Authentication, Firestore 같은 서비스와 그 설정, 등록된 앱을 묶는 최상위 단위다. 사실표 1절 기준. 프로젝트 생성은 Spark(무료)로 시작한다. 이미 만든 프로젝트에 기능만 추가할 때는 새 프로젝트를 만들지 않는다(사실표 1절). 사실표는 9단계였으나 5단계로 압축했다(웹 앱 등록은 36번으로 이동). 버튼 문구와 Gemini/Analytics 화면 순서는 사실표 11절 1번에 따라 `[확인필요]`. 연수 후에 이 프로젝트를 삭제하는 방법은 52번에서 안내한다. 예시 이름에 실명을 넣지 않는 이유: 프로젝트 ID가 공개 주소에 드러난다(검수 7-D). 이름과 ID의 관계(공식 문서 https://firebase.google.com/docs/projects/learn-more): 프로젝트 이름은 여러 프로젝트를 구별하려는 내부 표시라 언제든 바꿀 수 있다. 프로젝트 ID는 Firebase가 고유하게 자동 지정하고, 프로젝트를 설정하는 동안에는 고칠 수 있지만 리소스가 만들어진 뒤에는 바꿀 수 없다. 문서에는 ID가 이름에서 만들어진다는 설명이 없으므로 "이름에서 만들어진다"고 말하지 않고, 화면에 ID가 보이거나 고칠 수 있는 칸이 나오면 거기에도 실명이 없는지 같이 본다 `[확인필요: 화면에서 ID가 보이는 위치]`. 공개 주소가 `PROJECT_ID.web.app` 형태라는 점은 M7 배포 주소와 이어진다. Gemini in Firebase를 켜는 선택지가 나오므로 "Gemini 같은 AI 서비스 키는 비밀"이라는 점을 36번과 연결해 한 줄 말한다. (3분)

## [슬라이드 36] 공통 설정 2: 웹 앱 등록과 firebaseConfig
- 유형: 실습 (참가자 실습, Spark)
- 본문:
  - 웹 앱 등록 = 프로젝트에 웹 앱 구성(firebaseConfig)을 생성하는 일.
  - **firebaseConfig(안에 든 apiKey 포함) = 클라이언트가 프로젝트를 식별하는 설정값. 공개되어도 된다. 접근 통제는 Claude Code가 만드는 보안 규칙이 맡는다(M7).**
  - **AI 서비스 키(Gemini 등)·서비스 계정 키 = 서버 측 자격증명. 저장소·클라이언트 코드에 노출하면 안 된다.**
    (서비스 계정 키 = 서버가 관리자 권한으로 접속할 때 쓰는 자격증명 파일, JSON)
- 도식: `.steps` 4단계 + 오른쪽에 2칸 비교 카드
  1. 프로젝트 개요 페이지에서 **웹 아이콘(`</>`)** 클릭
  2. **앱 닉네임** 입력(내부 구분용 이름일 뿐)
  3. **앱 등록(Register app)** 클릭
  4. 화면에 나오는 `firebaseConfig`를 **눈으로 확인**만 한다(복사해서 붙일 앱은 만들지 않는다)

  비교 카드:
  - 공개해도 OK (프로젝트 식별 설정값): `firebaseConfig` 전체, 그 안의 `apiKey` 포함. 프로젝트를 식별만 하고 권한은 주지 않는다.
  - 절대 공개 금지 (서버 측 자격증명): 서비스 계정 키(JSON), AI 서비스 키(Gemini 등), 외부 서비스 비밀 키
- 프롬프트: (Claude Code 사용 없음. 콘솔 직접 조작)
- 예상 결과: `firebaseConfig` 코드 블록이 화면에 보인다. 항목은 apiKey, authDomain, projectId 등이다 `[확인필요: 항목 전체 목록은 문서 본문에서 미확인, 일반적으로 알려진 형태]`.
- 막힐 때:
  - 웹 아이콘이 안 보임 → 프로젝트 개요 페이지로 돌아가 "앱 추가" 영역을 찾는다 `[확인필요: 화면 위치]`.
  - "설정값을 숨겨야 하나?" → 숨기지 않아도 된다. 접근 통제는 Claude Code가 만드는 보안 규칙이 맡는다(M7).
- 노트: 공개 가능 근거는 공식 문서(https://firebase.google.com/docs/projects/api-keys, 검수 확인): 키는 프로젝트와 앱을 **식별**할 뿐 **권한 부여**는 하지 않는다. **안전한 조건: 그 키가 Firebase 서비스로만 제한되어 있어야 하고, 허용 목록에 Generative Language API(Gemini)가 없어야 한다.** 그래서 Gemini API 키는 절대 코드에 넣지 않는다. 서비스 계정 키·AI 서비스 키도 코드·HTML·깃에 넣지 않는다. 참가자는 화면에서 `apiKey`라는 글자를 직접 보므로, "API 키는 모두 비밀"이라고 말하지 않는다(구분: firebaseConfig = 프로젝트 식별 설정값, AI 서비스 키·서비스 계정 키 = 서버 측 자격증명). 흔한 오류: 설정값을 비밀로 오해해 숨기다 앱이 안 돌아가는 것. 접근 규칙의 내용은 이 연수에서 설명하지 않고 M7에서 Claude Code가 만든다. 이 단계는 앱을 만드는 것이 아니라 "접속 정보가 어떻게 생겼는지 보는" 단계다. (2분)

## [슬라이드 39] Firestore 사용 상황: 문서 지향 NoSQL 데이터베이스
- 유형: 개념
- 본문:
  - Firestore = 문서 지향 NoSQL 데이터베이스. **데이터는 컬렉션 안의 문서에 저장하고, 문서는 필드(키-값)로 이루어진다.**
  - 쓴다: ① 수업·학습지·제출물 저장 ② 교사가 올린 자료를 학생이 실시간으로 보기
  - 안 쓴다: 큰 파일(영상·큰 이미지) → Storage가 맞다. 단 Storage는 Blaze 필요.
- 도식: 컬렉션-문서-필드 계층도 하나. 컬렉션 2개 `users/{uid}`, `classes/{classId}` 아래에 문서와 필드. (예시 경로는 이 두 개만. 클래스룸 예시 소재)
- 노트: 사실표 3절. 한 줄 정의는 "문서를 컬렉션에 담아 저장하는 실시간 클라우드 데이터베이스". 용량 한도: 문서 1개 최대 1MiB(검수 확인: quotas 문서 "Maximum size for a document 1 MiB (1,048,576 bytes)"). MiB·GiB는 저장 용량 단위(1MiB는 약 1MB)라고 한 줄 덧붙인다. 짧은 글(문항·답안·HTML 문자열)은 Firestore 문서에 두면 결제 수단 없이 가능하다(사실표 5·9절). 요금 참고: Standard Edition 무료 한도 1GiB 저장, 하루 읽기 5만, 쓰기 2만(Spark). 컬렉션 그룹 쿼리·복합 색인은 심화이므로 여기서는 이름만 언급하고 넘어간다(필요하면 사실표 3절 "색인" 참고). (1분)

## [슬라이드 40] Firestore 설정 절차: 데이터베이스 만들기
- 유형: 실습 (참가자 실습, Spark)
- 본문:
  - 데이터베이스를 만들 때 **프로덕션(잠금) 모드**로 시작한다.
  - 프로덕션 모드는 처음에 모든 접근을 막고, 접근 조건은 Claude Code가 규칙 파일로 만들어 배포한다(M7).
  - 테스트 모드는 누구나 읽기·쓰기가 되는 기한이 정해진 임시 설정이라 쓰지 않는다.
- 도식: `.steps` 5단계 + 아래 비교 표(2열)
  1. 프로젝트 선택 → 왼쪽 패널 **데이터베이스 및 스토리지(Databases & Storage) > Firestore** `[확인필요: 한국어 메뉴명, 리허설에서 실제 화면과 대조]`
  2. **데이터베이스 만들기(Create database)** 클릭
  3. 에디션 선택 화면이 나오면 **Standard** 선택. 에디션 = 데이터베이스 종류, 기본형을 고른다. `[확인필요: 에디션 선택 화면 유무와 화면 순서]`
  4. **위치(location)** 선택. 서울(asia-northeast3)을 고를 수 있다. **위치는 만든 뒤 바꿀 수 없으므로 신중히 고른다.**
  5. 보안 모드 **프로덕션 모드** 선택 → **만들기(Create)**

  | 구분 | 테스트 모드 | 프로덕션 모드 |
  |---|---|---|
  | 접근 | 누구나 읽기·쓰기 허용 | 클라이언트(웹/앱) 접근 전부 거부 |
  | 기간 | 기한이 정해진 임시 설정 `[확인필요: 30일 만료]` | 만료 없음 |
- 프롬프트: (Claude Code 사용 없음. 콘솔 직접 조작)
- 예상 결과: Firestore 데이터 화면이 열린다. 데이터는 비어 있다.
- 막힐 때:
  - 위치를 고를 수 없음 → 프로젝트 기본 Google Cloud 리소스 위치가 이미 정해진 경우다(사실표 3절). 그대로 진행한다.
  - 나중에 `Missing or insufficient permissions` → 프로덕션 모드는 처음에 전부 거부한다. 정상이다. 접근 조건은 M7에서 Claude Code가 규칙 파일로 만들어 배포한다.
- 노트: 사실표 3절. **프로덕션 모드 권장은 사실표의 작성자 의견**이다. 테스트 모드는 "연수 첫 체험용으로만, 학생 정보가 들어가면 위험". 테스트 모드의 30일 만료는 현재 quickstart 문서에서 문장을 찾지 못해 "기한이 정해진 임시 설정"으로 말하고 `[확인필요]`로 둔다(검수 5절). 확인된 것: 프로덕션 모드는 "Denies all reads and writes from mobile and web clients"(quickstart), 위치는 "once you provision a database instance, you cannot change its location"(locations 문서), 서울(asia-northeast3)은 locations 목록에 있다. Cloud Firestore API는 만들 때 자동 사용 설정된다. 규칙 문법은 이 연수에서 다루지 않는다. 이 단계에서 데이터를 넣거나 앱을 연결하지 않는다. (3분)

## [슬라이드 41] 요금제 사용 상황: Spark와 Blaze
- 유형: 개념
- 본문:
  - **Spark = 무료 요금제**(무료 사용량 한도 안에서만 사용). **Blaze = 종량제 요금제**(무료 한도 안은 무료, 넘으면 사용량만큼 청구, 결제 수단 등록 필수).
  - Blaze 필요: Cloud Functions 배포, Cloud Storage(2026-02-03부터)
  - 용어: MAU = 월간 활성 사용자 수 / GiB = 저장 용량 단위 / GB-초 = 함수 실행 시간 × 메모리
- 도식: 2열 비교 표(문서 표기)

  | 기능 | Spark | Blaze |
  |---|---|---|
  | Authentication(기본) | 월 5만 MAU | 동일 |
  | Firestore Standard | 1GiB, 읽기 5만/일, 쓰기 2만/일 | 동일 무료 한도 후 종량 |
  | Hosting | 10GB 저장, 360MB/일 전송 | 동일 무료 한도 |
  | Storage | 사용 불가 | 5GB 저장 등 표기 |
  | Functions | 사용 불가 | 월 200만 호출, 40만 GB-초 |
- 노트: 사실표 8절. 공식 이름: "No-cost (Spark plan)", "Pay as you go (Blaze plan)". 기본 Authentication, Firestore, Hosting은 Spark에서 사용 가능. Blaze가 필요한 것: Cloud Functions(배포), Cloud Storage(2026-02-03부터). Storage는 Spark에서 기존 버킷 포함 읽기/쓰기 접근을 잃고 새 기본 버킷도 Blaze에서만 생성 가능하다. **충돌 없음(검수 확인)**: pricing 페이지 Spark의 Cloud Storage가 "Not applicable"로 바뀌었고, FAQ의 Blaze 요건은 2026-02-03 시행이며 미업그레이드 시 데이터는 남지만 접근할 수 없다. 무료 사용량·한도(Auth 5만 MAU, Firestore 1GiB·읽기 5만·쓰기 2만, Hosting 10GB·360MB/일, Functions Spark 불가)는 pricing 페이지로 확인됨. 무료 사용량 수치는 문서 표기이며 바뀔 수 있으므로 연수 당일 pricing 페이지(https://firebase.google.com/pricing)로 다시 확인한다. Blaze여도 무료 사용량 안에서는 비용이 0일 수 있으나 **결제 수단 등록은 필수**다. 신규 사용자에게 $300 체험 크레딧이 적용되는지는 `[확인필요]`. 그래서 이 연수는 Spark로 완성되는 항목(Auth·Firestore)만 참가자 실습으로 두었다. (1분)

## [슬라이드 42] 요금제 설정 절차: 예산 알림 (강사 시연)
- 유형: 데모 (강사 시연) · **심화 선택**
- 본문:
  - **예산 알림은 알림일 뿐, 사용을 멈추지 않는다.**
  - 요금제 변경과 결제는 **사람이 직접 확인한다.** 연수에서는 결제 수단을 등록하지 않는다.
- 도식: `.steps` 3단계(심화 선택 박스)
  1. 콘솔 **설정(Settings) > 사용량 및 결제(Usage and billing)** 에서 결제·사용량 확인 `[확인필요: 한국어 메뉴명]`
  2. Blaze 업그레이드 시 **알림 전용 예산(Alerts-only budget)**이 자동으로 제안된다 (이 연수에서는 업그레이드를 시연하지 않고 화면 캡처로 보여 준다)
  3. 금액과 알림 임계값(예: 50%, 90%, 100%)을 정하면 이메일 발송 `[확인필요: 임계값 기본값]`
  - 예산 유형: **알림 전용**(이메일만, 서비스 계속) / **지출 한도(Spend cap)**(Firebase AI Logic, App Hosting, Cloud Functions, Extensions 한정, 100% 도달 시 그 달 남은 기간 중지)
- 노트: **강사 시연이므로 참가자는 따라 하지 않는다.** 사실표 8절 핵심 문구(공식): "Budget alerts do **not** pause services." Firestore·Storage·Hosting에는 지출 한도를 걸 수 없다(문서에 나열된 제품에 미포함). 제품별 사용량 대시보드가 있다. 실험 코드로 인한 뜻밖의 비용은 Local Emulator Suite로 피할 수 있다(Functions, Firestore, Realtime Database 대상). 연수 운영 권고(사실표의 작성자 의견): 참가자 개인 계정에 결제 수단 등록이 부담되므로 Blaze 단계는 시연으로 분리했다. 설정 위치와 한국어 메뉴명은 리허설 때 실화면으로 대조한다. (1분)

  - Storage = 파일(객체) 저장 서비스. 이미지·PDF·영상 같은 **파일**을 저장한다.

  - 안 쓴다: 짧은 글·HTML 텍스트 → Firestore (문서 한도 1MiB)
- 도식: Storage(파일 저장)와 Firestore(문서 저장) 두 박스. 큰 파일은 Storage로, 짧은 글은 Firestore로 화살표. Storage에 `Blaze 필요` 표식.
- 노트: 사실표 5절. **현재 요건: Storage 사용에는 Blaze 필요, 2026-02-03부터 적용**(검수 확인: Storage FAQ). 문서 1MiB 한도는 quotas 문서로 확인됨. 그래서 이번 클래스룸 예시는 HTML을 Firestore 문서에 저장하는 방식을 우선 권장한다(결제 수단 불필요). 학생 사진은 개인정보이므로 연수에서는 올리지 않는다(44번 질문과 연결). 설계서에 적힌 "2024-10-30 이후 정책"은 사실표에서 확인되지 않았고 사실표는 2026-02-03 요건을 최신으로 본다. (1분)

## [슬라이드 44] 질문: Firestore냐, Storage냐, 올리지 않을까
- 유형: 점검 (참가자 질문)
- 본문:
  - **학습지 문항은? 수업 동영상은? 학생 사진은?**
  - 짝과 1분 이야기 → Firestore / Storage / 올리지 않음

## [슬라이드 47] Hosting 설정 절차 (강사 시연)
- 유형: 데모 (강사 시연) · **심화 선택**
- 본문:
  - 터미널에서 4단계: CLI 설치 → 로그인 → 초기화 → 배포.
  - 배포는 **공개 행위**다. Claude Code에게는 **플랜 모드**로 시킨다.
- 도식: `.steps` 5단계(심화 선택 박스)
  1. Node.js(CLI를 돌리는 실행 환경) 설치 후 `npm install -g firebase-tools` (Firebase CLI = 터미널용 명령 프로그램 설치)
  2. `firebase login` (브라우저에서 구글 계정 인증)
  3. 프로젝트 폴더에서 `firebase init hosting` (프로젝트 선택, 공개 폴더 지정 등 질문에 답함) `[확인필요: 질문 순서와 문구는 CLI 버전에 따라 다름]`
  4. 공개 폴더에 `index.html` 등을 둔다
  5. `firebase deploy --only hosting` → `PROJECT_ID.web.app` 으로 접속
  - Claude Code에 시키는 요청 문장 예시(플랜 모드에서, 시연용):
    ```
    이 폴더를 Firebase Hosting에 배포하는 단계를 계획만 세워줘. 실행은 하지 말고,
    내가 승인한 뒤에만 명령을 실행해. 배포 전에 공개 폴더에 개인정보가 든 파일이 없는지 먼저 확인해줘.
    ```
- 노트: **강사 시연이며 참가자는 Node.js·CLI를 설치하지 않는다.** 사실표 6절. 흔한 오류: 로그인 안 된 상태에서 배포, 공개 폴더 안에 `index.html` 없음(기본 안내 페이지가 뜸), 배포 주소를 승인된 도메인에 추가하지 않아 `auth/unauthorized-domain`(기본 주소는 이미 포함인지 `[확인필요]`), `.firebaserc`의 잘못된 프로젝트 선택. `firebase init hosting`, `firebase deploy --only hosting`, `web.app`·`firebaseapp.com` 주소는 Hosting quickstart로 확인됨(검수). 질문 순서만 미확인. 요청 문장 예시는 설계서의 "플랜 모드로" 지시를 따른 것이며, 앱 코드를 만드는 프롬프트가 아니라 배포 **계획**만 요청한다. 배포는 사람이 직접 확인한 뒤에 한다(48번). (1분)

## [슬라이드 49] Cloud Functions 사용 상황: 서버리스 백엔드 코드
- 유형: 개념
- 본문:

- 도식: 학생 브라우저 → Cloud Functions(서버 측, Secret으로 저장된 AI 키 사용) → AI 서비스. 브라우저에는 키가 없음을 표시.

## [슬라이드 50] Cloud Functions 설정 절차 (강사 시연)
- 유형: 데모 (강사 시연) · **심화 선택**
- 본문:
  - Blaze 업그레이드 → CLI 초기화 → **비밀값 저장** → 배포.
  - 비밀값(AI API 키)은 브라우저 코드·HTML·`.env` 커밋에 **넣지 않는다**.
- 도식: `.steps` 5단계(심화 선택 박스)
  1. 콘솔에서 **Blaze로 업그레이드**(결제 수단 등록) 후 **예산 알림** 설정 (42번) `[확인필요: 비용, 결제 수단 등록은 승인 후]`
  2. Node.js 20 또는 22 `[확인필요: 지원 버전]` + `npm install -g firebase-tools` (Node.js = CLI를 돌리는 실행 환경, CLI = 터미널용 명령 프로그램)
  3. 프로젝트 폴더에서 `firebase init functions` `[확인필요: 언어 선택 등 질문]`
  4. 비밀값을 **Secret**으로 저장: `firebase functions:secrets:set 이름`
  5. 배포: `firebase deploy --only functions`
- 노트: **강사 시연이며 참가자는 따라 하지 않는다. 시연에서 실제 결제 수단을 쓰지 않아도 되도록 화면 캡처 사용을 권장한다.** 사실표 7절. 비밀값 관리: 권장 방식은 매개변수화된 구성(Parameterized configuration)이며 유형에 Secret이 포함된다. Secret 값은 Cloud Secret Manager에 저장되고 **개별 함수에 바인딩**해야 쓸 수 있다. 위 명령과 코드의 `defineSecret`·`secrets: [...]` 옵션은 functions get-started, config-env 문서로 확인됨(검수). 일반(비밀 아닌) 설정은 `functions/.env`. 옛 방식 `functions.config()`는 deprecated(v6.0.0), 2027년 3월 중단 예정이므로 **연수 자료에서 쓰지 않는다**. 흔한 오류: Blaze가 아니라 배포 거부, Secret 값 누락으로 CLI가 배포를 막음, Node 버전 불일치, Secret을 함수에 바인딩하지 않아 런타임 값이 빔. 사용량 상한을 거는 지출 한도 예산은 Cloud Functions에 적용 가능하다(42번). (1분)

  | ☐ 프로젝트 만들기 | ☐ 요금제·예산 알림 |
  | ☐ 웹 앱 등록, firebaseConfig 확인 | ☐ Storage |
  | ☐ Google 로그인 켜기 | ☐ Hosting 배포 |
  | ☐ Firestore 만들기(프로덕션 모드) | ☐ Cloud Functions |

  하단: 연수 후 삭제 → 콘솔 **프로젝트 설정 > 일반(General) > 맨 아래 "프로젝트 삭제"** → 체크박스를 확인하고 삭제. 30일 안에는 Google Cloud 콘솔에서 복구할 수 있다.
- 노트: 프로젝트 삭제 절차는 검수에서 확인되었다(Firebase 도움말 "Delete your project", https://support.google.com/firebase/answer/9137886). 한국어 UI 메뉴명은 리허설에서 한 번 대조한다. 실제 학생 계정과 이름은 입력하지 않았는지 마지막으로 확인한다. 이 모듈 전체의 비용 원칙: 연수는 Spark(무료)로 끝낸다. (1분)
