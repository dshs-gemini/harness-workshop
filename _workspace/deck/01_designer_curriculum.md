> **설계자 공지 (오류 처리 규칙에 따라 맨 위에 적음)**
> 1. **줄인 기능은 없다.** 다만 위 3·4번 변경으로 원본의 `t2-agent-practice`, `t2-skill-design`, `t2-skill-practice`와 Firebase 보안 규칙·규칙 플레이그라운드는 덱에서 의도적으로 제외했다. 섹션 id별 위치는 4절 대조표에 있다.
> 2. **강사 시연은 없다. 모든 설정은 참가자 전원이 함께 한다.** Firebase **요금제(Blaze 변경과 예산 알림)·Storage·Hosting(Node.js·CLI 설치와 로그인)·Cloud Functions**의 설정 절차(슬라이드 42, 45, 47, 50)를 참가자 실습으로 한다(옛 구성의 '강사 시연·심화 선택'을 삭제). Cloud Functions 배포는 Blaze(종량제)가 필요하고, Storage 기본 버킷도 Blaze가 필요하다(2026-02-03 정책). 그래서 **참가자가 본인 개인 계정에 본인 결제 수단을 등록**해 Blaze로 올리고, **예산 알림부터 정한다**(예산 알림은 알림일 뿐 사용을 멈추지 않는다). 결제 수단이 없거나 등록이 안 되는 참가자는 짝 화면을 보며 따라간다. Hosting 배포는 M7(60)에서 Claude Code가 한다. 연수 후에는 테스트 프로젝트를 삭제하고 청구 내역을 확인한다(52). Blaze에서 Spark로 되돌리는 방법은 공식 문서로 확인하지 못했다 `[확인필요]`. 참가자가 직접 실습하는 Firebase 항목은 프로젝트 생성, 웹 앱 등록, Authentication(Google 로그인), Firestore 생성, 요금제 변경, Storage 시작하기, Node.js·CLI 설치와 로그인, 연수용 Cloud Functions 배포다. M7 프로젝트는 Authentication·Firestore·Hosting만 쓴다.
> 3. 원본은 3.5~4시간 분량이다. 섹션을 빼지 않고 슬라이드당 메시지를 하나로 줄여 M1~M6과 마무리를 130분에 맞추고, 남은 50분을 M7 프로젝트에 배정했다(합계 180분). 그래서 원본의 긴 설명은 발표자 노트로 옮긴다.
> 4. **파일 경로 충돌 경고:** `slide-writer` 에이전트 정의의 기본 출력은 `_workspace/02_writer_{모듈}_slides.md`이다. 이 경로에는 기존 클래스룸 PPT 원고가 있다. 이번 덱 원고는 반드시 **`_workspace/deck/02_writer_{모듈}_slides.md`** 에 쓴다. 마찬가지로 `firebase-guide-researcher`의 기본 출력도 `_workspace/deck/02_researcher_firebase_facts.md`에 쓴다(오케스트레이터 스킬 기준).
> 5. 브리프 준수: 클래스룸 앱은 **예시 소재**로만 쓴다. 덱의 어떤 실습도 클래스룸 앱 코드를 만들게 하지 않는다. M7 프로젝트에서 만드는 것은 참가자 자기 교과 단원의 **수업 슬라이드와 학생 워크북 웹앱**, 그리고 그것을 만드는 하네스가 생성한 팀 파일이다. 클래스룸 앱이 아니다.

### 사전 준비(연수 안내문, 슬라이드 2에서 점검)
- Claude Code 설치와 로그인을 미리 끝낸다. Claude Code는 Pro·Max·Team·Enterprise 또는 Console(API) 계정이 필요하고 무료 claude.ai 계정으로는 쓸 수 없다(원본 intro).
- **Git은 필수다.** Claude Code 설치에는 필요 없지만, 이 연수의 하네스 플러그인 설치(M4 22의 `/plugin marketplace add revfactory/harness`)는 GitHub 저장소를 git으로 내려받는다. 공식 문서(2026-10-25 확인): Windows에서 git이 없으면 `Failed to clone marketplace repository: Command 'git' not found or is in an unsafe location`로 실패하고, 해결은 Git for Windows 설치다. 모든 OS에서 M1 4번에서 `git --version`으로 미리 확인한다. Windows에서 없으면 Git for Windows를 먼저 설치한다. macOS·Linux의 git 기본 설치 여부는 `[확인필요]`. Git for Windows가 있으면 Claude Code가 Git Bash로 Bash 도구를 쓴다.
- Firebase 실습용 **개인 구글 계정**을 준비한다. 학교 관리(Workspace) 계정은 프로젝트 생성이 막혀 있을 수 있다 `[확인필요]`. 실제 학생 정보는 쓰지 않는다.
- Node.js와 Firebase CLI는 M6 47에서 함께 설치하고 `firebase login`까지 한다(M7 59–60에서 이어서 쓴다). 미리 설치해 두면 시간이 남는다. 없으면 47의 막힐 때를 따른다 `[확인필요: 학교 PC 설치 권한]`.
- **결제 수단(필수): 본인 개인 계정에 본인 결제 수단**을 준비한다. M6 42에서 Firebase 테스트 프로젝트를 Blaze로 올리고 Storage·Cloud Functions를 함께 해 보기 때문이다. 학교 카드·타인 카드는 쓰지 않는다. 무료 사용량 안에서는 비용이 0일 수 있으나 결제 수단 등록은 필수이며 예산 알림을 먼저 정한다. 쓰고 싶지 않은 참가자는 짝 화면을 보며 따라간다.
- 쉬는 시간(33)에 Firebase 콘솔에 개인 구글 계정으로 로그인해 둔다. `firebase login`(터미널)은 M7 59에서 한다.
- GitHub 로그인(`gh auth login`)은 이 연수에서 실습하지 않는다. 로그인 원리의 예시로만 M7 58에서 설명한다.
- M7에서 쓸 자기 교과 단원 1개와 그 성취기준 문장(교육과정 문서에서 복사할 수 있게)을 미리 정해 오면 좋다.
- 별도 사전 설치 안내문은 이번 산출 범위가 아니다. 위 내용은 슬라이드 2 노트에만 적는다.

## 5. Firebase 모듈(M6) 기능 목록과 슬라이드 배정

### researcher(`firebase-guide-researcher`)에게 요청하는 확인 항목
기능마다 에이전트 정의의 통일 형식(한 줄 정의 · 동작 원리 · 쓰는 상황 2개 · 안 쓰는 상황 1개 · 콘솔 설정 단계 번호 · 흔한 오류 · 요금제 참고 · 출처 URL)을 따른다. 특히 아래는 슬라이드에 그대로 들어가므로 공식 문서로 확인한다.
1. 콘솔 왼쪽 메뉴 이름(한국어/영어 병기): 이전 검수에서 확인한 것은 "보안(Security) > Authentication", "데이터베이스 및 스토리지(Databases & Storage) > Firestore"다. Storage, Hosting, Functions, 사용량 및 결제의 메뉴 위치는 확인필요.
2. 프로젝트 생성 단계(Google 애널리틱스 선택 여부 포함), 웹 앱 등록 후 나오는 `firebaseConfig`가 공개되어도 되는 이유와 비밀 정보(AI API 키, 서비스 계정 키)의 구분.
3. Authentication: Google 제공업체 켜기 단계, 승인된 도메인. 2025-04-28 이후 만든 프로젝트에는 `localhost`가 기본으로 없다는 사실(이전 검수 확인)을 출처와 함께 적는다.
4. Firestore: 생성 단계, 위치(나중에 바꿀 수 없음 여부), 프로덕션(잠금) 모드와 테스트 모드의 차이, 문서 크기 한도 1MiB.
5. (덱에서 제외) 보안 규칙·규칙 플레이그라운드는 M6에서 다루지 않으므로 슬라이드용 확인이 필요 없다. M7에서 Claude Code가 만드는 `firestore.rules`의 내용은 Claude Code 출력으로 확인한다.
6. Storage: 기본 버킷 생성에 Blaze가 필요한지(2026-02-03부터 적용되는 정책, 1차 검수에서 확인됨), 기존 무료 버킷의 처리, 보안 규칙이 Firestore와 따로 있다는 점.
7. Hosting: CLI 기준 절차(`firebase login` → `firebase init hosting` → `firebase deploy`), Spark에서 가능한지, Firebase App Hosting과의 차이(헷갈리지 않게 한 줄).
8. Cloud Functions: 배포에 Blaze 필요(이전 검수 확인), 비밀값 보관 방법(`firebase functions:secrets:set` 등).
9. 요금제: Spark/Blaze 차이, 예산 알림은 **알림일 뿐 사용을 자동으로 멈추지 않는다**는 점, 예산 알림 설정 위치.
10. 테스트 프로젝트를 연수 후 삭제하는 방법(설정 > 프로젝트 삭제 위치).
11. 공식 Firebase 플러그인(Firebase MCP 서버)이 Firebase CLI와 같은 자격증명을 쓴다는 점(M7 58·59). 근거: https://firebase.google.com/docs/cli/mcp-server

| 보안 규칙 | Firestore·Storage 요청의 허용 조건을 선언하는 접근 제어 규칙 | 요청마다 규칙을 평가해 허용·거부한다. 이 연수에서는 설명하지 않고, M7에서 Claude Code가 `firestore.rules`(로그인한 본인 uid 문서만 읽기·쓰기)를 만들어 배포한다 |
| 승인된 도메인 | Authentication이 로그인 요청을 받아들이는 접속 주소 목록 | 목록에 없는 주소에서 로그인하면 `auth/unauthorized-domain` 오류가 난다 |
| Hosting | 웹 콘텐츠를 공개 주소로 배포하는 서비스 | `firebase deploy`로 올린 파일을 공개 URL로 제공한다 |
| Cloud Functions | 서버 측 코드를 이벤트·HTTP 요청으로 실행하는 서비스 | 서버에서 실행되므로 AI API 키 같은 비밀값을 보관·사용할 수 있다 |
| Spark / Blaze | 무료 사용 한도 요금제 / 사용량 기준 종량제 요금제 | Functions 배포 등 일부 기능은 Blaze가 필요하다 |
| firebaseConfig | 웹 앱을 식별하는 설정 값 | 공개돼도 되는 값이다. 비밀로 지킬 것은 AI API 키·서비스 계정 키이며, 데이터 접근은 보안 규칙이 막는다 |
| 터미널 로그인 | 터미널에서 `firebase login`, `gh auth login`처럼 한 번 해 두는 로그인. 로그인 정보는 내 컴퓨터에 저장된다 | 이후 Claude Code가 같은 로그인으로 그 도구의 명령을 대신 실행한다. 자동인 것은 실행이고, 승인은 사람이 한다 |

- 사실이 확실하지 않으면 `[확인필요]`. 이미 짚어 둔 확인 대상: 플랜 모드 승인 화면 문구(원본의 `[승인하시겠습니까? y/n]`는 예시), 권한 모드 이름("Auto 모드" 포함, 공식 문서 대조), `/plugin install`의 마켓플레이스 이름, Firebase 메뉴 이름 전부, `firebase login --no-localhost` 동작, 학교 PC 설치 권한.
- 앱 제작으로 흐르지 않는다. 클래스룸은 "예를 들면"으로만 등장한다. **예외:** M7(53–64)은 참가자 자기 교과 단원의 슬라이드와 워크북 웹앱을 하네스와 Claude Code가 실제로 만든다. 이때도 클래스룸 앱 코드는 만들지 않는다. 복잡한 설정은 교사의 인지 부하이므로, 설정과 코드·규칙 파일·배포는 Claude Code가 하고 사람은 Firebase 콘솔 설정과 승인만 한다.
- **콘솔 메뉴·버튼 이름은 `한글(English)` 형식으로 쓴다. 한글을 앞에 두고 영문은 괄호에 병기하며, 슬라이드마다 순서를 바꾸지 않는다**(예: `데이터베이스 및 스토리지(Databases & Storage) > Firestore`, `데이터베이스 만들기(Create database)`, `설정(Settings) 탭 > 승인된 도메인(Authorized domains)`). 서비스 이름(Authentication, Firestore, Storage, Hosting, Cloud Functions)은 고유 명칭이라 그대로 쓴다. 한국어 메뉴명이 공식 한국어 문서로 확인되지 않은 것은 `[확인필요]`를 붙이고 리허설에서 실제 화면과 대조한다. "영문 UI 기준" 같은 문구는 쓰지 않는다.
- 한 슬라이드에 내용을 구겨 넣지 않는다. 설명이 더 필요하면 슬라이드를 추가하고 번호·분 합계(180분)를 함께 맞춘다.

- **Firebase 사실 처리:**
  - 접근 규칙 `firestore.rules`는 Claude Code가 만들고 배포한다. 배포 전 플랜 모드 계획에서 "무엇을 배포하는지"를 한국어로 설명하게 한다. 교사용 정답은 웹앱 파일에 넣지 않는다(페이지 소스로 보인다).

  - Storage·Cloud Functions는 쓰지 않는다(Blaze 필요, M6 41). 이 모듈은 Spark로 완결된다.
  - Firebase SDK 버전 번호, 파일 구조, Firestore 문서 경로는 슬라이드에서 지정하지 않는다. Claude Code가 정한다(지어내지 않음).
  - 교사는 Firebase 콘솔 Firestore 데이터 화면에서 응답을 확인한다. 교사용 열람 화면, 정답 표시·채점은 만들지 않는다.
  - 로그인 정보 처리: 이름·이메일을 Firestore 문서에 저장하지 않고 uid만 쓰도록 요청한다. 로그인한 계정으로 할 수 있는 일은 Claude Code도 할 수 있으므로 테스트 계정·연습용 프로젝트만 쓴다(58 노트).
