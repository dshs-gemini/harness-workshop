## [슬라이드 10] 모호한 요청 vs 구체적인 요청
- 유형: 개념
- 본문:
  - Claude Code에게도 작업 지시는 구체적으로 한다.
  - 문장에 **대상 · 범위 · 형식 · 기준** 네 가지를 담는다.
  - 다시 요청할 일이 줄어든다.
- 도식: 카드 2장 비교(원본 `.grid2`의 `card bad` / `card good`).
  - 나쁜 예(모호한 요청): "퀴즈 좀 만들어줘"
  - 좋은 예(구체적인 요청): "고1 정보 수업 '변수와 자료형' 단원 복습용으로, 객관식 5문항짜리 퀴즈를 만들어줘. 각 문항에 정답과 한 줄 해설을 붙이고, 난이도는 쉬움 3개·보통 2개로 섞어줘"
  - 좋은 예 문장 아래에 네 요소를 색으로 표시: 대상(고1 정보 수업), 범위('변수와 자료형' 단원 복습용), 형식(객관식 5문항, 정답과 한 줄 해설), 기준(쉬움 3개·보통 2개).
- 노트: (발표자 대본) "같은 퀴즈 요청인데 오른쪽 카드는 누가, 무엇을, 어떤 모양으로, 어떤 기준으로 만들지 다 들어 있습니다. 네 가지를 빼먹으면 Claude Code가 추측해서 만들고, 그러면 다시 요청해야 합니다." 짝에게 왼쪽 카드를 고쳐 말해 보게 하면 좋다(30초, 선택). 담당 과목에 맞게 바꿔 말해도 된다고 안내한다. (2분)

## [슬라이드 11] 컨텍스트와 플랜 모드
- 유형: 개념
- 본문:
  - 컨텍스트 = 모델 입력으로 유지되는 대화·파일 내용(컨텍스트 윈도우). 대화가 길어지면 관련 없는 내용이 쌓여 답이 흐려질 수 있다.
  - 플랜 모드 = 파일 수정 없이 읽기 전용으로 계획만 세우고, 승인 후 실행한다. `Shift`+`Tab`으로 켠다.
  - 하단 상태 표시줄에서 지금 모드를 확인한다.
- 도식: 왼쪽에 표, 오른쪽에 플랜 모드 흐름.
  - 표(원본 그대로):

    | 명령 | 동작 | 언제 쓰나 |
    |---|---|---|
    | `/clear` | 대화 기록을 초기화합니다 (컨텍스트 비우기) | 완전히 다른 작업을 새로 시작할 때 |
    | `/compact` | 지금까지의 대화를 요약해서 압축합니다 (요약본만 남기기) | 같은 작업을 계속하되 맥락은 유지하고 싶을 때 |

  - `.flow`: 요청 → 계획만 제시(파일 안 고침) → 사람이 승인 → 실제 작업. 아래에 화면 하단 상태 표시줄 위치 표시.
- 노트: (발표자 대본) "Claude Code는 이전 요청과 읽은 파일을 컨텍스트로 기억합니다. 컨텍스트가 길어지면 `/clear`로 대화 기록을 초기화하고, 같은 작업을 이어 가되 요약본만 남기고 싶으면 `/compact`입니다. 파일을 여러 개 만들거나 고치는, 되돌리기 번거로운 일은 먼저 플랜 모드로 계획을 보고 승인합니다." 덧붙임: `Shift`+`Tab`은 플랜 모드뿐 아니라 이후 M3에서 다룰 권한 모드(도구 실행 승인 정책)를 순환 전환하는 단축키이기도 하다. 하단 상태 표시줄에서 현재 모드를 확인한다. 모드 표시는 하단에 `⏸ plan mode on` 같은 문구로 보인다(M3 21 표 참고). (2분)

## [슬라이드 12] 실습: 플랜 모드로 수업 개요 만들기
- 유형: 실습
- 본문:
  1. `/clear`로 대화 기록을 초기화한다.
  2. `Shift`+`Tab`을 하단에 `⏸ plan mode on`이 보일 때까지 누른다(Auto로 시작했다면 세 번). 또는 프롬프트 앞에 `/plan`을 붙인다.
  3. 아래 프롬프트를 붙여 넣고, 계획을 읽은 뒤 승인 화면에서 **"Yes, manually approve edits"** 를 고른다.
- 프롬프트:
  ```
  고1 정보과학 '조건문과 반복문' 1차시(50분) 수업 개요를 markdown 파일로 만들어줘.
  도입(5분)-전개(35분)-정리(10분) 구조로 나누고, 전개 단계에는 학생이 직접 코드를
  고쳐보는 미니 실습을 하나 포함해줘. 파일 이름은 lesson-01.md로 해줘
  ```
- 예상 결과: 터미널 하단에 `⏸ plan mode on`이 보이고, 파일을 만들기 전 계획이 먼저 나온다.
  ```
  계획: lesson-01.md 파일을 새로 만들겠습니다. 구성은 다음과 같습니다…
  1. Yes, and use auto mode
  2. Yes, manually approve edits   <- 연수에서는 이것을 고른다
  3. No, keep planning
  ```
  계획을 읽고 "Yes, manually approve edits"를 고르면 폴더에 `lesson-01.md`가 생긴다. "manually approve edits"를 고르면 세션이 Manual 모드가 되므로 파일을 만들 때 허용을 한 번 더 묻는다. 그때 허용한다. 1번을 고르면 세션이 Auto 모드로 바뀌므로 연수에서는 고르지 않는다. 3번은 계획을 더 고치게 하고 싶을 때 쓴다.
- 막힐 때:
  - `Shift`+`Tab`을 눌러도 plan 표시가 안 나옴 → 순환 순서는 Manual → Accept edits → Plan이다(Auto로 시작했다면 첫 번째 누름에 Manual로 바뀐다). 하단 표시줄에서 `⏸ plan mode on`이 보일 때까지 계속 누르거나, 프롬프트 앞에 `/plan`을 붙인다.
  - 승인 화면의 선택지가 위와 조금 다름 → 화면에서 "manually approve edits"에 해당하는 것을 고른다. 모르겠으면 손을 든다.
- 노트: (발표자 대본) "먼저 대화 기록을 초기화합니다. 이전 실습 세션이 있다면 `/clear`. 그다음 `Shift`+`Tab`으로 플랜 모드. 이 프롬프트를 보면 대상(고1 정보과학), 범위(1차시 50분), 형식(markdown, 도입-전개-정리, 파일 이름), 기준(미니 실습 하나)이 다 있죠. 계획이 나오면 읽어 보고 두 번째 'manually approve edits'를 고르세요. 첫 번째를 고르면 Auto 모드로 바뀌어 이후 확인이 줄어듭니다. 파일이 만들어지기 전에 사람이 확인한다는 점이 핵심입니다." 용어: markdown = 제목·목록을 기호(#, -)로 적는 간단한 글 형식. 담당 과목에 맞게 과목·단원을 바꿔도 된다고 안내한다. 승인 후 `lesson-01.md`가 생성될 때까지 기다린다. (4분)

## [슬라이드 13] 실습: 파일 확인하고 이어서 고치기
- 유형: 실습
- 본문:
  1. 평소 쓰던 편집기(메모장, VS Code 등)로 `lesson-01.md`를 열어 확인한다.
  2. 마음에 안 드는 부분은 새로 만들지 말고 이어서 수정을 요청한다.
  3. 무엇을 바꿀지만 말하면 된다(이전 내용이 컨텍스트에 남아 있다).
- 프롬프트:
  ```
  전개 단계 미니 실습을 더 쉽게 바꿔줘. for문 대신 if문만 쓰는 문제로 바꿔줘
  ```
- 예상 결과: Claude Code가 방금 만든 `lesson-01.md`의 전개 단계 미니 실습을 if문만 쓰는 쉬운 문제로 고친다. 다시 파일을 열면 바뀐 내용이 보인다. (과목을 바꿔 실습한 경우 그에 맞는 쉬운 수정 요청으로 바꾼다.)
- 막힐 때:
  - `lesson-01.md`를 찾을 수 없음 → 터미널에서 실습 폴더(`claude-training`)를 연 상태인지 확인하고, 폴더 안에서 파일 목록을 열어 본다.
  - 파일 수정 허용을 물음 → 허용한다. 계획 화면이 다시 나오면 플랜 모드가 켜져 있는 것이니 `Shift`+`Tab`으로 Manual로 바꾼다.
- 노트: (발표자 대본) "터미널이 아니라 평소 쓰는 편집기로 파일을 열어 보세요. 사람이 눈으로 확인하는 단계입니다. 그리고 고치고 싶은 부분이 있으면 처음부터 다시 만들지 말고 '더 쉽게 바꿔줘'처럼 이어서 말하세요. Claude Code는 방금 만든 파일을 기억하고 있습니다." 먼저 끝난 참가자는 다른 요소(시간 배분, 정리 단계 질문 추가 등)를 이어서 고쳐 보게 한다. (3분)

## [슬라이드 14] 방금 무슨 일이 있었나
- 유형: 정리
- 본문:
  - 구체적인 프롬프트 → 플랜 모드 → 컨텍스트 유지, 이 세 가지가 방금 실습에 모두 들어 있었다.
  - 앞으로 모든 실습이 이 세 가지 위에서 이루어진다.
- 도식: `.flow` 3단 도식.
  - ① 구체적인 프롬프트(대상·시간·구조·형식 지정) → ② 플랜 모드(파일을 만들기 전 계획 확인) → ③ 컨텍스트 유지(다시 설명하지 않고 "더 쉽게 바꿔줘"만으로 이어서 수정)
  - 하단에 `lesson-01.md` 파일 아이콘 + 라벨 "나의 첫 산출물".
- 노트: (발표자 대본) "짧은 실습이었지만 세 가지가 다 들어 있었습니다. 구체적으로 말했고, 계획을 먼저 확인했고, 설명을 반복하지 않고 이어서 고쳤죠. 다음 모듈부터는 이 말하기 방식 위에 규칙(CLAUDE.md)과 스킬을 얹습니다." 이 슬라이드는 실습 시간으로 센다. (1분)
