## [슬라이드 15] CLAUDE.md = 세션 시작 시 자동 로드되는 프로젝트 지침
- 유형: 개념
- 본문:
  - CLAUDE.md는 폴더 맨 위에 두는 텍스트 파일. 세션을 시작할 때마다 컨텍스트에 자동 로드되는 프로젝트 지침 파일
  - 적는 것 4가지: 산출물 형식 · 대상 독자와 어조 · 반복되는 제약 · 절대 하지 말 것
  - 한계: "부탁"이지 "강제"가 아니다
- 도식: `CLAUDE.md` 파일 그림 한 장. 4개 카드(형식 / 독자·어조 / 반복 제약 / 금지)가 파일 안의 항목으로 들어 있고, 오른쪽에 "대화를 새로 시작해도 다시 읽힘" 화살표. 맨 아래 경고 띠: "산문으로 적은 부탁 → 가끔 놓칠 수 있음".
- 노트: "1.3에서 컨텍스트는 대화를 새로 시작하면 초기화된다고 했습니다. 매번 '한국어로, HTML 한 파일로'를 다시 말하기 싫다면 CLAUDE.md에 적어 두면 세션 시작 때마다 자동으로 로드됩니다." 예시 4개는 원본 그대로: 형식("학생 배포용 자료는 항상 자급형 HTML 한 파일"), 독자·어조("고1 대상, 존댓말, 어려운 용어는 처음 나올 때 한 줄 설명"), 반복 제약("수식은 KaTeX, `\` 이스케이프 주의"), 금지("학생 이름·학번이 든 예시 데이터 만들지 않기"). 그냥 텍스트 파일이라 메모장으로 열어 고쳐도 되고 Claude에게 고쳐 달라고 해도 된다. 한계 설명은 짧게만: "CLAUDE.md는 컨텍스트에 들어가는 지침이라 모델이 가끔 따르지 못할 수 있습니다. 그래서 결과는 사람이 직접 확인합니다." (2분)

## [슬라이드 16] 실습: /init 으로 CLAUDE.md 만들고 규칙 5개 추가
- 유형: 실습
- 본문:
  - 1단계: `/init` 입력. 폴더를 훑어 기본 뼈대 CLAUDE.md를 만든다
  - 2단계: 아래 프롬프트를 붙여 넣어 우리 규칙 5개를 추가
  - 직접 타자 치지 않는다. 붙여 넣기만
- 프롬프트:
  1단계
  ```
  /init
  ```
  2단계
  ```
  CLAUDE.md에 다음 규칙을 추가해줘:
    1. 이 폴더는 고등학교 정보과 수업 자료 제작용이다
    2. 학생 배포용 산출물은 항상 외부 파일 참조가 없는 자급형 HTML 한 파일로 만든다
    3. 본문은 한국어, 코드와 전문 용어는 원어를 유지한다
    4. 학생 이름·학번 등 개인정보가 들어간 예시 데이터는 절대 만들지 않는다
    5. 코드 예제는 별도 요청이 없으면 파이선으로 작성한다
  ```
- 예상 결과: 폴더에 `CLAUDE.md`가 생기고, 열어 보면 뼈대 아래에 규칙 5개가 들어 있다. 파일 수정 승인을 물으면 허용한다.
- 막힐 때: (1) `/init`이 반응이 없으면 `claude`를 실습 폴더(`claude-training`)에서 실행했는지 확인. 폴더가 비어 있어도 뼈대는 만들어진다. (2) 다른 과목이면 1번 규칙의 "정보과"를 내 과목으로 바꿔서 붙여 넣는다.
- 노트: 순서대로 진행. 먼저 `/init`(기본 뼈대 자동 생성), 다음에 규칙 추가. 학교급·과목은 바꿔도 된다고 안내. 완성되면 편집기로 CLAUDE.md를 열어 보게 한다. 막힌 참가자는 짝 화면을 함께 본다. (4분)

## [슬라이드 17] 실습: 규칙이 지켜지는지 확인하기
- 유형: 실습
- 본문:
  - 형식을 말하지 않고 요청한다
  - 자급형 HTML · 한국어 · 파이선 예제로 나오면 성공
  - 규칙은 폴더마다, 전역 규칙은 `~/.claude/CLAUDE.md`
- 프롬프트:
  ```
  조건문 개념을 설명하는 학생용 학습 자료를 하나 만들어줘
  ```
- 예상 결과: 형식을 다시 설명하지 않았는데도, CLAUDE.md 규칙에 따라 자급형 HTML 파일로, 한국어 본문에 파이선 코드 예제를 넣어 생성한다. (생성 내용은 실행마다 다르다.)
- 막힐 때: (1) 규칙이 반영되지 않은 것 같으면 `/exit` 후 `claude`를 다시 실행(세션 시작 때 CLAUDE.md를 읽는다)하고 같은 요청을 한다 `[확인필요: 같은 세션에서 수정한 CLAUDE.md가 즉시 반영되는지]`. (2) 파일이 HTML이 아니면 "CLAUDE.md의 규칙 2번을 지켜서 다시 만들어줘"라고 말한다.
- 노트: 목적은 자료 품질이 아니라 "규칙이 말하지 않아도 적용되는지" 확인하는 것. 이 슬라이드가 CLAUDE.md의 효과를 눈으로 보는 순간이다. 여러 폴더를 오가는 교사 팁: 과목별·업무별 폴더마다 다른 CLAUDE.md를 둘 수 있고, 모든 프로젝트에 공통인 규칙(예: "항상 한국어로 답한다")은 홈 폴더의 `~/.claude/CLAUDE.md`(전역)에 적으면 어느 폴더에서 켜도 적용된다. 개인정보 금지 규칙(4번)은 이후 모든 실습에서 계속 작동한다는 점을 강조. (2분)

## [슬라이드 18] 슬래시 커맨드와 스킬 = 저장된 절차서
- 유형: 개념
- 본문:
  - `/init` `/clear` 같은 슬래시 커맨드는 미리 만들어진 명령
  - 스킬 = 내가 자주 시키는 요청을 저장해 둔 업무 매뉴얼(절차서)
  - 명령 이름 = `name` 값(없으면 폴더 이름). 예: `.claude/skills/quiz/SKILL.md` → `/quiz`
- 도식: 왼쪽에 표 8행(아래), 오른쪽에 폴더 도식 `.claude/skills/quiz/SKILL.md` → `/quiz` 화살표. SKILL.md 상단에 "description(한 줄, 늘 기억)"과 "본문(필요할 때만 읽음)" 두 칸.
  | 명령 | 기능 |
  |---|---|
  | `/help` | 사용 가능한 명령 목록 |
  | `/clear` | 대화 기록 초기화 |
  | `/compact` | 대화를 요약해 압축 |
  | `/init` | CLAUDE.md 뼈대 생성 |
  | `/permissions` | 권한(허용 범위) 확인·수정 (슬라이드 21) |
  | `/agents` | 서브에이전트 관리 안내(예전 버전은 목록·생성 화면) |
  | `/skills` | 설치된 스킬 목록 |
  | `/exit` | Claude Code 종료 |
- 노트: 표는 읽지 않고 훑는다. 앞쪽 몇 개는 이미 써 보았다. `/permissions`·`/agents`는 "나중에 쓴다"만 말하고 넘어간다(`/agents`는 요즘 버전에서 목록 대신 "서브에이전트는 Claude에게 만들어 달라고 하라"는 안내를 보여 준다). 이름 규칙: `name`을 쓰면 그 이름이 `/` 메뉴의 명령 이름이 된다. 폴더 이름으로도 호출할 수 있지만 명령 이름은 `name` 값이 우선이고, `name`이 없으면 폴더 이름이 명령 이름이다. 핵심 한 줄: "내가 반복해서 시키는 요청 자체를 나만의 슬래시 커맨드로 저장한 것이 스킬." 스킬은 평소엔 description 한 줄만 기억하고(가벼움), 필요한 순간에만 본문 전체를 읽는다. 이것이 점진적 공개(progressive disclosure)이며 대화창이 불필요하게 무거워지지 않게 하는 장치다. 다음 슬라이드에서 직접 만든다고 예고. (1분)

## [슬라이드 19] 실습: /quiz 스킬 만들기
- 유형: 실습
- 본문:
  - 파일 경로와 형식을 몰라도 된다. Claude Code에게 부탁한다
  - 만들어진 SKILL.md를 폴더에서 직접 열어 확인
  - `disable-model-invocation: true` = 내가 `/quiz`라고 부를 때만 실행
- 프롬프트:
  ```
  .claude/skills/quiz/ 에 SKILL.md를 만들어줘.
    이름은 quiz, 설명은 "주제를 입력하면 객관식 퀴즈를 생성한다. 사용자가
    /quiz라고 명시적으로 호출했을 때만 실행한다"로 하고,
    $ARGUMENTS로 받은 주제에 대해 객관식 5문항(정답+한 줄 해설 포함)을
    만들도록 본문을 작성해줘. 난이도는 쉬움 2 · 보통 2 · 어려움 1로 섞어줘
  ```
- 예상 결과: 아래와 비슷한 파일이 생성된다(문구는 실행마다 조금 다를 수 있다).
  ```
  [file-box] .claude/skills/quiz/SKILL.md
  ---
  name: quiz
  description: 주제를 입력하면 객관식 퀴즈를 생성한다. 사용자가 /quiz라고
    명시적으로 호출했을 때만 실행한다.
  disable-model-invocation: true
  argument-hint: [주제]
  ---

  ## 지시사항

  $ARGUMENTS 주제에 대한 객관식 퀴즈 5문항을 만든다.

  - 난이도 구성: 쉬움 2문항, 보통 2문항, 어려움 1문항
  - 각 문항은 4지선다, 정답 표시, 한 줄 해설 포함
  - 학생이 헷갈릴 만한 오답 보기를 최소 1개 이상 포함
  - 출력은 markdown 표 형식으로 정리
  ```
  보조 설명: `disable-model-invocation: true`가 있으면 Claude가 눈치껏 알아서 퀴즈를 만들지 않고, 사람이 `/quiz`라고 직접 호출했을 때만 실행된다. 배포·삭제처럼 자동 실행되면 곤란한 명령에 특히 유용.
- 막힐 때: (1) 폴더가 `.claude/skills/quiz/`가 아니거나 파일 이름이 `SKILL.md`가 아니면 `/quiz`가 인식되지 않는다. 폴더를 열어 이름을 확인하고, 틀리면 "SKILL.md 위치를 .claude/skills/quiz/로 옮겨줘"라고 말한다. (2) 파일이 만들어졌는데 `/quiz`가 목록에 안 보이면 `/skills`로 확인하고, 안 보이면 `/reload-skills`를 입력한다(세션을 시작할 때 `.claude/skills/` 폴더가 없었다면 새 스킬이 자동으로 잡히지 않는다).
- 노트: 프롬프트는 원본 그대로. 프론트매터 키(`name`, `description`, `disable-model-invocation`, `argument-hint`)를 file-box에서 하나씩 짚어 준다: name = 명령 이름, description = Claude가 평소에 기억하는 한 줄, `argument-hint` = 입력창에 보이는 안내, `$ARGUMENTS` = 내가 입력한 주제가 들어갈 자리. 참가자가 손으로 파일을 쓰게 하지 않는다. 용어: 프론트매터(frontmatter) = 파일 맨 위 `---` 사이의 설정 칸. (4분)

## [슬라이드 20] 실습: /quiz 로 주제만 바꿔 재사용
- 유형: 실습
- 본문:
  - 주제만 말하면 5문항 퀴즈 표가 나온다
  - 주제를 바꿔 계속 재사용
  - 매번 형식을 설명하지 않아도 된다 = 스킬의 핵심
- 프롬프트:
  ```
  /quiz 재귀함수
  ```
  이어서 주제를 바꿔 한 번 더 (내 과목 주제로 바꿔도 됨)
  ```
  /quiz 반복문
  ```
- 예상 결과: 재귀함수를 주제로 한 5문항짜리 객관식 퀴즈 표가 생성된다(쉬움 2·보통 2·어려움 1, 정답과 한 줄 해설 포함). 문항 내용은 실행마다 다르다.

## [슬라이드 21] 권한 모드: 도구 실행 승인 정책
- 유형: 개념
- 본문:
  - 권한 모드 4가지: 일반(Manual) · 편집 자동 승인(Accept edits) · 계획(Plan) · Auto
  - 최신 버전은 Auto 모드로 시작한다. 처음 배울 때는 `Shift+Tab` 한 번으로 Manual로 바꾼다. 하단 상태 표시줄에서 확인
  - 모드 = 세션 전체의 기본 승인 수준. `permissions` 규칙(`allow`·`ask`·`deny`, `/permissions`) = 도구·명령 단위 예외. 평가 순서는 deny → ask → allow, deny는 모든 모드에서 적용되고 allow는 해당 호출의 승인 질문을 생략한다
  - 경고: 개인정보 폴더·실제 배포에는 완전 자동 승인 금지
- 도식: 4행 표 + 아래 빨간 경고 띠.
  | 모드 | 동작 | 하단 표시 |
  |---|---|---|
  | 일반(Manual) | 파일 수정·명령 실행 전마다 승인을 구한다. 처음 배울 때 가장 안전 | `⏸ manual mode on` |
  | 편집 자동 승인(Accept edits) | 파일 수정은 묻지 않고 진행, 명령 실행 등은 승인을 구한다 | `⏵⏵ accept edits on` |
  | 계획(Plan) | 어떤 변경도 실행하지 않고 계획만 제시 (M2에서 사용) | `⏸ plan mode on` |
  | Auto | 분류 모델이 대신 검토해 위험도 낮은 작업은 자동 진행 | `⏵⏵ auto mode on` |
  경고 띠: "학생 성적·개인정보가 든 폴더, 실제 서비스 배포 → 완전 자동 승인 금지. 사람이 눈으로 확인하는 단계를 남긴다"
- 노트: 권한 모드는 Claude Code가 도구(파일 수정, 명령 실행)를 실행할 때 사용자 승인을 어디까지 요구할지 정하는 정책이다. 원본의 3모드 표를 공식 권한 모드 문서에 맞춰 4모드로 바꿨다(원본 대비 변경). Shift+Tab 순서: Auto에서 한 번 누르면 Manual, 이어서 Accept edits, Plan 순이다. 시작 모드가 Auto인 것은 Claude Code v2.1.283 이상 기준이므로 화면 하단 표시가 다르면 화면 기준으로 안내한다. 개인정보가 든 폴더에서는 시작하자마자 `Shift+Tab`으로 Manual로 바꾸게 한다(완전 자동 승인 금지 원칙). 모드와 permissions 규칙의 관계: 모드는 규칙에 걸리지 않은 호출에 적용되는 기본 정책이고, 규칙은 그 위의 예외다. 규칙은 settings.json의 `permissions.allow/ask/deny`에 `Bash(npm run *)`, `Read(./.env)` 형식으로 쓰고 `/permissions`로 확인·추가·삭제한다. 평가는 deny → ask → allow 순이고 먼저 일치한 규칙이 결정한다. 넓은 deny는 구체적인 allow보다 우선하며 allow로 deny의 예외를 만들 수 없다. deny는 bypassPermissions를 포함한 모든 모드에서 적용되고, default(Manual) 모드에서 allow는 해당 도구의 승인 질문을 생략한다. 예: Manual 모드 + `Bash(npm test)` allow + `Read(./.env)` deny. 적용 범위는 managed > 명령행 > 로컬(.claude/settings.local.json) > 프로젝트(.claude/settings.json) > 사용자(~/.claude/settings.json) 순이고 규칙 배열은 합쳐지되 deny가 항상 우선한다. 주의: Bash 규칙은 명령 문자열 매칭이라 보안 경계가 아니므로(예: 전체 경로나 `sh -c`로 우회 가능) 강한 차단이 필요하면 샌드박스를 함께 쓴다. 공식 문서(code.claude.com/docs/en/permissions) 기준. 교원 연수에서 특히 강조하는 원칙이므로 경고 띠는 소리 내어 읽는다. M6에서 Firebase 규칙 게시·배포 직전의 사람 확인으로 다시 만난다. (2분)
