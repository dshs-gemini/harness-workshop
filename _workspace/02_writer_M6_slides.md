# 02. 슬라이드 원고: 모듈 6. 개인별 맞춤 피드백 (슬라이드 40–46)

## 가정
- 번호 범위(40–46, 7장)와 시간(25분 = 설명 7 / 실습 18)은 커리큘럼 고정값을 그대로 썼다. 장수는 바꾸지 않았다.
- 정답 저장 방식은 확정됐다(엔지니어 D6): 정답은 학습지 문서 `questions[i].answer`(0부터 세는 보기 번호, 서술형은 `null`)에 함께 저장된다. 슬라이드 42 프롬프트는 이 방식을 그대로 적었다.
- 피드백은 `classes/{classId}/worksheets/{id}/submissions/{uid}.feedback` 필드에 저장한다(명세 데이터 모델 그대로). 같은 문서에 `answers`와 `feedback`이 함께 있다. 최종 규칙(모듈 7, 엔지니어 D4)은 **교사는 `feedback`만 바꾸고, 학생은 `answers`·`submittedAt`만 바꾼다.** 학생 제출은 병합 저장(D5)이라 재제출해도 `feedback`이 남는다. 실습 중 임시 규칙에서는 이 제한이 없다. (슬라이드 41·43·44 노트 참고)
- 슬라이드 42의 "총 N문항"의 N은 **선택형 문항 수**다(서술형은 맞고 틀림이 없으므로). 엔지니어 완성본(`checkpoint-m6`)과 같다.
- 피드백 초안 로직은 브라우저에서 "정답 비교 + 교사가 입력한 문항별 안내 문구 조합"만 쓴다. AI 호출 없음, 요금제 불필요.
- 슬라이드 45은 심화 선택 박스다. 조립 단계(deck-builder)에서 눈에 띄는 "심화 선택" 박스 스타일로 표시해야 한다. 아래 45번 블록에 `[deck-builder 표기]`를 남겼다.

### 시간 합계 검산 (노트 기준)
| 슬라이드 | 40 | 41 | 42 | 43 | 44 | 45 | 46 | 합계 |
|---|---|---|---|---|---|---|---|---|
| 분 | 2 | 2 | 6 | 6 | 6 | 2 | 1 | **25** |

설명 7분 = 40(2) + 41(2) + 45(2) + 46(1). 실습 18분 = 42(6) + 43(6) + 44(6).
개념 연속 규칙: 40, 41 두 장 뒤에 실습 42이 오고, 45(데모), 46(정리)로 이어진다.

## [슬라이드 40] 맞춤 피드백, 세 단계로 만든다
- 유형: 개념
- 본문:
  - 답안 읽기 → 초안 만들기 → 교사가 검토해 전달
  - 초안은 보조교사가, 최종 책임은 교사가
  - 학생에게는 교사가 저장한 피드백만 보인다
- 도식: 가로 3칸 화살표 흐름. 1) "답안 읽기(학생 답안지 `submissions/{uid}`)" 2) "초안 만들기(정답 비교 + 안내 문구)" 3) "교사 검토·수정 후 저장(`feedback`)". 3번 칸만 강조색(`#b0402c`)으로 "교사 확인" 표시.
- 노트: (2분) "지난 시간에 학생 답안지가 쌓였습니다. 이제 답안지 한 장 한 장에 선생님 코멘트를 붙일 차례입니다. 서른 명 코멘트를 처음부터 쓰면 퇴근이 늦어집니다. 그래서 세 단계로 나눕니다. 먼저 답을 읽고, 정답과 비교해 초안을 만들고, 선생님이 고쳐서 보냅니다. 초안은 보조교사가 써 준 메모일 뿐, 학생에게 나가는 글은 반드시 선생님이 확인한 글입니다." 강조: 이 단계 구조는 오늘 만드는 기본 방식과 뒤의 AI 시연에서 똑같이 쓰인다. 소요 2분.

## [슬라이드 41] 비밀은 서버에, 피드백은 본인만
- 유형: 개념
- 본문:
  - AI 열쇠(API 키)를 브라우저에 두면 누구나 꺼내 쓴다
  - 열쇠는 서버(Cloud Functions = 교무실 금고)에 둔다
  - 피드백도 본인 답안지에 붙어 있어 본인만 본다
- 도식: 좌우 비교 2칸. 왼쪽 "X 브라우저에 키 보관: 학생이 개발자 도구로 열면 보임". 오른쪽 "O 서버(Cloud Functions)에 키 보관: 브라우저는 결과만 받음". 아래 한 줄 띠: "보안 원칙 2: 학생은 자기 제출물만 읽는다 (피드백도 제출물 안에 있다)".
- 노트: (2분) 용어 한 줄: 개발자 도구(F12 키로 여는 창) = 브라우저 속에 든 데이터를 들여다보는 점검 창, 교실로 치면 칠판 뒤편을 살피는 점검용 뒷문이다. "용어 하나만 설명합니다. Cloud Functions는 교무실 금고 같은 서버 쪽 공간입니다. 학생 화면(브라우저)에 들어 있는 것은 학생이 모두 열어볼 수 있다고 생각하셔야 합니다. 그래서 AI 키처럼 돈이 나가는 열쇠는 금고에 둡니다. 모듈 2에서 말씀드린 Firebase 웹 설정값은 공개해도 되는 것과 대비해 주세요. 오늘 기본 실습은 AI를 부르지 않으므로 키가 필요 없습니다. 두 번째 줄은 보안 원칙 2의 재확인입니다. 피드백이 `submissions/{uid}` 문서의 `feedback` 필드에 저장되므로, 학생 본인 문서만 읽을 수 있다는 같은 원칙이 적용됩니다. 같은 문서에 answers와 feedback이 함께 있으므로 쓰기 규칙을 나눈다. 교사는 feedback만 고칠 수 있고, 학생은 answers와 submittedAt만 고칠 수 있다. 이 규칙은 모듈 7 슬라이드 48에서 적용한다(지금 실습은 임시 규칙). Functions를 배포하려면 Blaze(종량제) 요금제가 필요하다(공식 문서). 무료 사용량과 AI API 비용은 연수 시점에 확인한다 `[확인필요: 무료 사용량·최신 정책]`. 소요 2분.

## [슬라이드 42] 실습: 정답 비교로 피드백 초안 만들기
- 유형: 실습
- 본문:
  - 선택형은 정답과 비교해 "맞음 / 다시 보기"
  - 교사가 문항별 안내 문구를 적어 두면 초안에 붙는다
  - 제출현황 표에 "피드백 초안 만들기" 버튼 추가
- 프롬프트:
  ```
  교사용 제출현황 표에서 학생 한 명을 눌러 답안을 볼 때, 그 화면에 "피드백 초안 만들기" 버튼을 추가해 줘.
  버튼을 누르면 다음 규칙으로 피드백 초안 글을 만들어 입력칸(여러 줄 텍스트)에 채워 줘.
  1) 선택형 문항은 학습지 문서 questions의 answer(0부터 세는 정답 보기 번호)와 학생 answers의 같은 순서 값을 비교한다. 맞으면 "문항 N: 맞았어요", 틀리면 "문항 N: 다시 한 번 살펴보세요"라고 쓴다. 문항 번호 N은 1부터 센다.
  2) 교사가 문항마다 "틀렸을 때 안내 문구"를 한 줄씩 입력할 수 있는 칸을 만들고, 틀린 문항에는 그 안내 문구를 이어서 붙인다. 안내 문구를 비워 두면 붙이지 않는다.
  3) 서술형 문항은 정답 비교를 하지 않고 "문항 N: 선생님이 직접 읽고 코멘트를 남길게요"라고 쓴다.
  4) 마지막 줄에 "총 N문항 중 M문항 맞았어요"를 넣는다. 여기서 N은 선택형 문항 수, M은 그중 맞은 수다. 선택형 문항이 없으면 이 줄은 넣지 않는다.
  이 단계에서는 AI를 부르지 말고 브라우저 코드만으로 만들고, 아직 Firestore에 저장하지 마. 초안은 입력칸에 채우기만 해.
  ```
- 예상 결과: 제출한 테스트 학생을 누르면 답안 아래에 "피드백 초안 만들기" 버튼이 보이고, 누르면 문항별 "맞았어요 / 다시 한 번 살펴보세요" 문장과 마지막 점수 줄(선택형 기준, 예: "총 2문항 중 1문항 맞았어요")이 입력칸에 채워진다. 틀린 문항 줄 뒤에는 교사가 적은 안내 문구가 붙는다. 이 시점에 Firestore에는 아직 아무것도 저장되지 않는다.
- 막힐 때:
  - 모든 문항이 틀렸다고 나온다 → 학습지에서 선택형 정답이 입력되어 있는지 확인. 그래도 같으면 화면 문구와 오류 메시지를 그대로 Claude Code에 붙여넣고 "정답 비교가 왜 모두 틀리게 나오는지 고쳐 줘"라고 요청
  - 버튼이 안 보인다 → 브라우저에서 새로고침(강력 새로고침) 후 교사 계정으로 로그인했는지 확인
- 노트: (6분) 시작 전 "정답 비교는 컴퓨터가 잘합니다. 서술형은 사람이 읽어야 합니다. 그래서 서술형 칸은 선생님이 쓰도록 비워 둡니다"라고 짚는다. 프롬프트 전체를 복사해 Claude Code에 붙여넣게 하고 코드는 읽지 않아도 된다고 안내. 5분 시점에 버튼이 보이지 않는 분을 조교가 확인. 이 단계는 저장하지 않는다는 점을 강조(다음 슬라이드에서 저장). 테스트 학생 계정의 제출 데이터만 사용하고 실제 학생 이름은 쓰지 않는다. 소요 6분.

## [슬라이드 43] 실습: 고쳐서 저장하면 학생 화면에 도착
- 유형: 실습
- 본문:
  - 교사가 초안을 마음대로 고친 뒤 "저장"
  - 저장 위치는 `submissions/{uid}`의 `feedback`
  - 학생 화면에 "선생님 피드백" 카드가 보인다
- 프롬프트:
  ```
  교사용 피드백 입력칸 아래에 "피드백 저장" 버튼을 추가해 줘.
  누르면 입력칸의 글을 그 학생의 제출물 문서 classes/{classId}/worksheets/{id}/submissions/{uid} 의 feedback 필드에 저장해 줘. 교사는 feedback 필드만 바꾸고, 다른 필드(answers, submittedAt)는 건드리지 마. (updateDoc으로 feedback만 갱신)
  저장하면 "저장했어요"라고 알려 주고, 이미 저장된 피드백이 있으면 학생을 다시 열 때 입력칸에 불러와서 다시 고칠 수 있게 해 줘.
  그리고 학생 화면에서 자신이 제출한 학습지 아래에, feedback 필드가 있을 때만 "선생님 피드백" 카드를 보여 줘. 내용은 글 그대로(줄바꿈 유지) 보여 주고, feedback이 없으면 "아직 피드백이 없어요"라고 표시해 줘.
  피드백 글은 화면에 넣을 때 HTML로 해석하지 말고 글자 그대로 출력해 줘.
  ```
- 예상 결과: 교사 화면에서 초안을 고쳐 저장하면 "저장했어요"가 뜬다. 콘솔 Firestore에서 해당 submissions 문서에 `feedback` 필드가 생긴다. 테스트 학생 계정으로 같은 학습지를 열면 "선생님 피드백" 카드에 방금 쓴 글이 보이고, 저장 전에는 "아직 피드백이 없어요"가 보인다.
- 막힐 때:
  - 저장 시 "권한 부족(permission-denied)" 오류 → 실습 중 임시 규칙(모듈 2 슬라이드 13에서 적용, 로그인하면 수업 아래 읽기·쓰기 허용)이 그대로인지 확인하고, 오류 메시지를 그대로 Claude Code에 붙여넣어 요청. 최종 규칙은 모듈 7에서 완성
  - 학생 화면에 카드가 안 보인다 → 학생 계정이 그 수업에 가입되어 있고 제출했는지 확인한 뒤 새로고침
- 노트: (6분) 핵심 메시지는 "초안은 보조교사, 저장은 선생님의 확인 도장"이다. 교사가 저장하기 전에는 학생에게 아무것도 보이지 않음을 시연으로 확인. 프롬프트 마지막 줄(HTML로 해석하지 말고 글자 그대로)은 교사 글이 화면에서 코드로 실행되지 않게 하는 안전 습관이라고 한 줄 설명하되 깊이 들어가지 않는다. 같은 문서에 answers와 feedback이 있어 쓰기 규칙을 나눈다고 예고한다. 교사는 feedback만, 학생은 answers와 submittedAt만 바꾼다(모듈 7 최종 규칙). 그래서 교사 저장은 feedback 하나만 갱신(updateDoc)하는 방식으로 만든다. 소요 6분.

## [슬라이드 44] 확인: 제출부터 피드백 수신까지 한 바퀴
- 유형: 실습
- 본문:
  - 학생 계정: 제출 → 교사 계정: 초안 → 수정 → 저장 → 학생 계정: 확인
  - 두 계정을 크롬 일반 창과 시크릿 창으로 나눠 쓴다
  - 전체 한 바퀴가 되면 완료
- 프롬프트: (이 슬라이드는 Claude Code 요청 없이 직접 확인하는 단계. 아래 체크리스트를 따른다.)
  ```
  1) 시크릿 창: 테스트 학생 계정으로 로그인 → 수업 선택 → 학습지 풀고 제출
  2) 일반 창: 교사 계정으로 로그인 → 제출현황에서 그 학생 선택 → "피드백 초안 만들기"
  3) 초안 끝에 교사 한마디를 한 줄 직접 써 넣기 → "피드백 저장"
  4) 시크릿 창: 학생 화면 새로고침 → "선생님 피드백" 카드에 내 글이 보이는지 확인
  5) (선택) 학생 답을 바꿔 다시 제출 → 교사 화면에서 초안을 다시 만들어 비교
  ```
- 예상 결과: 학생 화면의 "선생님 피드백" 카드에 교사가 고친 글(문항별 안내 + 직접 쓴 한마디)이 보인다. 교사 화면에서 같은 학생을 다시 열면 저장한 피드백이 입력칸에 불러와진다.
- 막힐 때:
  - 재제출하니 피드백이 사라졌다 → 학생 제출이 문서를 통째로 덮어쓰는 방식이면 `feedback`까지 지워진다(실습 중 임시 규칙에서는 실제로 지워짐). 모듈 5 슬라이드 36를 병합 저장으로 만들었다면 생기지 않는다. Claude Code에 "학생이 재제출해도 기존 feedback 필드는 지우지 말고, 병합 저장으로 answers와 submittedAt만 갱신해 줘"라고 요청. (모듈 7 최종 규칙에서는 덮어쓰기가 거부되어 권한 오류로 드러난다.)
  - 학생 화면에 다른 학생의 피드백이 보이는 것 같다 → 로그인한 계정이 맞는지 확인(화면 상단 이름). 두 계정을 한 창에서 오가지 않기
- 노트: (6분) 짝과 역할을 나눠도 좋다(한 명은 학생, 한 명은 교사 화면). 완료한 분은 손을 들게 하고 조교가 `checkpoint-m6`와 비교. 이 한 바퀴가 오늘의 "맞춤 피드백" 기본 완성이므로 모든 참가자가 여기까지 오는 것이 목표. 여기서 못 끝낸 분은 45번 데모를 보면서 이어서 해도 된다고 안내. 실제 학생 정보 사용 금지를 다시 한 번 상기. 소요 6분.

## [슬라이드 45] 심화 선택: AI가 초안을 써 주는 피드백 (강사 시연)
- 유형: 데모
- 본문:
  - 선택 과정: 오늘은 강사 시연, 직접 만들기는 연수 후 과제
  - 브라우저 → 함수(서버) → AI → 교사 화면 → 교사가 저장
  - AI 키는 서버에만. Functions 배포는 Blaze(종량제) 요금제가 필요하고 AI 비용도 든다
- 도식: 5칸 가로 흐름(마지막 칸만 강조색 "교사 확인"). "브라우저(교사가 버튼 클릭)" → "Cloud Functions(키 보관, 답안 전달)" → "AI(초안 생성)" → "교사 화면 입력칸(함수가 초안을 돌려줌, 저장 안 함)" → "교사가 검토 후 저장(Firestore `feedback`)". 3번째 칸 위에 자물쇠 아이콘 "API 키는 여기만". 함수는 Firestore에 직접 쓰지 않는다. 슬라이드 전체를 점선 테두리 + 상단 "심화 선택" 리본으로 표시. 오른쪽 아래에 연수 후 과제 프롬프트 링크/QR 자리 표시: `[QR/링크 자리: 연수 후 과제 프롬프트]` (내용은 아래 "연수 후 과제 프롬프트" 2개).
- 연수 후 과제 프롬프트: 한 번에 하나씩 순서대로 Claude Code에 붙여넣는다. (참고 구현은 엔지니어 문서, 실제 배포는 미검증)
  과제 1 — 함수 만들기
  ```
  이 클래스룸 프로젝트에 Cloud Functions 폴더(functions)를 추가해 줘. Node.js용 2세대 호출형 함수(onCall) 하나만 만들어 줘.
  - 함수 이름: generateFeedbackDraft, 지역: asia-northeast3
  - 입력: classId, worksheetId, studentUid
  - 함수 안에서 로그인한 사람이 classes/{classId}의 teacherUid와 같은지 먼저 확인하고, 아니면 거부해 줘.
  - classes/{classId}/worksheets/{worksheetId}의 questions와 submissions/{studentUid}의 answers를 읽어서 AI에게 보내 줘. 학생 이름, 이메일, uid는 AI에게 보내지 마.
  - AI API 키는 코드에 쓰지 말고 Firebase 비밀 값(Secret, 이름 AI_API_KEY)으로 읽어 줘.
  - AI 응답으로 받은 피드백 초안 글만 돌려주고, Firestore에는 저장하지 마. 저장은 교사가 화면에서 검토한 뒤에 한다.
  - 코드는 설명하지 말고, 내가 직접 해야 하는 일(요금제, 비밀 값 등록, 배포 명령)만 순서대로 알려 줘.
  ```
  과제 2 — 화면에 버튼 붙이기
  ```
  교사 제출현황의 학생 답안 화면에 "AI 초안 만들기" 버튼을 추가해 줘.
  - 누르면 generateFeedbackDraft 함수(지역 asia-northeast3)를 호출해서, 돌아온 글을 피드백 입력칸에 채워 줘. 바로 저장하지는 마.
  - 기다리는 동안 버튼을 잠그고 "AI가 초안을 쓰는 중…"이라고 보여 줘. 실패하면 오류를 쉬운 말로 보여 줘.
  - Firebase Functions SDK는 https://www.gstatic.com/firebasejs/12.19.0/firebase-functions.js 에서 불러와 줘.
  ```
- 노트: (2분) `[deck-builder 표기: 이 슬라이드는 "심화 선택" 박스 스타일(점선 테두리, 상단 리본 문구 "심화 선택 · 시간 되는 분만", 강조색 #356e67)로 조립. 기본 경로 슬라이드(40–44, 46)와 시각적으로 구분할 것]` 강사는 완성본(`checkpoint-final` 또는 심화 완성본)으로 시연한다. 같은 제출물에서 교사 버튼 한 번으로 AI 초안이 입력칸에 채워지는 모습을 보여 준다(이때 저장되지 않는다). 함수는 초안을 교사 화면으로 돌려줄 뿐이고, 교사가 고쳐서 "피드백 저장"을 눌러야 저장된다. 이 흐름은 방금 만든 기본 경로와 같다고 연결한다. 주의 말씀: Cloud Functions를 배포하려면 Blaze(종량제) 요금제와 결제수단 등록이 필요하고(공식 문서), 사용량에 따라 비용이 발생한다. `[확인필요: 무료 사용량, 최신 정책]` 키는 코드나 화면에 절대 노출하지 않고, 연수 중 참가자 키 입력은 하지 않는다. 연수 후 과제로 진행하려는 분은 링크의 프롬프트를 사용(콘솔 메뉴·CLI 명령은 `[확인필요]`). 소요 2분.
