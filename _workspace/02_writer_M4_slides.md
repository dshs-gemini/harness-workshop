- 예상 결과: (해당 없음)
- 막힐 때: (해당 없음)
- 노트: (2분) "이전 연수에서 만든 HTML 자료나 오늘 나눠 드린 샘플 자료를 생각하세요. 파일을 메일로 돌리는 대신 수업 안에 올려 두면, 가입한 학생만 수업 화면에서 열 수 있습니다. 자료는 `materials`라는 서랍에 한 장씩 들어갑니다. 서랍마다 제목(title), 내용(html), 올린 시각(createdAt)이 있습니다. ## [슬라이드 28] 자료는 유리 진열장에 넣어서 보여 준다
- 유형: 개념
- 본문: 원칙 1: 가입한 수업 자료만 읽는다. 원칙 5: 교사 HTML은 유리 진열장(sandbox iframe)에 넣어 보여 준다. 보이지만 손댈 수 없다.
- 도식: 좌우 2분할. 왼쪽 "원칙 1" 그림: 교실 A(가입함) 문은 열림, 교실 B(미가입) 문은 잠김 표시. 오른쪽 "원칙 5" 그림: 유리 진열장 안에 HTML 자료, 진열장 밖에 "로그인 정보"가 있고 진열장 안에서 밖으로 향한 손에 X 표시.
- 프롬프트: (해당 없음)
- 예상 결과: (해당 없음)
- 막힐 때: (해당 없음)
- 노트: (3분) "교실 열쇠(수업코드)로 가입한 학생만 그 교실 자료를 봅니다. 이것이 원칙 1입니다. 실제 잠금은 모듈 7에서 교무실 출입 규칙(보안 규칙)으로 완성합니다. 오늘은 '이런 규칙이 올 것이다' 정도만 기억하세요. 원칙 5입니다. 교사가 올린 HTML에는 스크립트가 들어 있을 수 있습니다. 그대로 우리 페이지에 끼워 넣으면 그 스크립트가 로그인 정보에 손을 댈 수 있습니다. 그래서 유리 진열장(sandbox iframe) 안에 넣어 보여만 줍니다." 
  [교사용 메모, 슬라이드에는 넣지 않음] sandbox 속성에서 `allow-same-origin`과 `allow-scripts`를 함께 주지 않는다. 이유: 두 가지를 같이 주면 srcdoc 안의 자료가 우리 페이지와 같은 출처로 취급되어 sandbox 속성 자체를 스스로 해제하고 로그인 정보에 접근할 수 있게 된다. 기본은 sandbox 속성을 값 없이(모든 제한 유지) 쓰고, 자료에 동작(스크립트)이 꼭 필요하면 `allow-scripts`만 따로 준다 `[확인필요: 최신 브라우저 동작]`. 이 모듈의 프롬프트는 값 없는 sandbox를 요청한다. 사실 확인은 content-reviewer가 한다.

## [슬라이드 29] 실습 1: 교사 자료 등록 폼 만들기
- 유형: 실습
- 본문: 수업 화면에 자료 등록 폼을 추가한다. 제목을 쓰고 HTML을 붙여넣어 저장한다. 저장 위치는 `classes/{classId}/materials/{id}`.
- 도식: 폼 화면 스케치. [제목 입력칸] [HTML 붙여넣기 큰 입력칸] [저장 버튼], 아래에 "저장됨" 메시지.
- 프롬프트:
```
현재 프로젝트의 교사용 수업 화면에 "수업자료 등록" 폼을 추가해 줘.

- 입력칸 2개: 제목(title), HTML 붙여넣기(html, 여러 줄 입력칸)
- "저장" 버튼을 누르면 Firestore의 classes/{classId}/materials 컬렉션에 문서를 새로 추가해 줘. 필드는 title, html, createdAt(서버 시간)만 써.
- 이 폼은 그 수업을 만든 교사(classes/{classId}의 teacherUid가 내 uid인 경우)에게만 보여 줘.
- 제목이 비어 있으면 저장하지 말고 "제목을 입력하세요"라고 알려 줘.
- html 내용의 크기를 UTF-8 바이트로 세어 90만 바이트를 넘으면 저장하지 말고 "자료가 너무 큽니다"라고 알려 줘.
- 저장에 성공하면 입력칸을 비우고 "저장했습니다"라고 보여 줘.
- 기존 로그인, 수업 만들기 기능은 건드리지 마.
```
- 예상 결과: 교사 계정으로 수업에 들어가면 제목칸과 HTML 입력칸이 있는 폼이 보인다. 샘플 HTML을 붙여넣고 저장하면 "저장했습니다"가 나온다. Firebase 콘솔 Firestore에서 `classes` → 해당 수업 → `materials`에 문서 1개가 생기고 title, html, createdAt이 들어 있다 `[확인필요: 콘솔 메뉴 이름]`.
- 막힐 때:
  - "Missing or insufficient permissions" 오류: 임시 규칙은 materials 쓰기를 이미 허용하므로 규칙 미게시나 로그아웃이 원인일 가능성이 크다. 콘솔 Firestore 규칙 탭에 `firestore.temp.rules`가 게시되어 있는지, 로그인한 상태인지 확인한다. 그래도 같으면 오류 메시지를 붙여넣고 "규칙 파일은 바꾸지 말고 앱 코드에서 원인을 찾아 줘"라고 요청한다.
  - 폼이 안 보임: 교사 계정으로 내가 만든 수업에 들어갔는지 확인한다.
- 노트: (5분) 샘플 HTML 파일(강사 배포 자료 또는 복구 폴더의 `samples/sample-material.html`)을 열어 전체 복사해 붙여넣게 한다. "코드는 우리가 쓰지 않습니다. 이 문장을 그대로 붙여넣으세요." 실행 후 콘솔에서 문서가 생겼는지 직접 보게 한다. 역할(role)은 화면 분기용이고, 권한 판정은 `classes/{classId}.teacherUid`로 한다는 점을 한 줄로 짚는다(프롬프트 속 조건이 그 뜻). 5분 안에 못 끝낸 참가자는 옆 사람과 함께 보게 하고 다음 슬라이드로 넘어간다. (강사 참고: 크기 기준은 글자가 아니라 바이트다. 한글은 글자당 3바이트라 한글 위주 자료는 약 30만 글자에서 걸린다. 프롬프트에는 바이트 기준만 쓴다.)

## [슬라이드 30] 실습 2: 학생 자료 목록과 유리 진열장 열람
- 유형: 실습
- 본문: 학생 수업 화면에 자료 목록을 만든다. 제목을 누르면 유리 진열장(sandbox iframe) 안에 자료를 보여 준다.
- 도식: 학생 화면 스케치. 왼쪽 자료 제목 목록, 오른쪽 큰 테두리 상자(= 유리 진열장) 안에 선택한 자료가 표시. 상자 테두리에 "sandbox" 라벨.
- 프롬프트:
```
현재 프로젝트의 학생용 수업 화면에 "수업자료" 목록을 추가해 줘.

- classes/{classId}/materials 컬렉션에서 자료를 불러와 최신순(createdAt 내림차순)으로 제목만 목록으로 보여 줘.
- 제목을 누르면 그 자료의 html 필드를 iframe의 srcdoc 속성으로 화면에 보여 줘.
- 그 iframe에는 반드시 sandbox 속성을 값 없이(모든 제한을 유지하는 형태로) 붙여 줘. allow-same-origin과 allow-scripts는 절대 넣지 마.
- 자료가 하나도 없으면 "아직 등록된 자료가 없습니다"라고 보여 줘.
- 교사 화면에서도 같은 목록과 열람이 되게 해 줘.
- 자료 html을 이 페이지의 다른 곳에 innerHTML로 넣지 마. 오직 iframe의 srcdoc으로만 보여 줘.
```
- 예상 결과: 학생 계정으로 가입한 수업에 들어가면 자료 제목 목록이 보인다. 제목을 누르면 박스 안에 자료가 나타난다. 자료 속 버튼이나 스크립트 동작은 막혀 있어도 정상이다(유리 진열장이므로).
- 막힐 때:
  - 자료가 하얀 화면으로만 보임: 샘플 HTML이 비었거나 일부만 붙여넣어졌다. 교사 화면에서 다시 등록해 본다.
  - 자료 속 버튼이 눌러지지 않음: 오류가 아니다. sandbox의 의도된 동작이다. 노트 설명 참고.
  - 목록 정렬 관련 "색인 필요" 오류: 단일 필드 정렬(createdAt)은 색인이 자동으로 만들어져 보통 나오지 않는다. 혹시 나오면 오류 메시지의 링크 안내를 Claude Code에 붙여넣어 해결한다.
- 노트: (5분) 핵심은 "자료는 iframe 안에서만 열린다"이다. 용어: srcdoc = 자료 글을 진열장 안에 직접 넣는 방식(진열장에 물건을 바로 올려 두는 것). 프롬프트에 allow-same-origin, allow-scripts를 넣지 말라는 줄이 있는 이유를 말로 설명한다: 두 가지를 함께 주면 진열장 유리가 사라져 자료 속 스크립트가 로그인 정보에 닿을 수 있다. 자료의 버튼이 안 눌리는 것은 정상임을 미리 말해 둔다. 이 설명이 없으면 "고장 났어요" 질문이 몰린다. 스크립트가 꼭 필요한 자료는 연수 후 과제로 안내한다.

## [슬라이드 31] 실습 3: 학생 계정으로 열람해 확인하기
- 유형: 실습
- 본문: 테스트 학생 계정(시크릿 창)으로 가입한 수업의 자료를 열어 본다. 가입하지 않은 계정에서는 안 보여야 한다. 실제 차단 검증은 모듈 7에서 한다.
- 도식: 체크리스트 3줄. [ ] 교사 계정: 자료 등록 완료 / [ ] 학생 계정(가입함): 목록·열람 OK / [ ] 학생 계정(미가입): "모듈 7에서 차단 확인" 예고 표시.
- 프롬프트:
```
방금 만든 수업자료 기능을 점검하려고 해. 다음을 확인해서 결과를 알려 줘.

1. 학생 화면에서 자료 목록과 iframe 열람이 정상 동작하는지 코드로 점검해 줘.
2. iframe의 sandbox 속성에 allow-same-origin 또는 allow-scripts가 들어 있지 않은지 확인해 줘.
3. 자료 html을 innerHTML 등으로 직접 화면에 넣는 곳이 없는지 찾아 줘.
4. 문제가 있으면 고치고, 무엇을 고쳤는지 한국어로 3줄 이내로 요약해 줘.
```
- 예상 결과: Claude Code가 "문제 없음" 또는 수정 내역 3줄 이내를 알려 준다. 사람의 확인: 시크릿 창에서 테스트 학생 계정으로 로그인해 수업코드로 가입하고 자료를 열어 본다. 가입하지 않은 두 번째 계정에서는 이 수업이 내 수업 목록에 없으므로 자료로 들어갈 길이 없다. 단, 규칙으로 막는 것은 모듈 7에서 검증한다.
- 막힐 때:
  - 학생 계정에서 목록이 비어 있음: 그 학생이 수업코드로 가입했는지(`members/{uid}` 문서) 확인한다. 교사가 자료를 등록했는지도 확인한다.
  - 시크릿 창 로그인이 안 됨: 모듈 2 막힘 모음(승인된 도메인, 팝업 차단)을 다시 본다.
- 노트: (3분) 먼저 시크릿 창으로 학생 확인을 시킨 뒤 위 프롬프트를 붙여넣게 한다. "여기서 일부러 차단 시도는 하지 않습니다. 규칙을 아직 완성하지 않았기 때문입니다. 모듈 7에서 학생 계정으로 미가입 수업 자료를 열어 보고 막히는 것을 눈으로 확인합니다." 실제 학생 계정이나 이름은 쓰지 않고 테스트 계정만 쓴다(개인정보 원칙).

## [슬라이드 32] 정리: 막힘 모음과 복구 지점
- 유형: 정리
- 본문: 오늘 만든 것: 자료 등록 폼 + 수업별 자료 목록·열람(유리 진열장). 막히면 `checkpoint-m4`를 연다. 다음은 웹 학습지.
- 도식: 3칸 요약. [등록 `materials`] → [목록] → [유리 진열장 열람]. 아래에 "막힘 모음" 상자 2개.
- 프롬프트: (해당 없음)
- 예상 결과: 교사가 자료를 올리고, 학생이 가입한 수업의 자료를 박스 안에서 열어 볼 수 있다.
