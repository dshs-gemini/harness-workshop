# 02. 슬라이드 원고: 모듈 3 수업코드 수강신청 (슬라이드 19–26)

## 가정
- 슬라이드 번호·장수·시간은 커리큘럼 고정값을 그대로 쓴다. 모듈 3 = 19–25(7장, 25분), 휴식 = 26(1장, 10분).
- 모듈 2 완료 상태(구글 로그인, `users/{uid}.role` 저장, 역할 선택 화면)에서 이어 시작한다고 가정한다.
- 수업 문서 이름(classId)을 수업코드와 같게 한다(결정 D1). 학생은 joinCode 검색(where)이 아니라 `classes/{코드}` 문서 1건만 읽는다. 검색 방식은 최종 보안 규칙(모듈 7)에서 권한 오류가 나기 때문이다.
- `members/{uid}`에 `uid` 필드를 추가하고(결정 D2, 사용자 승인된 명세 변경, 갱신된 명세 반영), "내가 가입한 수업"은 컬렉션 그룹 조회 + 색인 1개로 찾는다. 색인 생성 화면의 메뉴 이름·소요 시간은 `[확인필요]`로 유지한다.
- 모듈 2에서 임시 보안 규칙이 적용되어 있다고 가정한다. 최종 규칙은 모듈 7에서 완성한다.

---

## [슬라이드 19] 수업코드 = 교실 열쇠
- 유형: 개념
- 본문: 수업을 만들면 6자리 수업코드가 생긴다. 그 코드가 수업 문서의 이름이다. 학생은 코드(교실 열쇠)로 들어온다.
- 도식: 왼쪽에 서류함 그림 두 칸. `classes/{수업코드}` 카드(폴더 이름표 "K7M4QX", 내용: title, teacherUid, joinCode)와 그 안쪽의 `members/{uid}` 카드(joinedAt, uid)를 폴더 안의 폴더로 그린다. 열쇠 아이콘에 "수업코드 예: K7M4QX = 폴더 이름"을 붙인다. 화살표: 교사 → classes/{코드} 생성, 학생 → 코드 입력 → classes/{코드} 한 장 꺼내기 → members 추가.
- 노트: (3분) "오늘의 두 번째 기능입니다. 교실에 들어가려면 열쇠가 필요하죠. 교사가 수업을 만들면 서류함에 수업 카드가 한 장 생기고, 그 카드의 이름표가 열쇠 번호인 수업코드입니다. 학생이 코드를 넣으면 그 이름표의 폴더를 바로 꺼내고, 그 안에 '출석 명단' 카드가 한 장 생깁니다. 카드 이름이 학생 uid(출석부 번호)입니다. 출석 명단 카드에는 uid를 한 번 더 적어 둡니다. '내가 가입한 수업'을 찾는 데 쓰입니다." teacherUid는 만든 교사의 uid라고 짚는다. 용어 첫 등장: Firestore=학급 서류함, joinCode=교실 열쇠. 여기까지 개념 1장.

## [슬라이드 20] 보안 원칙 3·4 미리보기
- 유형: 개념
- 본문: 원칙 3: 수업은 교사만 만든다. 원칙 4: 수업코드를 알아야 들어간다. 전체 수업 목록은 학생이 볼 수 없다.
- 도식: 교무실 출입문 그림(보안 규칙 = 교무실 출입 규칙). 두 줄 표. 위 줄 "수업 만들기: 교사 O / 학생 X". 아래 줄 "코드 한 개로 한 교실 찾기 O / 모든 교실 목록 훑어보기 X". 옆에 작은 글씨로 "전체를 내려받아 비교하지 않는다".
- 노트: (4분) "보안 규칙은 교무실 출입 규칙입니다. 규칙 5개를 오늘 하나씩 소개하고, 마지막 모듈에서 한꺼번에 적용해서 막히는지 직접 확인합니다. 오늘은 3번과 4번입니다. 수업 작성은 그 수업의 교사만 할 수 있습니다. 판단 기준은 role 표시가 아니라 수업 문서의 teacherUid입니다. 그리고 4번, 학생이 수업 목록 전체를 열어 코드를 훑어보고 알아내면 열쇠의 의미가 없습니다. 그래서 코드를 아는 사람만 그 교실 하나를 찾게 합니다. 구현은 이렇습니다. 수업 문서의 이름을 수업코드로 붙입니다. 그러면 학생은 코드로 그 문서 한 장만 바로 꺼낼 수 있고, 서류함 전체를 뒤질 필요도, 권한도 없습니다." 설명 7분 중 개념 2장 완료. 다음 장부터 실습입니다." 질문: "수업코드를 칠판에 그대로 써 두면 어떻게 될까요?" 한 줄 던지고 넘어가도 된다(선택).

## [슬라이드 21] 실습 1: 교사가 수업 만들기
- 유형: 실습
- 본문: 교사 화면에 "수업 만들기"를 추가한다. 제목을 넣으면 6자리 수업코드가 자동 발급된다.
- 도식: 화면 목업. 제목 입력칸 + [수업 만들기] 버튼 → 아래에 "수업코드: K7M4QX" 크게 표시.
- 프롬프트:
```
지금 만든 클래스룸 앱의 교사 화면에 "수업 만들기" 기능을 추가해 줘.
- 교사(users 문서의 role이 teacher인 사람)에게만 수업 만들기 화면이 보이게 해 줘.
- 수업코드(joinCode)는 영문 대문자와 숫자 6자리 무작위 문자열로 만들어 줘. 헷갈리는 글자 0, O, 1, I는 쓰지 마.
- Firestore의 classes 컬렉션에 수업 문서를 만들 때 문서 이름(문서 ID)을 수업코드와 똑같이 해 줘. 경로는 classes/{수업코드}야.
- 문서 필드는 title, teacherUid, joinCode 세 개만 쓰고, teacherUid에는 지금 로그인한 교사의 uid, joinCode에는 수업코드를 넣어 줘.
- 저장하기 전에 classes/{수업코드} 문서가 이미 있는지 한 건만 읽어서 확인하고, 있으면 코드를 새로 만들어 줘.
- 만든 뒤에는 화면에 수업 제목과 수업코드를 크게 보여 줘.
```
- 예상 결과: 교사 계정으로 로그인하면 "수업 만들기" 입력칸이 보인다. 제목을 넣고 누르면 6자리 코드(예: K7M4QX)가 화면에 크게 뜬다. 코드에 0, O, 1, I가 없다. Firebase 콘솔의 Firestore 데이터 화면에서 `classes` 아래 새 문서에 title, teacherUid, joinCode가 보이고, 문서 이름이 수업코드(예: `K7M4QX`)와 같다 `[확인필요: 콘솔 메뉴 이름]`.
- 막힐 때: (1) 권한 오류(permission-denied / "Missing or insufficient permissions")가 나면 임시 규칙은 이 동작을 이미 허용하므로 규칙 문제가 아닐 가능성이 크다. Firebase 콘솔 Firestore 규칙 탭에 `firestore.temp.rules`가 게시되어 있는지, 앱에 로그인한 상태인지 확인한다. 그래도 같으면 오류 메시지 전체를 Claude Code에 붙여넣고 "규칙 파일은 바꾸지 말고 앱 코드에서 원인을 찾아 줘"라고 요청한다. (2) 수업 만들기 칸이 안 보이면 내 계정의 role이 teacher인지 콘솔의 `users/{uid}` 문서에서 확인한다.
- 노트: (6분) 프롬프트를 통째로 복사해 Claude Code에 붙여넣게 한다. 코드는 직접 쓰지 않는다. 0/O, 1/I를 빼는 이유: 칠판에 쓴 코드를 학생이 잘못 읽지 않도록. "teacherUid를 넣는 것이 중요합니다. 나중에 이 수업의 주인이 누구인지 판단하는 기준이 됩니다. 문서 이름이 수업코드인 것도 확인하세요. 다음 실습에서 학생이 이 이름으로 문서를 꺼냅니다."

## [슬라이드 22] 실습 2: 학생이 코드로 가입하기
- 유형: 실습
- 본문: 학생 화면에 수업코드 입력칸을 만든다. 맞는 코드면 그 수업의 members에 내 문서가 생긴다.
- 도식: 화면 목업. 코드 입력칸 + [가입하기] 버튼. 아래에 흐름: 코드 입력 → `classes/{코드}` 1건 읽기 → `classes/{코드}/members/{내 uid}` 생성(joinedAt, uid).
- 프롬프트:
```
학생 화면에 "수업코드로 가입하기" 기능을 추가해 줘.
- 학생(role이 student인 사람) 화면에 수업코드 입력칸과 [가입하기] 버튼을 만들어 줘.
- 입력한 코드는 앞뒤 공백을 지우고 대문자로 바꿔서 사용해 줘.
- 수업 문서 이름이 수업코드이므로, classes/{입력한 코드} 문서 한 건만 읽어서(getDoc) 수업이 있는지 확인해 줘. classes 컬렉션 전체를 내려받거나 where 조건으로 검색하지 마.
- 수업이 있으면 classes/{코드}/members/{내 uid} 문서를 만들고, 필드는 joinedAt(서버 시각)과 uid(내 uid) 두 개만 저장해 줘.
- 그 members 문서가 이미 있으면 "이미 가입한 수업이에요"라고 알려 줘.
- 수업이 없으면 "수업코드를 다시 확인해 주세요"라고 알려 줘. 코드 형식(6자리)이 아니면 읽기 전에 같은 안내를 보여 줘.
```
- 예상 결과: 학생 계정에서 교사가 만든 코드를 넣으면 "가입했어요" 같은 메시지가 뜬다. 콘솔에서 `classes/{수업코드}/members/{학생 uid}` 문서가 생겼고 joinedAt과 uid가 들어 있다. 같은 코드를 또 넣으면 "이미 가입한 수업"이라고 나온다.
- 막힐 때: (1) "Missing or insufficient permissions"가 나오면 임시 규칙은 학생의 classes/{코드} 읽기와 members 쓰기를 이미 허용한다. 콘솔 Firestore 규칙 탭에 `firestore.temp.rules`가 게시되어 있는지, 로그인한 상태인지 확인한다. 그래도 같으면 오류 전체를 붙여넣고 "규칙 파일은 바꾸지 말고 앱 코드에서 원인을 찾아 줘"라고 요청한다(최종 규칙은 모듈 7에서 완성한다). (2) 맞는 코드인데 "없는 코드"라고 나오면 코드를 복사해 붙여넣고 소문자·공백이 섞이지 않았는지 확인한다.
- 노트: (5분) 이 프롬프트의 핵심 문장은 "문서 한 건만 읽고, 전체를 내려받거나 where로 검색하지 마"입니다. 보안 원칙 4와 연결된다고 다시 한 번 말한다. 검색(where)으로 만들면 지금은 되는 것처럼 보여도 모듈 7 최종 규칙에서 권한 오류가 난다고 예고한다. "members 문서에 uid를 한 번 더 적는 이유는 다음 슬라이드에서 '내가 가입한 수업'을 찾기 위해서입니다." 테스트 학생 계정은 시크릿 창에서 로그인(모듈 2 슬라이드 17 방식).

## [슬라이드 23] 실습 3: 내 수업 목록
- 유형: 실습
- 본문: 교사는 내가 만든 수업, 학생은 내가 가입한 수업이 목록으로 보인다. 학생 목록에는 수업 제목만 보인다.
- 도식: 화면 목업 두 개를 나란히. 교사: "내가 만든 수업" 목록(제목 + 수업코드). 학생: "내가 가입한 수업" 목록(제목만, 수업코드는 표시하지 않음).
- 프롬프트:
```
로그인한 뒤 첫 화면에 "내 수업" 목록을 보여 줘.
- 교사: classes에서 teacherUid가 내 uid인 수업만 조회해서 제목과 수업코드를 보여 줘. 정렬은 가져온 뒤 브라우저에서 제목 순으로 해 줘(Firestore orderBy는 쓰지 마).
- 학생: members 컬렉션 그룹 조회(collectionGroup)로 uid 필드가 내 uid인 가입 문서만 찾고, 각 가입 문서의 부모 수업 문서(classes/{classId})를 한 건씩 읽어서 제목만 보여 줘. 학생 화면에는 수업코드를 보여 주지 마. 수업 전체 목록을 가져와서 걸러내는 방식은 쓰지 마.
- 목록이 비어 있으면 "아직 수업이 없어요"라고 보여 줘.
- 수업 제목을 누르면 그 수업 화면(주소 끝이 #/class/{classId})으로 이동하게 해 줘. 수업 화면에는 수업 제목, (교사에게만) 수업코드, "← 내 수업으로" 버튼만 먼저 만들어 줘. 자료와 학습지는 다음 시간에 붙일 거야.
```
- 예상 결과: 교사 계정에는 방금 만든 수업과 코드가 보인다. 학생 계정에는 가입한 수업의 제목이 보인다. 수업이 없는 계정은 "아직 수업이 없어요"가 뜬다.
- 막힐 때: (1) 학생 목록을 처음 열면 거의 모두에게 "The query requires a COLLECTION_GROUP_ASC index"로 시작하는 오류와 링크가 브라우저 콘솔(또는 화면)에 뜬다. 링크를 눌러 색인을 만들고 1~5분 기다린 뒤 새로고침한다 `[확인필요: 오류 문구 정확한 표기, 색인 생성 화면 메뉴 이름, 소요 시간]`. 링크 대신 오류 전체를 Claude Code에 붙여넣고 "색인 안내대로 해결해 줘"라고 해도 된다. (2) 권한 오류면 콘솔 Firestore 규칙 탭에 `firestore.temp.rules`가 게시되어 있는지, 로그인한 상태인지 먼저 확인한다. 그래도 같으면 오류 전체를 붙여넣고 "규칙 파일은 바꾸지 말고 앱 코드에서 원인을 찾아 줘"라고 요청한다.
- 노트: (4분) **슬라이드 시작 전에 "이 오류는 거의 모두에게 한 번 나옵니다"라고 미리 말한다.** 컬렉션 그룹 조회는 "모든 수업의 출석 명단을 한꺼번에 훑어 내 이름표만 찾는 조회"입니다. 색인(인덱스)은 도서관의 색인 카드입니다. 색인을 만드는 동안 기다리지 말고 슬라이드 24 짝 활동(교사 쪽 가입 확인)을 먼저 진행해도 됩니다. 강사는 연수 전에 강사 프로젝트에서 색인 생성 시간을 재 둔다. 모든 수업의 출석 명단에서 내 uid를 찾으려면 Firestore가 "색인 카드를 먼저 만들어 주세요"라고 요청합니다(색인은 1개). 오류가 아니라 안내이니 당황하지 말라고 말해 준다. 슬라이드 22에서 uid를 한 번 더 적어 둔 이유가 바로 이 조회입니다. "학생 목록에서 수업코드를 보여 주지 않는 이유: 코드는 교실 열쇠이니 가입한 뒤에도 교사만 나눠 주도록."

## [슬라이드 24] 짝 활동: 옆 사람 수업코드로 가입
- 유형: 실습
- 본문: 옆 사람의 수업코드로 가입해 보자. 일부러 틀린 코드도 넣어 보자. 어떻게 되는가?
- 도식: 두 사람이 코드를 주고받는 그림. 아래 체크 질문 3개: (1) 맞는 코드를 넣으면? (2) 틀린 코드를 넣으면? (3) 같은 코드를 두 번 넣으면?
- 프롬프트: (Claude Code 프롬프트 없음. 짝과 직접 확인한다.)
- 예상 결과: (1) 가입 성공, 내 수업 목록에 나타남. (2) "수업코드를 다시 확인해 주세요" 안내가 뜸. (3) "이미 가입한 수업이에요".
- 막힐 때: 틀린 코드에서 오류 화면(흰 화면)이 나오면 Claude Code에 "틀린 코드를 넣으면 친절한 안내가 나오게 해 줘"라고 요청한다.
- 노트: (2분) 한 명은 교사, 한 명은 학생 역할로 바꿔서 진행해도 되고, 각자 시크릿 창의 테스트 학생 계정을 써도 된다. 실제 학생 이름·이메일은 쓰지 않는다. 정답: (1) 가입 성공, 내 수업 목록에 나타남. (2) "수업코드를 다시 확인해 주세요" 안내가 뜨고 아무것도 만들어지지 않음(6자리가 아니면 읽기 전에, 6자리지만 없는 코드면 읽은 뒤에 안내. 둘 다 같은 문구). (3) "이미 가입한 수업이에요". 틀린 코드에서 오류 화면(흰 화면)이 나오면 Claude Code에 "틀린 코드를 넣으면 친절한 안내가 나오게 해 줘"라고 요청하게 한다. 시간이 남으면 질문: "코드를 한 글자만 바꾸어 가며 계속 넣으면 어떻게 될까요?" (마지막 모듈에서 규칙을 점검할 때 다시 생각해 보자고 예고.)

## [슬라이드 25] 막힘 모음 + 복구 지점 checkpoint-m3
- 유형: 정리
- 본문: 색인 필요 오류는 안내 링크로 해결. 권한 오류는 오류 메시지를 통째로 붙여넣기. 그래도 막히면 `checkpoint-m3`.
- 도식: 막힘 유형 3칸 카드. (1) "The query requires an index" → 링크 클릭 / 몇 분 대기. (2) "Missing or insufficient permissions" → 오류 전체 붙여넣기. (3) 아무것도 안 보임 → 로그인한 계정의 role 확인. 맨 아래 폴더 아이콘 `checkpoint-m3`.
- 노트: (1분) 모듈 3 산출물: 수업 만들기(코드 발급) + 코드로 가입 + 내 수업 목록. 복구 지점: `checkpoint-m3`. "막혔다면 checkpoint-m3 폴더를 열고 다음 모듈부터 따라오세요." 다음은 10분 휴식이고, 막힌 분은 휴식 시간에 강사·조교가 `checkpoint-m3`로 복구를 도와 준다고 예고한다. 모듈 3 시간 합계: 슬라이드 19(3) + 20(4) + 21(6) + 22(5) + 23(4) + 24(2) + 25(1) = 25분 (설명 7 / 실습 18).

## [슬라이드 26] 휴식 10분
- 유형: 정리
- 본문: 휴식 10분. 막힌 분은 강사석으로. `checkpoint-m3`에서 이어 시작할 수 있어요.
- 도식: 큰 타이머 "10:00"과 커피잔 아이콘. 우측 아래 폴더 아이콘 `checkpoint-m3`.
- 노트: (10분) 휴식 시작 직전에 "수업 만들기, 코드 가입, 내 수업 목록이 되는 분은 그대로 쉬시고, 안 되는 분은 손을 들어 주세요"라고 말한다. 조교 동선: 교실 앞쪽에서 뒤쪽으로 한 바퀴 돌며 손든 참가자를 확인한다. 증상별로 (1) 로그인 자체가 안 되는 분은 모듈 2 막힘 모음 확인, (2) 수업 생성·가입이 안 되는 분은 `checkpoint-m3` 폴더를 열어 같은 폴더에서 Claude Code를 실행하게 안내한다. 복구 방법: (1) 나눠 준 `checkpoint-m3` 폴더를 통째로 내 컴퓨터에 복사한다(지금까지 쓰던 폴더는 지우지 않는다). (2) 복사한 폴더 안의 `firebase-config.js` 파일 하나만 내 설정값으로 바꾼다. 직접 바꾸려면 메모장으로 열어 `export const firebaseConfig = { ... };`의 중괄호 안을 슬라이드 9에서 복사해 둔 내 firebaseConfig 내용으로 통째로 바꿔 저장한다. Claude Code로 바꾸려면 복사한 폴더에서 Claude Code를 실행하고 다음을 붙여넣는다. 「이 폴더의 firebase-config.js 안에 있는 firebaseConfig 값을 아래 내 설정값으로 바꿔 줘. 다른 파일과 다른 내용은 절대 바꾸지 마. 바꾼 뒤 이 폴더를 localhost 주소로 여는 명령 한 줄만 알려 줘.」 그 아래에 슬라이드 9에서 복사한 firebaseConfig 블록을 붙인다. (3) localhost 주소로 열어 로그인한다. 설정값을 안 바꿨으면 화면 맨 위에 "firebase-config.js에 내 Firebase 설정값을 넣어 주세요"라는 빨간 안내가 보인다. (4) Firebase 콘솔 작업(프로젝트, 구글 로그인, Firestore, 임시 규칙)은 다시 하지 않는다. (5) 주의: 복구 지점으로 옮긴 뒤에는 수업을 새로 만든다. 내가 만든 테스트 수업은 문서 이름이 수업코드가 아니거나 members에 uid가 없어서 복구 화면에 안 보일 수 있다. users 문서(역할)는 그대로 쓸 수 있다. 휴식 후 모듈 4는 HTML 수업자료 등록(슬라이드 27)부터 시작한다.
