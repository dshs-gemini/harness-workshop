# 02. 슬라이드 원고: 모듈 1. 도입·완성본 데모 (슬라이드 1–6, 15분)

## 가정
- 번호 범위(1–6), 장수(6장), 시간(15분 = 설명 10 / 실습 5)은 커리큘럼 고정값 그대로 사용했다.
- 슬라이드별 시간: 1번 1분 + 2번 3분 + 3번 2분 + 4번 2분 + 5번 5분 + 6번 2분 = 15분. 실습(5번) 5분, 나머지 설명 10분.
- 데모는 완성본(`checkpoint-final`)을 사용한다. 슬라이드 2의 화면 캡처는 자리 표시만 두었다(deck-builder/강사가 실제 캡처 삽입).
- 참가자는 사전 준비(구글 계정, Claude Code, Node.js, Firebase CLI, 크롬)를 마쳤다고 가정한다. 미완료 참가자는 슬라이드 3에서 확인한다.
- 모듈 1 실습은 로그인이 없으므로 `index.html`을 파일로 직접 열어도 동작한다. 로컬 서버 필요 여부는 모듈 2에서 다룬다.
- 슬라이드 5의 터미널 명령과 Claude Code 실행 명령은 운영체제·버전에 따라 다를 수 있어 `[확인필요]`로 표시했다.

## [슬라이드 1] 나만의 온라인 클래스룸 만들기
- 유형: 정리
- 본문: Claude Code로 나만의 온라인 클래스룸 만들기 (교원 연수 180분)
  오늘의 최종 산출물: 배포된 내 클래스룸 웹 주소 1개
- 도식: 표지. 중앙에 연수 제목, 하단에 "오늘 집에 가져갈 것: https://(내 프로젝트).web.app 형태의 주소" 한 줄 (주소 형태는 예시 표기, 실제 도메인 형식은 모듈 7에서 확인).
- 노트: (1분) "오늘 여러분은 코드를 한 줄도 직접 쓰지 않고, 내 학급용 온라인 클래스룸을 만들어 인터넷 주소까지 가져갑니다. 로그인, 수업코드, 수업자료, 학습지, 맞춤 피드백까지 다섯 가지 기능입니다." 시작 시각을 알리고 바로 데모로 넘어간다.

## [슬라이드 2] 완성본 먼저 보기
- 유형: 데모
- 본문: 오늘 만들 클래스룸을 2분만 먼저 봅니다.
  교사: 수업 만들기 → 자료 → 학습지 → 피드백
  학생: 코드 가입 → 열람 → 제출 → 피드백 확인
- 도식: 가로 두 줄 흐름도.
  - 윗줄(교사, 보조색 `#356e67`): [수업 만들기] → [자료 등록] → [학습지 작성] → [피드백 전달]
  - 아랫줄(학생, 강조색 `#b0402c`): [수업코드로 가입] → [자료 열람] → [학습지 제출] → [내 피드백 확인]
  - 두 줄 사이에 세로 화살표: "수업코드", "제출 답안", "피드백"으로 교사-학생 연결.
  - 흐름도 옆에 **[화면 캡처 자리: 교사 화면 / 학생 화면 각 1장]**
- 노트: (3분) 강사가 완성본(`checkpoint-final`)을 열어 시연한다. 화면 두 개(교사 계정 일반 창, 테스트 학생 계정 시크릿 창)를 준비해 둔다.
  진행 순서: (1) 교사로 로그인해 수업을 만들고 수업코드를 보여준다. (2) 학생 창에서 그 코드로 가입한다. (3) 교사가 자료와 학습지를 올리면 학생 창에 나타나는 것을 보여준다. (4) 학생이 제출하고 교사가 피드백을 보내면 학생 화면에 도착하는 것을 보여준다.
  "지금은 어떻게 만드는지 몰라도 됩니다. 이 흐름이 오늘 우리가 지나갈 길입니다." 시연 계정은 모두 테스트 계정이며 실제 학생 이름을 쓰지 않았음을 한 마디 한다.

## [슬라이드 3] 오늘의 지도와 준비물 점검
- 유형: 개념
- 본문: 7개 모듈을 하나씩 더해 갑니다. 준비물: 구글 계정, Claude Code(유료 계정 필요), 크롬.
  연습은 테스트 계정으로만 합니다. 실제 학생 정보는 넣지 않습니다.
- 도식: 가로 로드맵 7칸.
  1 도입 → 2 로그인 → 3 수업코드 → (휴식) → 4 HTML 자료 → 5 학습지 → 6 맞춤 피드백 → 7 배포·보안
  아래에 준비물 체크박스 5개: [ ] 구글 계정(교사용) + 테스트 학생용 계정 1개 / [ ] Claude Code 로그인 완료 (Pro·Max·Team·Enterprise 또는 Console 계정 필요, 무료 플랜 불가) / [ ] Node.js, Firebase CLI 설치 / [ ] 터미널에서 `firebase login` 완료 / [ ] 크롬 브라우저
- 노트: (2분) 로드맵은 한 번만 훑는다. 기능을 한 칸씩 더하고, 모듈이 끝날 때마다 복구 지점이 있다고 예고한다.
  개인정보 원칙: "연습에서는 여러분의 두 번째 구글 계정 같은 테스트 계정만 학생 역할로 씁니다. 실제 학생 이름, 이메일은 절대 넣지 않습니다. 실제 학급에 쓸 때는 소속 기관의 개인정보 지침을 따릅니다."
  준비물이 안 된 참가자는 손을 들게 하고 조교가 휴식 전까지 돕는다.
  Claude Code 계정(사전 안내에도 반드시 포함): Claude Code는 Pro·Max·Team·Enterprise 또는 Console(API) 계정이 필요하고 무료 claude.ai 플랜으로는 쓸 수 없다(공식 문서 확인). 유료 계정 준비 여부는 연수 당일이 아니라 사전 안내 단계에서 걸러 둔다. 설치는 공식 설치 명령을 쓴다(macOS: `curl -fsSL https://claude.ai/install.sh | bash`). `[확인필요: Windows PowerShell 설치 명령 전체 문구]`
  용어 한 줄 비유: "Node.js = 도구를 돌리는 엔진, Firebase CLI = 터미널에서 Firebase에 올리는 배달 도구(설치 명령 `npm install -g firebase-tools`, Node.js 필요), 터미널 = 컴퓨터에 글자로 명령을 내리는 창(교무실 내선 전화)." `[확인필요: Node.js 최신 설치 방법]`
  `firebase login`은 브라우저 인증이 있어 모듈 7에서 시간이 길어진다. 사전 안내문에 넣고, 못 한 참가자는 휴식 시간에 마치게 한다.

## [슬라이드 4] Claude Code는 말로 시키는 보조교사
- 유형: 개념
- 본문: Claude Code = 말로 시키면 파일을 만들어 주는 보조교사.
  우리는 코드를 읽지 않고, 요청하고 확인합니다.
  요청이 구체적일수록 결과가 정확합니다.
- 도식: 3칸 순환 그림. [교사가 요청 문장을 쓴다] → [보조교사(Claude Code)가 파일을 만든다] → [교사가 화면에서 확인한다] → (다시 요청). 가운데 말풍선 예시: "환영 문구가 있는 첫 화면을 만들어 줘".
- 노트: (2분) 비유: "복사실에 자료 제작을 맡기는 것과 같습니다. 무엇을, 누구를 위해, 어떤 모양으로 원하는지 말해야 원하는 자료가 나옵니다." 코드의 의미를 이해하지 못해도 괜찮고, 결과가 화면에서 맞게 보이는지가 우리의 검수 기준이라고 안내한다.
  요청 문장 요령 한 줄: "무엇을 + 누구를 위해 + 확인 방법"을 적으면 좋다. 다음 슬라이드가 실습이므로 설명을 짧게 끝낸다.

## [슬라이드 5] 첫 요청: "환영합니다" 페이지 만들기
- 유형: 실습
- 본문: 1. 빈 폴더를 만들고 Claude Code를 실행합니다.
  2. 아래 요청 문장을 붙여넣습니다.
  3. 만들어진 index.html을 브라우저로 엽니다.
- 도식: 3단계 번호 카드. (1) 폴더 만들기 → (2) Claude Code 실행·요청 붙여넣기 → (3) 브라우저에서 확인. 마지막 카드에 "환영합니다" 화면 캡처 자리 표시.
- 프롬프트: 먼저 터미널(컴퓨터에 글자로 명령을 내리는 창, 교무실 내선 전화)에서 폴더를 만들고 Claude Code를 실행한다. 터미널 여는 법은 macOS는 터미널 앱, Windows는 PowerShell이다. `claude` 실행 명령은 공식 문서에서 확인됨. `[확인필요: 운영체제별 폴더 만들기 명령]`
  ```
  mkdir my-classroom
  cd my-classroom
  claude
  ```
  Claude Code 입력창에 아래 문장을 그대로 붙여넣는다.
  ```
  이 폴더에 index.html 파일을 하나 만들어 줘.
  화면 가운데에 "환영합니다. 우리 반 온라인 클래스룸"이라는 큰 제목이 보이게 해 줘.
  배경은 크림색(#f8f2e4), 글자는 진한 갈색(#2a2314)으로 하고, 초등학생도 읽기 쉬운 큰 글씨로 해 줘.
  파일은 index.html 하나만 만들고, 다른 설치나 설정은 하지 마.
  ```
- 예상 결과: 폴더 안에 `index.html`이 생기고, 브라우저로 열면 크림색 배경 가운데에 "환영합니다. 우리 반 온라인 클래스룸"이 크게 보인다. 브라우저에서 여는 방법: 파일 탐색기에서 `index.html`을 더블클릭하거나 터미널에서 `open index.html`(macOS) / `start index.html`(Windows) `[확인필요]`.
- 막힐 때:
  - Claude Code가 파일 만들기 허락을 물어볼 때: 내용을 읽고 "허용(yes)"을 고른다. 이 폴더 안의 파일 생성이라서 괜찮다. `[확인필요: 권한 확인 화면의 표시 문구]`
  - 브라우저에 아무것도 안 보일 때: Claude Code에 "index.html이 비어 있어. 다시 만들어 줘"라고 말하거나, 폴더 위치(`my-classroom`)가 맞는지 확인한다. 그래도 안 되면 `checkpoint-0`을 연다.
- 노트: (5분) 시연 후 바로 손을 움직이게 한다. 강사가 먼저 1분 동안 같은 순서로 해 보이고, 나머지 4분은 개별 진행. 조교는 "폴더 안에서 claude를 실행했는지", "붙여넣기가 됐는지"를 중점 확인한다.
  끝난 참가자에게는 "색을 바꿔 달라고 말해 보세요"라고 안내한다. 이것이 오늘의 반복 패턴(요청 → 확인 → 수정 요청)이다. 이 슬라이드의 결과물이 모듈 1 실습 산출물이다(빈 프로젝트 폴더 + "환영합니다" index.html).
  전원이 확인하지 못하면 `checkpoint-0`(빈 시작 폴더)로 안내한다.

## [슬라이드 6] 오늘의 작업 리듬
- 유형: 정리
- 본문: 요청 → 확인 → 막히면 오류 메시지를 그대로 붙여넣기.
  그래도 막히면 `checkpoint` 폴더에서 이어가기.
  모듈이 끝날 때마다 복구 지점이 있습니다.
- 도식: 순환 화살표 [요청] → [확인] → (막힘) → [오류 메시지 그대로 붙여넣기] → (그래도 막힘) → [checkpoint 폴더 열기]. 오른쪽에 복구 지점 목록: checkpoint-0, m2, m3, m4, m5, m6, final.
- 노트: (2분) "막히는 것은 정상입니다. 막혔을 때 오류 메시지를 읽으려 하지 말고 통째로 복사해 Claude Code에 붙여넣으세요. 대부분 그것으로 해결됩니다."
  복구 지점 사용법: "막혔다면 checkpoint 폴더를 열고 다음 모듈부터 따라오세요. 지금 모듈이 안 끝나도 다음 모듈은 바로 시작할 수 있습니다." 다음 모듈의 시작 지점은 직전 모듈의 체크포인트다(모듈 2는 `checkpoint-0`에서 시작). 이번 모듈의 복구 지점은 `checkpoint-0`(빈 시작 폴더)이다. `[확인필요: 체크포인트 폴더 배포 위치·접근 방법은 practice-engineer 확인]`
  마지막에 다음 모듈(Firebase 설정 + 구글 로그인)을 예고하고 모듈 1 합계 15분을 맞춰 마친다.
