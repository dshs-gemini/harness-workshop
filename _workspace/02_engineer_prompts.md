# 02. 모듈별 Claude Code 프롬프트와 복구 지점 (practice-engineer)

> 기준: `firebase-classroom-spec`, `01_designer_curriculum.md`, `02_engineer_rules.md`(설계 결정 D1~D9)
> 범위: 이 문서는 **연수 교재용**이다. 프롬프트 문장, 원고와의 일치 여부, 강사가 연수 전에 준비할 복구 지점(checkpoint)과 배포 파일의 상태 기준만 담는다. 예전에 있던 `_workspace/reference-app/` 참고 구현은 **현재 삭제되어 없다.** 그래서 이 문서의 명세(0-0절 목록, 0-1·0-1b절, 슬라이드 50 점검 페이지 명세)만으로 강사가 배포물을 다시 만들 수 있게 적었다.
> 명세 상태: members `uid` 필드(결정 D2)와 수업 문서 이름 = 수업코드(결정 D1)는 **승인·반영됨(2026-10-03)**. `firebase-classroom-spec` 명세 파일에 들어가 있다.
> 원칙: 프롬프트 하나에 기능 하나. 원고 프롬프트를 그대로 써도 되는 곳은 **[일치]**, 문장 일부를 바꾸거나 더한 곳은 **[보충]**, 바꿔야 동작하는 곳은 **[수정]**, 원고에 없던 프롬프트는 **[신규]**로 표시했다. [보충]·[수정]은 전체 문장을 다시 적고 "왜 바꿨나"를 붙였다.

### 0-1. 복구 지점(checkpoint): 강사가 연수 전에 준비한다

슬라이드가 안내하는 `checkpoint-*` 폴더 7개는 **강사가 연수 전에 직접 준비해 참가자에게 나눠 준다**(USB, 공유 드라이브, 압축 파일 링크 등 배포 방법은 강사가 정한다. 슬라이드 6 노트의 `[확인필요: 배포 위치]`는 "강사가 연수 직전 안내"로 채운다). 준비 방법은 두 가지 중 하나다.
- (가) 강사가 이 문서의 프롬프트를 연수 전에 자기 컴퓨터에서 차례대로 실행하고, 모듈이 끝날 때마다 폴더를 복사해 둔다. 참가자가 겪을 결과와 가장 비슷하므로 **기본 방법으로 권장**한다.
- (나) 참고 구현을 바탕으로 만든다. 단 예전 `_workspace/reference-app/`은 삭제되어 지금은 이 방법을 쓸 수 없다. 다른 참고 구현을 쓰더라도 아래 "갖춰야 할 상태"를 하나씩 확인한다.

어느 방법이든 아래 **공통 조건**과 **폴더별 상태**를 만족해야 다음 모듈 프롬프트가 그대로 이어진다.

#### 공통 조건 (모든 checkpoint)
1. 빌드 도구 없는 정적 폴더. 모듈 2 이후는 `index.html`, `style.css`, `app.js`, `firebase-config.js`(+ 필요 시 보조 js) 구조를 유지한다. 폴더마다 이름이 달라지면 "이 파일 하나만 바꾸세요" 안내가 깨진다.
2. **Firebase 설정값은 `firebase-config.js` 한 파일에만** 있고, 강사 값이 아닌 자리 표시 값(`여기에-내-apiKey` 등)으로 비워 둔다. 자리 표시 값이면 화면 맨 위에 "firebase-config.js에 내 Firebase 설정값을 넣어 주세요" 안내가 보여야 한다.
3. AI API 키 같은 비밀 값은 어떤 폴더에도 없다.
4. Firebase SDK는 CDN 모듈 `https://www.gstatic.com/firebasejs/12.19.0/…` 한 버전만 쓴다.
5. 데이터 경로·필드는 `02_engineer_rules.md` 4절 표(D7)와 같다: 수업 문서 이름 = 수업코드, `members/{uid}`에 `joinedAt`·`uid`, 시각 필드는 서버 시각(타임스탬프).
6. 사용자 글(이름, 제목, 피드백)은 글자 그대로(textContent) 표시하고, 자료 html은 sandbox iframe의 srcdoc으로만 넣는다.
7. `samples/sample-material.html`(모듈 4 연습 자료)과 짧은 `README.md`(처음 할 일: firebase-config.js 바꾸기, localhost로 열기 명령)를 넣는다. README는 Hosting 배포 대상에서 뺀다.
8. 강사 사전 점검: 강사 테스트 프로젝트에서 교사 계정 1개 + 학생 계정 1개로 그 폴더의 "끝 상태"를 한 바퀴 돌려 본다. 점검 후 `firebase-config.js`를 자리 표시 값으로 되돌린다.

### 0-3. 로컬 확인 방법 (모듈 2부터)

- 파일을 더블클릭(file://)해서 열면 **동작하지 않는다.** `app.js`를 모듈(`type="module"`)로 불러오는데, 크롬은 file:// 주소에서 모듈 파일 불러오기를 막는다. 구글 로그인도 http(s) 주소가 필요하다.
- 폴더에서 아래 명령 중 하나로 로컬 서버를 켜고 `http://localhost:5500`으로 연다. 보통은 모듈 2 프롬프트 결과로 Claude Code가 알려 준다.
  - `npx --yes http-server -p 5500 -c-1` (Node.js 필요, `-c-1`은 캐시를 꺼서 새로고침하면 바로 반영. 옵션 뜻은 http-server 공식 설명과 일치, 실제 실행은 강사 리허설에서 확인)
  - `python3 -m http.server 5500` (Python이 있는 경우)
- **2025-04-28 이후 만든 Firebase 프로젝트에는 승인된 도메인에 `localhost`가 기본으로 없다**(Firebase 공식 문서). 오늘 연수에서 만드는 프로젝트는 모두 해당되므로, 슬라이드 12에서 왼쪽 메뉴 보안(Security) > Authentication > 설정 탭 > 승인된 도메인 > "도메인 추가"로(한국어 메뉴 표기는 `[확인필요]`, 강사 리허설 캡처로 대체) `localhost`를 직접 넣는다. 이 단계를 건너뛰면 구글 로그인 팝업에서 승인된 도메인 오류가 난다.
- `127.0.0.1`은 `localhost`와 다른 도메인으로 취급되므로 `localhost` 주소로 연다.
- 운영 단계(실제 학급 사용)에서는 승인된 도메인에서 `localhost`를 지우는 것이 공식 권장이다(슬라이드 53 현장 적용 체크).

#### checkpoint-m4와 슬라이드 29 맞추기 (90만 바이트 제한) — (가)로 확정, 원고 반영됨

  ```
  - html 내용의 크기를 UTF-8 바이트로 세어 90만 바이트를 넘으면 저장하지 말고 "자료가 너무 큽니다"라고 알려 줘.
  ```
  - 기준은 바이트 하나뿐이다. "한글이 많으면 약 30만 글자"는 강사 노트에만 둔다. 프롬프트에 글자 기준이 함께 있으면 Claude Code가 글자 수로 검사하는 코드를 만들 수 있기 때문이다.
  - 이유: 문서 한도(1MiB = 1,048,576바이트)를 넘는 자료를 저장하면 Firestore 오류가 나는데, 슬라이드 32 막힐 때를 미리 막아 준다. 제목·생성 시각 같은 다른 필드 몫을 남기려고 1MiB보다 낮은 90만 바이트로 잡았다.

- 강사는 checkpoint-m4~final 전체에 같은 기준(90만 바이트, UTF-8)을 넣는다(0-0절 #1).
